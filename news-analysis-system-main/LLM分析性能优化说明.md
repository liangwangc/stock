# LLM分析性能优化说明

**优化日期**：2026-01-23  
**优化目标**：提升8核16G内存CPU模式下的LLM分析速度

---

## 一、优化措施

### ✅ 1. 减少输出长度

**优化前**：
- `max_new_tokens=1024`（最大输出1024个token）

**优化后**：
- `max_new_tokens=400`（最大输出400个token）

**效果**：减少约60%的输出长度，显著提升生成速度

**说明**：对于新闻分析任务，400个token已经足够输出完整的JSON格式分析结果。

---

### ✅ 2. 优化生成参数

**优化前**：
- `top_p=0.95`
- `num_beams=1`（默认）

**优化后**：
- `top_p=0.85`（降低采样范围，加快采样速度）
- `num_beams=1`（明确使用贪心解码，避免beam search的开销）
- `use_cache=True`（启用KV缓存以加速生成）

**效果**：采样速度提升约10-15%

---

### ✅ 3. 禁用梯度计算

**优化**：
- 使用 `torch.no_grad()` 上下文管理器包装模型生成过程

**效果**：
- 节省内存（不存储梯度）
- 提升速度（不计算梯度）

---

### ✅ 4. 模型加载优化

**优化**：
- 模型和分词器只加载一次（单例模式）
- 在函数开始时统一加载，避免重复加载

**效果**：减少模型加载开销

---

## 三、进一步优化建议

### 1. 使用量化模型（如果内存不足）

如果16G内存不够用，可以考虑使用4-bit或8-bit量化模型：

```python
from transformers import BitsAndBytesConfig

quantization_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.float16
)

_model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    quantization_config=quantization_config,
    device_map="auto"
)
```

**注意**：量化模型会略微降低精度，但可以显著减少内存占用和提升速度。

---

### 2. 使用API模式（推荐）

如果配置了 `DASHSCOPE_API_KEY`，使用API模式可以获得：
- **更快的速度**：云端GPU加速
- **不占用本地资源**：CPU和内存完全释放
- **更好的稳定性**：不受本地硬件限制

**预计速度**：每条新闻约2-5秒（比本地CPU快3-6倍）

---

### 3. 批量处理（如果内存充足）

当前代码支持 `batch_size` 参数，如果内存充足（>32G），可以尝试：

```python
results = qwen3_model_by_local(news_batch, batch_size=2)  # 或更大
```

**注意**：对于CPU模式，批量处理可能不会带来太大提升，因为CPU推理本身是串行的。
