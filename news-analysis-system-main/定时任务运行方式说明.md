# 定时任务运行方式说明

**创建时间**：2026-01-23  
**问题**：能否在 smart_stock_advisor 的设置页面中直接启动 news-analysis-system-main 的定时任务？

---

## 📋 答案

**简短回答**：**news-analysis-system-main 需要作为独立服务运行**，不能直接在 smart_stock_advisor 的设置页面中启动。

**原因**：
- `smart_stock_advisor` 有自己的新闻抓取系统（`UnifiedNewsSource` + `NewsCrawler`）
- `news-analysis-system-main` 是独立的新闻系统（财联社API + LLM分析）
- 两者使用不同的代码和逻辑，目前没有集成

---

## 🚀 方案对比

### 方案1：独立运行（推荐）✅

**方式**：news-analysis-system-main 使用自己的 `scheduler.py` 独立运行

**优点**：
- ✅ 简单直接，无需修改代码
- ✅ 独立管理，不影响 smart_stock_advisor
- ✅ 日志独立，便于排查问题
- ✅ 可以单独启动/停止

**启动方式**：
```bash
# Windows
cd d:\wjw_work\news-analysis-system-main
start_scheduler.bat

# 或直接运行
py scheduler.py
```

**配置**：
- 新闻获取：每10分钟
- LLM分析：每2小时
- 可在 `scheduler.py` 中修改

---

### 方案2：集成到 smart_stock_advisor（可选）

**方式**：将 news-analysis-system-main 的功能集成到 `ScheduledTaskManager` 中

**优点**：
- ✅ 统一管理界面
- ✅ 可以在设置页面中启动/停止
- ✅ 统一的日志和监控

**缺点**：
- ❌ 需要修改代码
- ❌ 需要将 news-analysis-system-main 的代码集成到 smart_stock_advisor
- ❌ 增加系统复杂度

**实现步骤**（如果选择此方案）：
1. 在 `ScheduledTaskManager` 中添加新的任务类型（如 `cls_news_fetch`、`llm_analysis`）
2. 实现对应的执行函数，调用 news-analysis-system-main 的功能
3. 在设置页面中添加创建这些任务的选项

---

## 💡 推荐方案

**推荐使用方案1（独立运行）**，原因：

1. **简单可靠**：不需要修改现有代码，降低出错风险
2. **独立维护**：两个系统可以独立更新和维护
3. **资源隔离**：LLM分析需要较多资源，独立运行不影响主系统
4. **灵活配置**：可以单独调整执行频率和参数

## 🔧 实际使用建议

### 开发/测试环境

```bash
# 手动启动，方便调试
cd d:\wjw_work\news-analysis-system-main
py scheduler.py
```

### 生产环境

**方式1：使用 Windows 任务计划程序（推荐）**

1. 打开"任务计划程序"
2. 创建基本任务
3. 设置触发器：当计算机启动时
4. 设置操作：
   - 程序：`py`
   - 参数：`D:\wjw_work\news-analysis-system-main\scheduler.py`
   - 起始于：`D:\wjw_work\news-analysis-system-main`
5. 完成配置

**方式2：使用后台服务**

可以使用 `nssm`（Non-Sucking Service Manager）将 Python 脚本注册为 Windows 服务：

```bash
# 下载 nssm
# 安装服务
nssm install NewsSystemScheduler "py" "D:\wjw_work\news-analysis-system-main\scheduler.py"
nssm set NewsSystemScheduler AppDirectory "D:\wjw_work\news-analysis-system-main"
nssm start NewsSystemScheduler
```

```
┌─────────────────────────────────────┐

│                                      │

              ↓
```

- 两个系统使用**相同的数据库**（`stock_data`）
- 数据自动共享，无需同步
- 可以独立运行和管理

3. **推荐使用 Windows 任务计划程序**，设置开机自启
4. **两个系统共享数据库**，数据自动同步

## 📝 注意事项

1. **确保数据库连接正常**：两个系统都需要连接到 `stock_data` 数据库
2. **资源占用**：LLM分析需要较多内存，建议在资源充足时运行
3. **日志监控**：定期查看 `logs/scheduler_YYYYMMDD.log` 文件
4. **错误处理**：如果任务失败，查看日志文件排查问题
