# 定时任务配置说明

**创建时间**：2026-01-23  
**功能**：统一管理新闻获取和LLM分析定时任务

---

## 📋 任务说明

### 1. 新闻获取任务
- **功能**：从财联社获取最新新闻并保存到数据库
- **默认间隔**：每10分钟执行一次
- **脚本**：`src/data_processing/get_cls_news.py`

### 2. LLM分析任务
- **功能**：对未分析的新闻进行LLM分析（分类、情感分析、摘要等）
- **默认间隔**：每2小时执行一次
- **脚本**：`src/analysis/main.py`

---

## 🚀 使用方法

### 方法1：使用统一调度器（推荐）

**启动调度器**：
```bash
# Windows
start_scheduler.bat

# 或直接运行
py scheduler.py
```

**优点**：
- 统一管理所有任务
- 自动日志记录
- 易于监控和维护

### 方法2：分别运行任务

**只运行新闻获取**：
```bash
py src/data_processing/get_cls_news.py
```

**只运行LLM分析**：
```bash
py src/analysis/main.py
```

## ⚙️ 配置修改

### 修改执行间隔

编辑 `scheduler.py` 文件中的 `setup_schedules()` 函数：

```python
def setup_schedules():
    # 新闻获取：每5分钟执行一次
    schedule.every(5).minutes.do(news_fetch_job)
    
    # LLM分析：每1小时执行一次
    schedule.every(1).hours.do(llm_analysis_job_wrapper)
    
    # 或者使用固定时间
    schedule.every().day.at("09:00").do(news_fetch_job)
    schedule.every().day.at("01:00").do(llm_analysis_job_wrapper)
```

### 常用时间配置示例

```python
# 每N分钟
schedule.every(5).minutes.do(news_fetch_job)

# 每N小时
schedule.every(2).hours.do(llm_analysis_job_wrapper)

# 每天固定时间
schedule.every().day.at("09:00").do(news_fetch_job)

# 每周特定时间
schedule.every().monday.at("09:00").do(news_fetch_job)

# 工作日（周一到周五）
schedule.every().monday.at("09:00").do(news_fetch_job)
schedule.every().tuesday.at("09:00").do(news_fetch_job)
schedule.every().wednesday.at("09:00").do(news_fetch_job)
schedule.every().thursday.at("09:00").do(news_fetch_job)
schedule.every().friday.at("09:00").do(news_fetch_job)
```

## 📝 Windows 任务计划程序配置（可选）

如果需要系统级别的定时任务（开机自启、后台运行），可以使用Windows任务计划程序：

### 步骤1：创建任务

1. 打开"任务计划程序"（Task Scheduler）
2. 点击"创建基本任务"
3. 输入任务名称：`新闻系统定时任务`

### 步骤2：设置触发器

- **触发器类型**：当计算机启动时
- 或选择：每天、在特定时间

### 步骤3：设置操作

- **操作**：启动程序
- **程序或脚本**：`py` 或 `python`
- **添加参数**：`D:\wjw_work\news-analysis-system-main\scheduler.py`
- **起始于**：`D:\wjw_work\news-analysis-system-main`

### 步骤4：完成配置

- 勾选"打开属性对话框"
- 在"常规"选项卡中，选择"不管用户是否登录都要运行"
- 在"条件"选项卡中，取消"只有在计算机使用交流电源时才启动此任务"

## 🔧 故障排查

### 问题1：任务没有执行

**检查**：
1. 查看日志文件，确认是否有错误
2. 确认调度器是否正在运行
3. 检查数据库连接是否正常

### 问题2：任务执行失败

**检查**：
1. 查看日志文件中的错误信息
2. 确认依赖包是否已安装
3. 确认数据库表结构是否正确

### 问题3：LLM分析任务很慢

**原因**：
- LLM模型加载需要时间
- 分析大量新闻需要较长时间

**建议**：
- 减少每次分析的新闻数量
- 增加执行间隔
- 使用API模式（如果本地资源不足）

## ✨ 特性

1. **统一管理**：一个脚本管理所有定时任务

## 📝 注意事项

1. **资源占用**：LLM分析需要较多内存和CPU资源
2. **网络连接**：新闻获取需要网络连接
3. **数据库连接**：确保数据库服务正常运行
4. **日志清理**：定期清理旧日志文件，避免占用过多磁盘空间
