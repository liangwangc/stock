# 股票预测性能问题分析与优化方案

## 一、当前性能问题

### 1.1 性能数据
- **当前速度**：1小时分析 560 只股票
- **平均耗时**：3600秒 / 560 ≈ **6.4秒/只**
- **理论速度**（20线程）：如果单只股票耗时3秒，20线程应该能达到 **180只/小时**
- **实际差距**：当前速度只有理论速度的 **31%**

### 1.2 性能问题分析

#### 🔴 问题1：实际线程数可能不是20

**可能原因**：
- 数据库配置中 `analysis_max_workers` 可能设置为更小的值（如3或5）
- 需要检查实际使用的线程数

**检查方法**：
1. 查看日志中的 `【分析模式】使用多线程并行分析（并发数: X）`
2. 检查数据库配置：`prediction_config` 表的 `performance.analysis_max_workers`

**影响**：
- 如果实际只有3线程：560只/小时 ÷ 3 = 187只/线程/小时 ≈ 5.3秒/只（接近当前速度）
- 如果实际是20线程：560只/小时 ÷ 20 = 28只/线程/小时 ≈ 128秒/只（明显异常）

#### 🟡 问题2：单只股票耗时过长（6.4秒）

**可能原因**：
1. **数据库查询慢**：每个股票可能有多次数据库查询
2. **计算耗时**：技术指标计算、因子分析等
3. **锁竞争**：多线程访问数据库时的锁竞争
4. **日志I/O**：虽然已优化，但可能仍有影响

**分析**：
- 如果单线程6.4秒/只，说明每个股票的预测本身就很慢
- 即使增加到20线程，如果单只股票耗时6.4秒，20线程也只能达到 1125只/小时

## 二、优化方案

### 2.1 立即优化：检查并增加线程数

#### 步骤1：检查当前线程数配置

**方法1：查看日志**
- 启动股票预测任务时，查看日志中的：
  ```
  【分析模式】使用多线程并行分析（并发数: X）
  ```

**方法2：检查数据库配置**
- 设置页面 → 参数设置 → 性能优化
- 查看 `analysis_max_workers` 的值
- 如果小于20，建议修改为 **20-30**

#### 步骤2：增加线程数

**推荐配置**：
- **最小推荐**：20线程（当前默认值）
- **推荐值**：30线程（如果数据库连接池足够大）
- **最大值**：50线程（需要确保数据库连接池至少50-100）

**修改方法**：
1. 设置页面 → 参数设置 → 性能优化
2. 将 `analysis_max_workers` 设置为 **30**
3. 确保 `analysis_enable_parallel` 为 `true`
4. 保存配置

**预期效果**：
- 从3线程增加到30线程：**速度提升10倍**（从560只/小时到5600只/小时）
- 从20线程增加到30线程：**速度提升50%**（从1125只/小时到1687只/小时）

---

### 2.2 中期优化：优化数据库查询性能

#### 优化1：检查数据库索引

**检查项**：
1. `stock_history_data` 表是否有以下索引：
   - `idx_symbol_date`：`(symbol, trade_date)`
   - `idx_trade_date`：`(trade_date)`
   - `uk_symbol_date_period`：`(symbol, trade_date, period_type)`（唯一索引）

**检查SQL**：
```sql
SHOW INDEX FROM stock_history_data;
```

**如果没有索引，创建索引**：
```sql
-- 如果不存在，创建索引
CREATE INDEX idx_symbol_date ON stock_history_data(symbol, trade_date);
CREATE INDEX idx_trade_date ON stock_history_data(trade_date);
```

#### 优化2：优化数据库连接池

**检查MySQL配置**：
```sql
SHOW VARIABLES LIKE 'max_connections';
```

**建议配置**：
- `max_connections`：至少 **100**（支持30-50个并发线程）
- 如果当前值小于100，需要修改MySQL配置

**修改方法**（MySQL配置文件 `my.cnf` 或 `my.ini`）：
```ini
[mysqld]
max_connections = 200
```

#### 优化3：批量查询优化

**当前问题**：
- 虽然已经预加载了部分数据（PE/PB、历史数据、新闻、行业信息）
- 但 `predict()` 方法中可能仍有其他数据库查询

**优化建议**：
- 检查 `stock_predictor.py` 的 `predict()` 方法
- 确保所有数据都通过预加载参数传递，避免重复查询

---

### 2.3 长期优化：代码性能优化

#### 优化1：减少数据库查询次数

**检查项**：
- `predict()` 方法中是否还有未预加载的数据库查询
- 每个股票预测过程中，数据库查询次数应该少于5次

**优化方法**：
- 将所有需要的数据在任务开始前批量查询
- 通过参数传递给 `predict()` 方法

#### 优化2：优化计算性能

**检查项**：
- 技术指标计算是否使用了向量化操作（numpy/pandas）
- 因子分析是否有重复计算

**优化方法**：
- 使用 `numpy` 和 `pandas` 的向量化操作
- 避免循环计算，使用批量计算

#### 优化3：减少锁竞争

**检查项**：
- 多线程访问数据库时是否有锁竞争
- `task_lock`、`progress_lock` 等锁的使用是否合理

**优化方法**：
- 减少锁的持有时间
- 使用读写锁或无锁数据结构（如果可能）
