# 股票收盘信息获取性能优化说明

**创建日期**：2026-01-15  
**优化版本**：v2.0

---

## 一、优化概述

针对定时获取股票收盘信息效率太慢的问题，进行了全面性能优化，主要改进包括：

### 1.1 性能瓶颈分析

**原版本问题**：
- ❌ **单线程串行处理**：逐个处理股票，每只股票都要等待前一只完成
- ❌ **固定延迟过长**：每只股票处理后有 `time.sleep(0.5)` 延迟，5000只股票需要约42分钟
- ❌ **逐个数据库查询**：每只股票都要单独查询数据库检查数据是否存在
- ❌ **没有批量处理**：虽然有批量保存方法，但没有使用

**性能影响**：
- 5000只股票 × 0.5秒延迟 = 2500秒（约42分钟）
- 5000次数据库查询 = 大量IO开销
- 单线程处理 = CPU利用率低

---

## 二、优化方案

### 2.1 多线程并发处理

**改进**：
- ✅ 使用 `ThreadPoolExecutor` 实现多线程并发
- ✅ 默认10个线程同时处理（可配置）
- ✅ 大幅提升处理速度（理论上可提升10倍）

**代码位置**：`utils/stock_history_collector.py` 的 `incremental_update_today()` 方法

### 2.2 批量查询已存在数据

**改进**：
- ✅ 批量查询今日数据已存在的股票（每批1000只）
- ✅ 减少数据库查询次数（从N次减少到N/1000次）
- ✅ 提前过滤掉已存在的股票，避免重复处理

**性能提升**：
- 5000只股票：从5000次查询减少到5次查询
- 查询时间：从数分钟减少到数秒

### 2.3 批量保存数据

**改进**：
- ✅ 收集所有采集到的数据，统一批量保存
- ✅ 使用 `save_stock_daily_data_batch()` 方法批量插入
- ✅ 减少数据库写入次数（从N次减少到N/100次）

**性能提升**：
- 5000条数据：从5000次写入减少到50次写入
- 写入时间：从数十分钟减少到数分钟

### 2.4 减少不必要延迟

**改进**：
- ✅ 多线程模式下移除固定延迟（由并发控制替代）
- ✅ 单线程模式延迟从0.5秒减少到0.1秒
- ✅ 只在批次之间添加延迟（多线程模式下减少50%）

## 三、使用方法

### 3.1 命令行使用

**基本用法（使用默认参数，10线程）**：
```bash
# Windows
py scripts/update_stock_history_daily.py

# Linux/Mac
python scripts/update_stock_history_daily.py
```

**自定义线程数**：
```bash
# 使用20个线程
py scripts/update_stock_history_daily.py --threads 20

# 使用单线程模式（兼容旧代码）
py scripts/update_stock_history_daily.py --threads 1
```

**自定义批次大小**：
```bash
# 批次大小为200
py scripts/update_stock_history_daily.py --batch-size 200
```

**完整参数**：
```bash
py scripts/update_stock_history_daily.py --threads 15 --batch-size 150
```

### 3.2 Python API使用

**基本用法**：
```python
from utils.stock_history_collector import StockHistoryCollector

collector = StockHistoryCollector()

# 使用默认参数（10线程，批次大小100）
result = collector.incremental_update_today(symbols=None)

# 自定义参数
result = collector.incremental_update_today(
    symbols=['600519', '000001'],
    max_workers=15,      # 15个线程
    batch_size=150       # 批次大小150
)
```

### 3.3 Web界面使用

**在定时任务中配置**：
1. 进入"设置"页面 > "股票数据获取"
2. 创建或编辑定时任务
3. 在任务配置中设置：
   - `threads`: 线程数（默认10，建议10-20）
   - `batch_size`: 批次大小（默认1000，建议100-200）
   - `delay`: 延迟时间（默认1.0秒，多线程模式下会自动减少）

**示例配置**：
```json
{
  "collection_type": "incremental",
  "threads": 15,
  "batch_size": 150,
  "delay": 1.0
}
```

## 五、参数调优建议

### 5.1 线程数（max_workers）

**建议值**：
- **小规模**（<1000只股票）：5-10线程
- **中规模**（1000-5000只股票）：10-15线程
- **大规模**（>5000只股票）：15-20线程

**注意事项**：
- 线程数过多可能导致API限流
- 线程数过多可能导致数据库连接池耗尽
- 建议根据实际测试结果调整

### 5.2 批次大小（batch_size）

**建议值**：
- **默认**：100-200
- **内存充足**：200-500
- **内存有限**：50-100

**注意事项**：
- 批次大小越大，内存占用越多
- 批次大小越大，批量保存效率越高
- 建议根据实际内存情况调整

### 5.3 延迟时间（delay）

**建议值**：
- **多线程模式**：0.5-1.0秒（系统会自动减少）
- **单线程模式**：0.1-0.5秒

**注意事项**：
- 延迟时间用于避免API限流
- 多线程模式下延迟会自动减少50%
- 如果API有限流，需要适当增加延迟

## 七、常见问题

### Q1: 多线程模式下出现API限流怎么办？

**解决方案**：
1. 减少线程数（从10减少到5）
2. 增加延迟时间（从1.0秒增加到2.0秒）
3. 分批处理（将股票列表分成多个批次）

### Q2: 内存不足怎么办？

**解决方案**：
1. 减少批次大小（从100减少到50）
2. 减少线程数（从10减少到5）
3. 分批处理（每次处理部分股票）

### Q3: 数据库连接池耗尽怎么办？

**解决方案**：
1. 减少线程数（减少并发数据库连接）
2. 增加数据库连接池大小
3. 使用连接池管理

### Q4: 如何回退到单线程模式？

**解决方案**：
```bash
# 命令行
py scripts/update_stock_history_daily.py --threads 1

# Python API
result = collector.incremental_update_today(symbols, max_workers=1)
```
