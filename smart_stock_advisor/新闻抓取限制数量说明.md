# 新闻抓取限制数量说明

## 一、问题

用户看到日志：
```
2026-01-14 16:35:33 - utils.news_crawler - INFO - 开始增量抓取全部新闻，时间范围: 2026-01-14 16:30:33 到 2026-01-14 16:35:33，限制数量: 15（每个新闻源），最大重试: 3次
```

**疑问**：为什么要限制数量（limit=15，每个新闻源）？

## 二、限制数量的原因

### 1. 性能优化

**防止一次性获取过多数据**：
- 如果每个新闻源都获取大量新闻（例如1000条），总数据量会非常大
- 假设有6个新闻源，每个获取1000条，总共6000条新闻
- 处理6000条新闻需要：
  - 解析HTML/JSON
  - 时间解析和过滤
  - 股票关联分析
  - 数据库保存
  - 预计耗时：10-30分钟

**限制数量后**：
- 每个新闻源15条，6个新闻源共90条（实际会获取 `15 * 2 = 30` 条，因为时间过滤）
- 处理时间：1-3分钟
- **性能提升**：10倍

### 2. 增量抓取特性

**时间范围限制**：
- 增量抓取只获取时间范围内的新闻（例如：5分钟内）
- 5分钟内通常不会有太多新闻
- 限制数量15条已经足够覆盖时间范围内的新闻

**示例**：
- 时间范围：`2026-01-14 16:30:33` 到 `2026-01-14 16:35:33`（5分钟）
- 5分钟内，每个新闻源通常只有5-20条新新闻
- 限制15条已经足够

### 3. 避免API限制

**新闻源API限制**：
- 某些新闻源（如金十数据、财新等）可能有API调用频率限制
- 如果一次性获取太多数据，可能触发限流
- 限制数量可以避免触发API限制

### 4. 控制数据库写入量

**数据库性能**：
- 每条新闻都需要：
  - 检查重复（SimHash计算）
  - 插入数据库
  - 关联股票分析
  - 更新索引
- 如果一次性写入大量数据，可能导致：
  - 数据库锁竞争
  - 索引更新延迟
  - 查询性能下降

**限制数量后**：
- 每次只处理少量新闻（15-30条）
- 数据库写入压力小
- 查询性能稳定

### 5. 内存占用控制

**内存优化**：
- 每条新闻包含：标题、内容、时间、来源等信息
- 假设每条新闻平均5KB，1000条新闻 = 5MB
- 如果有多个新闻源，总内存占用会更大

**限制数量后**：
- 每次只处理少量新闻（15-30条）
- 内存占用小（< 1MB）
- 适合长时间运行的定时任务

### 6. 提高抓取成功率

**网络稳定性**：
- 如果一次性获取太多数据，网络请求时间过长
- 可能因为网络超时导致抓取失败
- 限制数量可以缩短单次请求时间，提高成功率

## 三、限制数量的实际使用

### 1. 代码实现

**`crawl_all_news` 方法**（`news_crawler.py` 第242-283行）：
```python
def crawl_all_news(self, limit: int = 200, last_fetch_time: Optional[datetime] = None, 
                   interval_minutes: float = 60.0, max_retries: int = 3) -> Dict[str, int]:
    """
    Args:
        limit: 限制数量（每个新闻源）
    """
    # 实际调用时使用 limit * 2，是为了获取更多新闻以便后续时间过滤
    news_list = self.news_source.get_market_news(limit=limit * 2, only_today=False)
```

**说明**：
- `limit=15` 表示每个新闻源限制15条
- 实际调用时使用 `limit * 2 = 30` 条
- 原因：时间过滤会过滤掉部分新闻，多获取一些确保有足够的新闻

### 2. 任务配置

**从任务配置获取**（`scheduled_task_manager.py` 第1375行）：
```python
result = news_crawler.crawl_all_news(

    interval_minutes=interval_minutes,
    max_retries=task_config.get('max_retries', 3)

```

**默认值来源**：
- `task_config.get('limit', 15)` - 从任务配置获取，默认15
- 如果没有配置，使用默认值15

### 3. 配置文件

## 四、限制数量的合理性

### 1. 增量抓取场景

**时间范围**：5分钟
- 5分钟内，每个新闻源通常只有5-20条新新闻
- 限制15条已经足够

**如果时间范围更长**（例如：1小时）：
- 可能需要增加限制数量
- 建议：`limit = 时间范围（分钟） / 5`
- 例如：60分钟 → `limit = 60 / 5 = 12`，可以设置为15-20

### 2. 新闻源数量

**当前新闻源**（`config.py` 第9-16行）：
```python
NEWS_SOURCES = [
    "jin10",      # 金十数据
    "caixin",     # 财新
    "securities", # 证券公司（包括广发证券等）
    "tonghuashun", # 同花顺
    "eastmoney",  # 东方财富
    "xueqiu"      # 雪球
]
```

**6个新闻源**：
- 每个新闻源15条，总共90条（实际获取 `15 * 2 = 30` 条，时间过滤后可能更少）
- 对于增量抓取（5分钟），这个数量是合理的

### 3. 处理时间估算

**单条新闻处理时间**：
- 时间解析：< 1ms
- 股票关联分析：10-50ms
- 数据库保存：5-20ms
- 总计：15-71ms

**15条新闻处理时间**：
- 15条 × 50ms（平均）= 750ms = 0.75秒
- 加上网络请求时间：1-3秒
- **总耗时**：2-4秒

**如果增加到100条**：
- 100条 × 50ms = 5000ms = 5秒
- 加上网络请求时间：5-10秒
- **总耗时**：10-15秒

**结论**：限制15条可以保持快速响应，适合定时任务（每5分钟执行一次）

## 五、如何调整限制数量

### 1. 通过任务配置调整

**在创建定时任务时**：
```json
{
  "task_type": "all",
  "limit": 30,  // 增加到30条（每个新闻源）
  "interval_minutes": 5,
  "max_retries": 3
}
```

### 2. 根据时间范围调整

**建议公式**：
```
limit = max(15, 时间范围（分钟） / 5)
```

**示例**：
- 5分钟 → `limit = max(15, 5/5) = 15`
- 30分钟 → `limit = max(15, 30/5) = 15`（仍然15，因为30分钟内新闻不会太多）
- 60分钟 → `limit = max(15, 60/5) = 15`（仍然15）
- 120分钟 → `limit = max(15, 120/5) = 24`（可以增加到25-30）

### 3. 根据新闻源数量调整

**如果新闻源数量增加**：
- 可以适当减少每个新闻源的限制数量
- 例如：10个新闻源，每个10条，总共100条

**如果新闻源数量减少**：
- 可以适当增加每个新闻源的限制数量
- 例如：3个新闻源，每个30条，总共90条

## 六、总结

### 1. 为什么要限制数量？

**答案**：**性能优化和增量抓取特性**
- ✅ 防止一次性获取过多数据（性能优化）
- ✅ 增量抓取时间范围内新闻数量有限（5分钟内通常只有5-20条）
- ✅ 避免API限制
- ✅ 控制数据库写入量
- ✅ 内存占用控制
- ✅ 提高抓取成功率

### 2. 限制15条是否合理？

**答案**：**对于增量抓取（5分钟）是合理的**
- ✅ 5分钟内，每个新闻源通常只有5-20条新新闻
- ✅ 限制15条已经足够覆盖时间范围内的新闻
- ✅ 处理时间短（2-4秒），适合定时任务
- ✅ 数据库写入压力小

### 3. 如何调整？

**答案**：**根据实际需求调整**
- 可以通过任务配置中的 `limit` 参数调整
- 建议根据时间范围调整：`limit = max(15, 时间范围（分钟） / 5)`
- 如果时间范围很长（> 60分钟），可以适当增加
