# 新闻抓取问题分析与优化方案

## 问题分析

### 问题1：为什么抓取当天的数据很多网站都获取不到？

**根本原因**：
1. **各个新闻源不支持 `only_today` 参数**：
   - 所有新闻源（如 `eastmoney_news_source.py`, `tencent_news_source.py`, `stcn_news_source.py`, `cs_news_source.py`, `cls_news_source.py` 等）的 `get_market_news()` 和 `get_stock_news()` 方法**都不支持 `only_today` 参数**
   - 它们总是返回所有能获取到的新闻（通常是最近的一些新闻）

2. **时间解析问题**：
   - 各个新闻源的时间解析（`_parse_time` 方法）可能不准确
   - 有些网站使用相对时间（"1小时前"、"今天"、"昨天"），解析可能出错
   - 如果解析出错，`unified_news_source.py` 在过滤时会错误地过滤掉新闻

3. **过滤逻辑在聚合层**：
   - `unified_news_source.py` 在聚合所有新闻源的数据后，才根据 `only_today` 参数过滤
   - 如果各个新闻源获取到的新闻都不是当天的（或者时间解析错误），过滤后就没有数据了

4. **调用时没有传递 `only_today` 参数**：
   - 在 `unified_news_source.py` 第348行：`news = source.get_market_news(limit // len(self.sources) + 1)`
   - 调用各个新闻源时没有传递 `only_today` 参数，因为各个新闻源的方法签名不支持这个参数

### 问题2："全部"新闻抓取功能

**当前实现**：
- `task_type='all'` 时，只是先抓市场新闻，再抓股票新闻
- 仍然使用 `only_today=True`（默认值）

**用户需求**：
- 选择"全部"时，应该获取所有新闻（不限制日期）
- 然后进行新闻分析，关联到股票、板块、行业、大盘等

## 解决方案

### 方案1：修复各个新闻源的 `only_today` 支持

**选项A：让各个新闻源支持 `only_today` 参数**（推荐）
- 修改各个新闻源的 `get_market_news()` 和 `get_stock_news()` 方法签名，添加 `only_today` 参数
- 在各个新闻源内部进行过滤（如果有能力识别日期）
- 优点：过滤更准确，减少不必要的数据传输
- 缺点：需要修改所有新闻源，工作量较大

**选项B：改进 `unified_news_source.py` 的时间解析和过滤**（当前方案）
- 改进时间解析逻辑，处理各种时间格式
- 改进过滤逻辑，确保能正确识别当天新闻
- 优点：只需修改一个文件
- 缺点：如果新闻源本身没有当天新闻，仍然无法获取

**选项C：混合方案**（推荐）
- 改进时间解析逻辑
- 在各个新闻源内部尽量获取最新新闻（不强制过滤）
- 在 `unified_news_source.py` 层进行精确过滤
- 如果 `only_today=False`，则不过滤，返回所有新闻

### 方案2：实现"全部"新闻抓取功能

1. **修改 `crawl_market_news` 和 `crawl_stock_news` 方法**：
   - 当 `only_today=False` 时，不限制日期，获取所有新闻

2. **实现全部新闻的关联分析**：
   - 获取所有新闻后，使用新闻关联分析器（`NewsStockMapper`）分析每条新闻
   - 关联到股票、板块、行业
   - 如果新闻包含市场关键词（如"大盘"、"指数"、"A股"等），标记为大盘相关

3. **修改任务类型处理**：
   - `task_type='all'` 时，设置 `only_today=False`
   - 获取所有新闻，然后进行关联分析
