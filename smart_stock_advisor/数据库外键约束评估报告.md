## 一、评估原则

### 1.1 外键约束的优缺点

**优点**：
- ✅ **数据完整性**：确保引用数据存在，防止孤立记录
- ✅ **级联操作**：支持级联删除/更新，简化数据管理
- ✅ **自动验证**：数据库层面自动验证数据一致性

**缺点**：
- ⚠️ **性能影响**：每次插入/更新需要检查外键约束，增加开销
- ⚠️ **锁竞争**：外键检查可能增加锁竞争，影响并发性能
- ⚠️ **灵活性降低**：删除主表记录时可能被外键阻止

### 1.2 评估标准

1. **数据完整性要求**：是否必须保证数据一致性
2. **写入频率**：高频写入的表不建议添加外键
3. **数据量大小**：大数据量表的外键检查开销更大
4. **业务逻辑**：是否可以通过应用层保证数据一致性

## 三、建议添加的外键约束

### 3.1 低优先级（可选）

#### 💡 `stock_predictions.config_id` → `prediction_config.id`

**建议**：⚠️ **不建议添加**

**原因**：
1. **写入频率高**：`stock_predictions` 表每天可能写入数千条记录
2. **性能影响**：每次插入预测结果都需要检查配置是否存在
3. **业务逻辑**：应用层已确保 `config_id` 的有效性（通过 `PredictionConfigManager`）
4. **灵活性**：配置可能被删除，但历史预测记录需要保留

**替代方案**：
- ✅ 应用层验证：在插入预测结果前验证 `config_id` 是否存在
- ✅ 定期数据清理：通过定时任务清理无效的 `config_id` 引用

**SQL示例**（仅供参考，不建议执行）：
```sql
-- 不建议执行
ALTER TABLE `stock_predictions`
ADD CONSTRAINT `fk_predictions_config`
FOREIGN KEY (`config_id`) REFERENCES `prediction_config`(`id`) ON DELETE SET NULL;
```

### 3.2 不建议添加的外键约束

#### ❌ `stock_predictions.symbol` → `stock_history_data.symbol`

**建议**：❌ **强烈不建议添加**

**原因**：
1. **数据量巨大**：`stock_history_data` 表包含近10年数据，数据量可能达到数百万条
2. **写入频率极高**：每天需要更新数千只股票的数据
3. **性能影响严重**：每次插入/更新都需要检查外键，严重影响性能
4. **业务逻辑**：股票代码是字符串，不是主键，无法建立外键约束
5. **数据独立性**：预测结果和历史数据是相对独立的业务实体

**替代方案**：
- ✅ 应用层验证：在插入预测结果前验证股票代码是否存在
- ✅ 定期数据清理：通过定时任务清理无效的股票代码引用

## 五、数据完整性保证方案

### 5.1 应用层验证

**优点**：
- ✅ 性能影响小
- ✅ 灵活性高
- ✅ 可以自定义验证逻辑

**实施**：
- 在插入数据前验证引用数据是否存在
- 使用事务确保数据一致性

**示例代码**：
```python
# 在插入预测结果前验证 config_id
def insert_prediction(symbol, config_id, ...):
    # 验证 config_id 是否存在
    config = config_manager.get_config_by_id(config_id)
    if not config:
        raise ValueError(f"配置ID {config_id} 不存在")
    
    # 插入预测结果
    db.insert_prediction(...)
```

### 5.2 定期数据清理

**优点**：
- ✅ 不影响写入性能
- ✅ 可以清理历史无效数据

**实施**：
- 创建定时任务，定期检查并清理无效的引用
- 记录清理日志，便于追踪

**示例SQL**：
```sql
-- 查找无效的 config_id 引用
SELECT DISTINCT sp.config_id
FROM stock_predictions sp
LEFT JOIN prediction_config pc ON sp.config_id = pc.id
WHERE sp.config_id IS NOT NULL AND pc.id IS NULL;

-- 清理无效引用（设置为NULL）
UPDATE stock_predictions sp
LEFT JOIN prediction_config pc ON sp.config_id = pc.id
SET sp.config_id = NULL
WHERE sp.config_id IS NOT NULL AND pc.id IS NULL;
```
