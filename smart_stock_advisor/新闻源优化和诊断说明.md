**问题**：当前只有2-3个新闻源能正常获取新闻，其他获取不到，特别是金十数据

## 一、优化内容

### 1.1 金十数据新闻源优化

**文件**：`quant_trading_platform/news/jin10_news_source.py`

**优化内容**：
1. **添加多个备用URL**：
   - URL 1: `https://flash-api.jin10.com/get_flash_list`（快讯API）
   - URL 2: `https://rili.jin10.com/dc/news/newsFlash`（日历API）
   - URL 3: `https://api.jin10.com/news/list`（官方API，需要密钥）

2. **添加请求头**：
   - User-Agent
   - Referer
   - Accept
   - Accept-Language

3. **改进数据解析**：
   - 支持多种响应格式（data、result、list）
   - 支持多种时间格式（时间戳毫秒/秒、字符串）
   - 支持多种字段名（title/headline/content）

4. **错误处理**：
   - 逐个尝试URL，失败后继续下一个
   - 详细的错误日志

### 1.2 统一新闻源优化

**文件**：`quant_trading_platform/news/unified_news_source.py`

**优化内容**：
1. **添加超时控制**：
   - 每个新闻源最多30秒超时
   - 使用线程独立执行，避免阻塞

2. **错误隔离**：
   - 单个新闻源失败不影响其他
   - 失败后继续下一个新闻源

3. **改进日志**：
   - 记录每个新闻源的获取情况
   - 超时和错误都有明确提示

## 三、金十数据问题分析

### 3.1 可能的原因

1. **URL失效**：
   - 原URL `https://rili.jin10.com/dc/news/newsFlash` 可能已失效
   - 需要找到新的API接口

2. **需要认证**：
   - 金十数据可能需要API密钥
   - 可能需要登录或Cookie

3. **反爬虫机制**：
   - 可能需要特定的请求头
   - 可能有频率限制

4. **接口变更**：
   - API接口可能已更新
   - 参数格式可能已改变

### 3.2 解决方案

1. **尝试多个URL**：
   - 已添加3个备用URL
   - 逐个尝试，找到可用的

2. **添加请求头**：
   - 模拟浏览器请求
   - 添加Referer等头部信息

3. **配置API密钥**（如果有）：
   - 在配置文件中添加 `JIN10_API_KEY`
   - 传递给 `UnifiedNewsSource`

4. **使用其他新闻源**：
   - 如果金十数据确实无法使用，可以暂时禁用
   - 使用其他可用的新闻源（如新浪财经、网易财经）

## 四、使用建议

### 4.1 运行诊断

首先运行诊断脚本，查看各新闻源的状态：
```bash
py scripts/diagnose_news_sources.py
```

### 4.2 根据结果调整

1. **如果金十数据超时**：
   - 检查网络连接
   - 尝试配置API密钥
   - 考虑暂时禁用金十数据

2. **如果其他新闻源失败**：
   - 查看错误信息
   - 检查URL是否有效
   - 检查是否需要特殊请求头

3. **优化可用新闻源**：
   - 优先使用能正常获取的新闻源
   - 在 `UnifiedNewsSource` 中调整顺序

## 五、临时解决方案

如果金十数据确实无法使用，可以暂时禁用：

**方法1：修改初始化顺序**
在 `unified_news_source.py` 中，将金十数据放到最后，或者添加开关。

**方法2：配置开关**
添加配置项控制是否启用金十数据：
