# 开始数据收集 - 快速指南

## ⚠️ 重要提示

1. **数据量大**：收集10年数据（约5000只A股 + 3000只美股）需要**数天时间**
2. **建议先测试**：先用测试模式验证脚本是否正常工作
3. **可以中断**：使用Ctrl+C中断后，可用`--resume`继续
4. **进度自动保存**：每只股票处理完后自动保存进度




## ⏱️ 时间估算

### A股（5000只股票，10年数据）

- **每只股票**：约2-3秒（包含延迟）
- **每批（50只）**：约2-3分钟
- **总批次数**：约100批
- **预计总时间**：约 **4-6小时**（连续运行）

### 美股（3000只股票，10年数据）

- **每只股票**：约1-2秒（yfinance通常较快）
- **每批（50只）**：约1-2分钟
- **总批次数**：约60批
- **预计总时间**：约 **2-3小时**（连续运行）

**注意**：实际时间取决于：
- 网络速度
- API响应速度
- API限制频率
- 数据库写入速度

## 🔍 检查进度

### Python脚本检查

```python
import json

with open('data/collect_progress_cn.json', 'r', encoding='utf-8') as f:
    progress = json.load(f)
    
print(f"总股票数: {progress['total_symbols']}")
print(f"已完成: {len(progress['completed_symbols'])}")
print(f"失败: {len(progress['failed_symbols'])}")
print(f"剩余: {progress['total_symbols'] - len(progress['completed_symbols']) - len(progress['failed_symbols'])}")
print(f"当前批次: {progress.get('current_batch', 0)}")
```

## 🛠️ 故障处理

### 1. API限制错误

**症状**：频繁出现"请求过于频繁"错误

**解决**：
- 增加延迟：`--delay 2.0`
- 减小批次：`--batch-size 20`
- 暂停一段时间后继续

### 2. 网络超时

**症状**：连接超时错误

**解决**：
- 检查网络连接
- 使用`--resume`继续（会自动跳过已完成的）

### 3. 数据库错误

**症状**：数据库连接失败或写入错误

**解决**：
- 检查数据库服务是否运行
- 检查数据库配置（`config_db.py`）
- 检查磁盘空间

### 4. 内存不足

**症状**：脚本运行缓慢或崩溃

**解决**：
- 减小批次大小：`--batch-size 20`
- 关闭其他占用内存的程序

## 💡 最佳实践

1. **先用测试模式验证**：确保脚本和数据库配置正确
2. **在非交易时间运行**：避开API高峰期
3. **保持网络稳定**：使用稳定的网络连接
4. **定期检查进度**：查看进度文件确认正常运行
5. **备份数据库**：大量数据收集前备份数据库
6. **分批进行**：如果时间有限，可以分多次收集
7. **监控资源**：注意CPU、内存、磁盘使用情况
