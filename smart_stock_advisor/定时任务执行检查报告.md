# 定时任务执行检查报告

## 一、调度机制概述

- **调度库**: `schedule`（Python 轻量级定时任务库）
- **调度线程**: 独立 daemon 线程，每秒执行一次 `schedule.run_pending()`
- **任务来源**: 从数据库 `scheduled_tasks` 表加载 `is_active=1` 的任务

## 二、调度类型与执行逻辑

| 类型 | 配置来源 | 执行方式 | 是否正确 |
|------|----------|----------|----------|
| **daily** | schedule_time（如 15:00） | 每天指定时间执行 | ✅ |
| **daily+weekdays** | schedule_weekdays（1-7） | 指定星期几执行 | ✅ |
| **hourly** | schedule_time 的分钟部分 | 每小时第 N 分钟执行 | ✅ |
| **interval** | task_config.interval_minutes | 每 N 分钟执行 | ✅ |
| **monthly** | task_config.schedule_month_day | 每月指定日期执行 | ✅ |
| **custom** | cron_expression | 当前退化为每天 15:05 | ⚠️ |

## 三、发现的潜在问题

### 1. 【重要】调度器延迟初始化

**现象**: `ScheduledTaskManager` 只在首次调用 `get_scheduled_task_manager()` 时创建，而该函数仅在访问任务相关 API 时被调用。

**影响**: 若服务器启动后无人访问「定时任务管理」相关页面或接口，**调度器不会启动，所有定时任务都不会执行**。

**建议**: 在 Web 应用启动时主动初始化调度器（例如在 `before_first_request` 或主模块加载时调用一次 `get_scheduled_task_manager()`）。

### 2. schedule_time 类型兼容

数据库字段 `schedule_time` 为 `TIME` 类型，可能返回 `datetime.time` 或字符串。代码中 `_normalize_schedule_time()` 已处理多种类型，**当前逻辑正确**。

### 3. interval 任务首次执行

`schedule.every(N).minutes.do(fn)` 会在调度器首次检查时立即执行一次（若已到时间），之后按间隔执行。**符合预期**。

### 4. 周末/节假日

调度器 **不区分** 周末和节假日，`daily` 任务在周末也会按设定时间触发。如需仅交易日执行，需在任务逻辑内部自行判断（部分任务如股票数据更新已使用 `get_next_trading_day`）。

## 四、执行流程验证

1. **加载**: `load_and_start_tasks()` → `SELECT * FROM scheduled_tasks WHERE is_active = 1`
2. **注册**: `_schedule_task()` 根据 `schedule_type` 注册到 `schedule` 库
3. **循环**: `_scheduler_loop()` 每秒执行 `schedule.run_pending()`
4. **执行**: `job.should_run` 为 True 时执行 `task_wrapper()` → `_execute_task(task_id)`

**结论**: 在调度器已启动的前提下，**会按配置的时间和频率执行**。

## 五、建议修复

在 `web_app.py` 中增加应用启动时初始化调度器，确保服务一启动就开始调度任务，而不依赖用户访问。
