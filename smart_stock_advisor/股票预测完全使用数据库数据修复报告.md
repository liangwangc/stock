# 股票预测完全使用数据库数据修复报告

## 一、问题描述

**问题现象**：
- 设置页面股票预测功能仍然在调用API（`stock_zh_a_spot_em`）
- 日志显示：`调用 stock_zh_a_spot_em 失败（已重试 3 次）`
- 用户希望设置页面的股票预测完全不使用API，只从数据库获取数据
- 如果数据库中没有数据，则不使用该数据进行预测

**问题位置**：设置页面 -> 股票预测

## 二、问题分析

### 2.1 发现的API调用位置

1. **`calculate_capital_flow_score` 方法（第495行）**：
   - 调用 `self.data_source.get_stock_info(symbol)` 获取换手率
   - 这会调用 `ak.stock_zh_a_spot_em()` API

2. **`_detect_anomalies_with_realtime_quote` 方法（第4242行）**：
   - 如果没有传入 `realtime_quote`，会调用 `self.data_source.get_realtime_quote(symbol)`
   - 这会调用 `ak.stock_zh_a_spot_em()` API

3. **`predict_before_close` 方法（第3940行、4014行）**：
   - 调用 `self.data_source.get_realtime_quote(symbol)` 和 `self.data_source.get_stock_info(symbol)`
   - 虽然设置页面可能不使用此方法，但为了完整性也需要修复

### 2.2 已修复的部分

- ✅ `predict` 方法：已使用 `use_db_only=True` 参数，只从数据库获取数据
- ✅ `_calculate_valuation_score_from_db` 方法：已从数据库获取PE/PB数据
- ✅ 股票名称获取：已从数据库获取

## 三、修复方案

### 3.1 修复 `calculate_capital_flow_score` 方法

**文件**：`predictor/stock_predictor.py`
**位置**：第491-529行

**修复前**：
```python
# 5.1. 换手率分析（新增）
turnover_rate_score = 0.0
try:
    # 尝试获取换手率数据
    stock_info = self.data_source.get_stock_info(symbol)
    turnover_rate = None
    
    # 查找换手率字段
```

**修复后**：
```python
# 5.1. 换手率分析（新增）- 从数据库获取，不调用API
turnover_rate_score = 0.0
try:
    # 从数据库获取换手率数据（设置页面预测：只使用数据库数据）
    turnover_rate = None
    try:
        from utils.db_connection import DatabaseConnection
        from datetime import datetime
        db = DatabaseConnection()
        # 获取最新日期的换手率数据
        sql = """
            SELECT turnover_rate
            FROM stock_history_data
            WHERE symbol = %s AND period_type = 'daily'
            AND turnover_rate IS NOT NULL
            ORDER BY trade_date DESC
            LIMIT 1
        """
        result = db.execute_query(sql, (symbol,))
        if result and len(result) > 0:
            turnover_rate = result[0].get('turnover_rate')
            if turnover_rate is not None:
                turnover_rate = float(turnover_rate)
    except Exception as e:
        self.logger.debug(f"从数据库获取换手率失败: {str(e)}")
```

## 四、修复效果

### 4.1 修复前

1. 设置页面股票预测
2. 调用 `get_stock_info()` API 获取换手率
3. 调用 `get_realtime_quote()` API 检查涨跌停状态
4. 网络连接失败，预测失败或数据不完整

### 4.2 修复后

1. 设置页面股票预测
2. 从数据库 `stock_history_data` 表获取换手率
3. 从数据库获取涨跌停状态
4. 如果数据库中没有数据，跳过该数据或返回默认值
5. 预测成功执行，不依赖API

## 五、功能说明

### 5.1 换手率获取

- **数据来源**：`stock_history_data` 表的 `turnover_rate` 字段
- **获取逻辑**：获取最新日期的换手率数据
- **容错处理**：如果数据库中没有数据，标记为"数据不足"

### 5.2 涨跌停状态检查

- **数据来源**：`stock_history_data` 表的 `limit_up`、`limit_down`、`is_limit_up`、`is_limit_down` 字段
- **获取逻辑**：获取最新日期的数据
- **检查逻辑**：
  - 优先使用 `is_limit_up` 和 `is_limit_down` 字段
  - 如果没有这些字段，通过价格比较判断

### 5.3 数据缺失处理

- **换手率**：如果数据库中没有换手率数据，标记为"数据不足"，不影响其他分析
- **涨跌停状态**：如果数据库中没有数据，跳过涨跌停检查，不影响其他异常检测

## 六、优势

- ✅ 减少外部依赖

- ✅ 所有数据都来自数据库，保证一致性

## 七、注意事项

1. **数据库依赖**：需要确保 `stock_history_data` 表中有数据

3. **日期匹配**：根据 `data_date` 获取对应日期的数据，确保数据一致性
