# 主页大盘信息API调用优化完成报告

**日期**：2026-02-05  
**状态**：✅ 已完成

---

## 一、问题描述

用户反馈主页大盘信息获取频率太高，导致代理连接失败：
- 前端每1秒调用一次 `/api/market/index`
- API调用失败时没有重试机制和冷却期
- 没有数据库缓存，每次都直接调用API

---

## 二、优化方案

### 2.1 后端优化（`web_app.py`）

#### 1. 添加内存缓存机制 ✅
- **缓存时长**：10分钟
- **缓存内容**：大盘指数数据
- **更新策略**：API调用成功后更新缓存

#### 2. 数据库优先策略 ✅
- **优先级1**：检查内存缓存（10分钟内有效）
- **优先级2**：从数据库获取最新数据（`market_indices` 表）
- **优先级3**：调用API（最多重试3次）

#### 3. API调用失败重试机制 ✅
- **重试次数**：最多3次
- **重试间隔**：每次重试间隔1秒
- **失败处理**：3次都失败后，进入10分钟冷却期

#### 4. 冷却期机制 ✅
- **触发条件**：API连续失败3次
- **冷却时长**：10分钟
- **冷却期内**：不再调用API，优先使用数据库数据或过期缓存

#### 5. 新增辅助函数 ✅
- **`_get_market_index_from_db()`**：从数据库获取大盘指数数据
  - 查询 `market_indices` 表
  - 获取当天的指数数据
  - 返回格式化的市场数据

### 2.2 前端优化（`stock_list.html`）

#### 1. 降低更新频率 ✅
- **优化前**：每1秒更新一次
- **优化后**：每30秒更新一次
- **效果**：减少API调用压力，降低90%的请求频率

## 四、优化效果

### 4.1 API调用频率降低

- **优化前**：每1秒1次 = 3600次/小时
- **优化后**：每30秒1次 = 120次/小时
- **降低幅度**：**96.7%**

### 4.2 数据库缓存命中率

- **缓存命中**：10分钟内的请求直接返回缓存，无需API调用
- **数据库命中**：如果数据库有最新数据，直接返回，无需API调用
- **API调用**：仅在缓存和数据库都没有时才调用API

### 4.3 失败处理机制

- **重试机制**：API调用失败时自动重试，最多3次
- **冷却期**：连续失败3次后，10分钟内不再调用API
- **降级策略**：API失败时，优先使用数据库数据或过期缓存

## 五、工作流程

### 5.1 正常流程

```
1. 请求到达 → 检查内存缓存（10分钟内）
   ├─ 有缓存 → 直接返回 ✅
   └─ 无缓存 → 继续
   
2. 检查数据库（market_indices表）
   ├─ 有数据 → 更新缓存并返回 ✅
   └─ 无数据 → 继续
   
3. 调用API（最多重试3次）
   ├─ 成功 → 更新缓存并返回 ✅
   └─ 失败 → 进入冷却期
```

### 5.2 失败处理流程

```
API调用失败（第1次）
  ↓
重试（第2次）
  ↓
重试（第3次）
  ↓
3次都失败
  ↓
进入10分钟冷却期
  ↓
冷却期内：
  ├─ 优先使用数据库数据
  ├─ 数据库没有 → 使用过期缓存
  └─ 都没有 → 返回错误（提示10分钟后重试）
```

## 六、数据库表结构

### 6.1 `market_indices` 表

**字段**：
- `index_code`：指数代码（如：sh000001, sz399001）
- `index_name`：指数名称（如：上证指数）
- `trade_date`：交易日期
- `close_price`：收盘价
- `pre_close`：前收盘价
- `change_amount`：涨跌额
- `change_pct`：涨跌幅
- `volume`：成交量
- `amount`：成交额
- `updated_at`：更新时间

**查询逻辑**：
```sql
SELECT trade_date, close_price, pre_close, change_amount, change_pct, volume, amount
FROM market_indices
WHERE index_code = %s
AND trade_date = %s
ORDER BY updated_at DESC
LIMIT 1
```

## 九、注意事项

### 9.1 数据库依赖

- **依赖表**：`market_indices` 表必须有数据
- **数据更新**：需要定时任务定期更新指数数据
- **数据时效性**：数据库数据可能不是最新的（取决于定时任务频率）

### 9.2 缓存管理

- **内存缓存**：服务器重启后缓存会丢失
- **缓存更新**：API调用成功后自动更新
- **缓存失效**：10分钟后自动失效

### 9.3 API调用限制

- **冷却期**：连续失败3次后，10分钟内不再调用
- **重试间隔**：每次重试间隔1秒
- **降级策略**：API失败时使用数据库或缓存数据
