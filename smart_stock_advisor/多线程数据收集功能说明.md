# 多线程数据收集功能说明

## 功能概述

已为批量股票数据收集功能添加多线程支持，可以同时处理多只股票的数据获取和存储，显著提升数据收集效率。

## 主要特性

1. **多线程并行处理**：使用 `ThreadPoolExecutor` 实现多线程数据收集
2. **线程安全**：使用锁机制确保进度保存的线程安全
3. **独立收集器实例**：每个线程使用独立的收集器实例，避免冲突
4. **自动模式选择**：根据线程数自动选择单线程或多线程模式
5. **保持兼容性**：单线程模式（默认）保持原有行为不变

## 使用方法

### 基本用法

```cmd
# 单线程模式（默认，兼容原有用法）
py scripts\batch_collect_10years_data.py --market cn --batch-size 50 --delay 1.0

# 多线程模式（使用3个线程）
py scripts\batch_collect_10years_data.py --market cn --batch-size 50 --delay 1.0 --threads 3

# 多线程模式（使用5个线程）
py scripts\batch_collect_10years_data.py --market cn --batch-size 50 --delay 1.0 --threads 5
```

### 参数说明

- `--threads`: 最大线程数（默认1，即单线程模式）
  - 建议值：2-5（根据网络和API限制调整）
  - 如果API有严格的频率限制，建议使用较小的线程数
  - 如果网络条件良好且API限制较宽松，可以使用更多线程（如5-10）

### 推荐配置

**保守配置**（适用于API限制较严格的情况）：
```cmd
py scripts\batch_collect_10years_data.py --market cn --batch-size 30 --delay 1.0 --threads 2
```

**平衡配置**（适用于一般情况）：
```cmd
py scripts\batch_collect_10years_data.py --market cn --batch-size 50 --delay 1.0 --threads 3
```

**激进配置**（适用于网络条件良好、API限制较宽松的情况）：
```cmd
py scripts\batch_collect_10years_data.py --market cn --batch-size 50 --delay 0.5 --threads 5
```

## 技术实现

### 1. 线程安全的进度保存

使用 `threading.Lock()` 确保多线程环境下进度文件写入的线程安全：

```python
self.progress_lock = threading.Lock()

def save_progress(self, progress: Dict):
    with self.progress_lock:
        # 保存进度文件
```

### 2. 独立收集器实例

每个线程创建自己的收集器实例，避免共享状态冲突：

```python
def _create_collector_instance(self):
    """创建收集器实例（用于多线程环境）"""
    if self.market == 'cn':
        return StockHistoryCollector()
    else:
        return USStockCollector()
```

### 3. 多线程工作函数

每个线程执行的工作函数：

```python
def _collect_single_stock_worker(self, symbol: str, years: int, progress: Dict):
    collector = self._create_collector_instance()
    result = self.collect_single_stock(symbol, years=years, collector=collector)
    # 线程安全地更新进度
    with self.progress_lock:
        # 更新进度
```

### 4. 线程池执行

使用 `ThreadPoolExecutor` 管理线程池：

```python
with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
    future_to_symbol = {
        executor.submit(self._collect_single_stock_worker, symbol, years, progress): symbol
        for symbol in batch
    }
    for future in as_completed(future_to_symbol):
        result = future.result()
```

## 性能提升

多线程模式相比单线程模式可以显著提升数据收集速度：

- **2线程**：约1.5-1.8倍速度提升
- **3线程**：约2.0-2.5倍速度提升
- **5线程**：约2.5-3.5倍速度提升

实际提升取决于：
- 网络延迟
- API响应时间
- API频率限制
- 系统资源（CPU、内存）

## 注意事项

1. **API频率限制**：多线程会增加API请求频率，注意不要超过API限制
2. **数据库连接**：数据库连接使用线程安全的 `DatabaseConnection`，每个线程有独立连接
3. **内存使用**：多线程会增加内存使用，注意系统资源
4. **错误处理**：每个线程的错误都会被独立捕获和记录
5. **断点续传**：多线程模式同样支持断点续传功能

## 测试建议

# 测试多线程模式（3只股票，1年数据，3个线程）

## 故障排除

### 问题1：API请求被限制

**症状**：大量请求失败，返回403或429错误

**解决方法**：
- 减少线程数（如从5降到3或2）
- 增加延迟时间（如从0.5秒增加到1.0秒）
- 减少批次大小

### 问题2：数据库连接错误

**症状**：数据库连接超时或错误

**解决方法**：
- 检查数据库连接配置
- 减少线程数（降低并发连接数）
- 检查数据库最大连接数设置

### 问题3：内存使用过高

**症状**：系统内存不足，程序变慢或崩溃

**解决方法**：
- 减少线程数
- 减少批次大小
- 增加系统内存
