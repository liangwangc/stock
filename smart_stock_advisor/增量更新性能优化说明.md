# 增量更新性能优化说明

**创建日期**：2026-01-15

---

## 一、问题

增量更新当日数据非常慢，十几分钟才更新100条。

---

## 二、优化方案

### 2.1 问题分析

**性能瓶颈**：
1. `collect_stock_daily_data()` 方法调用了太多API
2. 每个股票需要调用多个API（股票信息、K线数据、实时行情、买卖盘、成本分布、资金流向、融资融券等）
3. 每个API调用都需要等待响应，串行执行导致总时间很长

**API调用列表**（每个股票）：
- `get_stock_info()` - 获取股票信息
- `get_all_stock_list()` - 获取股票列表（如果缓存失效）
- `get_stock_data()` - 获取K线数据（前后各10天）
- `get_realtime_quote()` - 获取实时行情
- `get_bid_ask_data()` - 获取买卖盘数据
- `get_cost_distribution()` - 获取成本分布（很慢）
- `get_realtime_capital_flow()` - 获取资金流向
- `get_margin_trading_data()` - 获取融资融券数据

**估算**：如果每个API调用需要1-2秒，8个API调用就需要8-16秒/股票，100个股票就需要800-1600秒（13-27分钟）。

---

## 三、优化实现

### 3.1 快速模式（fast_mode）

**新增参数**：`collect_stock_daily_data(symbol, date, fast_mode=False)`

**快速模式优化**：
1. **优先从数据库获取历史数据**：用于计算技术指标，而不是从API获取前后10天
2. **只获取当日数据从API**：减少API调用范围
3. **跳过不必要的API调用**：
   - 买卖盘数据（历史数据不可用）
   - 成本分布（计算很慢）
   - 资金流向（历史数据不可用）
   - 融资融券数据（可以后续批量获取）
4. **优化股票名称获取**：优先从数据库获取，减少API调用

### 3.2 代码修改

**位置**：`utils/stock_history_collector.py`

**修改内容**：

1. **方法签名**：
```python
def collect_stock_daily_data(self, symbol: str, date: str, fast_mode: bool = False) -> Optional[Dict]:
```

2. **股票名称获取优化**：
```python
if fast_mode:
    # 快速模式：优先从数据库获取股票名称
    sql = "SELECT name FROM stock_history_data WHERE symbol = %s LIMIT 1"
    result = self.storage.db.execute_query(sql, (str(symbol).zfill(6),))
    if result and len(result) > 0:
        stock_name = result[0].get('name', '')
```

3. **K线数据获取优化**：
```python
if fast_mode:
    # 快速模式：只获取当日数据从API，历史数据从数据库获取
    days_data = self.data_source.get_stock_data(symbol, start_date=date, end_date=date)
    
    # 从数据库获取历史数据（用于计算技术指标）
    history_data = self.storage.get_stock_history_data(
        symbol=symbol,
        start_date=history_start,
        end_date=history_end,  # 排除当日

```

4. **跳过不必要的API调用**：
```python
# 买卖盘数据（快速模式：跳过）
if not fast_mode:
    bid_ask = self.data_source.get_bid_ask_data(symbol)
    # ...

# 成本分布（快速模式：跳过）
if not fast_mode:
    cost_dist = self.data_source.get_cost_distribution(symbol)
    # ...

# 资金流向（快速模式：跳过）
if not fast_mode:
    capital_flow = self.data_source.get_realtime_capital_flow(symbol)
    # ...

# 融资融券（快速模式：跳过）

    margin_data = self.data_source.get_margin_trading_data(symbol)
    # ...
```

5. **增量更新调用快速模式**：
```python
# 多线程模式
data = self.collect_stock_daily_data(symbol, today, fast_mode=True)

# 单线程模式
data = self.collect_stock_daily_data(symbol, today, fast_mode=True)
```

## 四、性能提升

### 4.1 API调用次数对比

| 模式 | API调用次数/股票 | 说明 |
|-----|----------------|------|
| **普通模式** | 8次 | 所有API都调用 |
| **快速模式** | 2次 | 只调用实时行情和当日K线数据 |

**减少**：75%的API调用

### 4.2 性能估算

**优化前**（普通模式）：
- 每个股票：8个API调用 × 1-2秒 = 8-16秒
- 100个股票：800-1600秒（13-27分钟）

**优化后**（快速模式）：
- 每个股票：2个API调用 × 1-2秒 = 2-4秒
- 100个股票：200-400秒（3-7分钟）
- **多线程（10线程）**：20-40秒

**性能提升**：**3-7倍**

## 五、使用说明

### 5.1 自动启用

**增量更新自动使用快速模式**：
- `incremental_update_today()` 方法自动调用 `fast_mode=True`
- 无需手动配置

### 5.2 手动使用

**如果需要完整数据**（非快速模式）：
```python
data = collector.collect_stock_daily_data(symbol, date, fast_mode=False)
```

**如果需要快速更新**（快速模式）：
```python
data = collector.collect_stock_daily_data(symbol, date, fast_mode=True)
```

## 六、注意事项

### 6.1 快速模式跳过的数据

**以下数据在快速模式下会被跳过**（设置为None）：
- 买卖盘数据（`bid_levels`, `ask_levels`, `bid_ask_ratio`等）
- 成本分布（`cost_distribution`, `cost_distribution_intraday`）
- 资金流向（`main_net_inflow`, `large_inflow`等）
- 融资融券数据（`margin_balance`, `short_balance`等）

**如果需要这些数据**：
- 可以后续批量获取
- 或使用普通模式（`fast_mode=False`）

### 6.2 技术指标计算

**快速模式下技术指标仍然计算**：
- 从数据库获取历史数据（60天）
- 计算MA5/10/20/60、RSI、MACD、X2等
- 性能不受影响（数据库查询很快）

## 七、总结

### 7.1 优化效果

✅ **API调用减少75%**：从8次减少到2次  
✅ **性能提升3-7倍**：从13-27分钟减少到3-7分钟（单线程）或20-40秒（10线程）  
✅ **自动启用**：增量更新自动使用快速模式  
✅ **向后兼容**：普通模式仍然可用

### 7.2 适用场景

**快速模式适用于**：
- ✅ 增量更新当日数据
- ✅ 批量更新多只股票
- ✅ 对性能要求高的场景

**普通模式适用于**：
- ✅ 需要完整数据（买卖盘、成本分布、资金流向等）
- ✅ 单只股票详细数据采集
- ✅ 对数据完整性要求高的场景
