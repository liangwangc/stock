# 历史预测实际数据字段来源说明

## 概述

历史预测详情页面（`history.html`）中显示的以下字段来自`stock_predictions`表：
- `actual_price`：实际价格
- `actual_change_pct`：实际涨跌幅
- `actual_direction`：实际方向
- `prediction_hit`：预测命中

### 4. 实际数据来源（推测）

根据代码逻辑和数据库结构，实际数据应该从以下来源获取：

#### 4.1 实际价格（actual_price）
- **来源**：`stock_history_data`表的`close_price`字段
- **查询条件**：`symbol = 股票代码` AND `trade_date = target_date`
- **获取方式**：从数据库`stock_history_data`表查询目标日期的收盘价

#### 4.2 实际涨跌幅（actual_change_pct）
- **计算方式**：`(actual_price - current_price) / current_price * 100`
- **其中**：
  - `actual_price`：目标日期的收盘价（从`stock_history_data`表获取）
  - `current_price`：预测时的价格（存储在`stock_predictions.current_price`字段）

#### 4.3 实际方向（actual_direction）
- **判断逻辑**：
  ```python
  if actual_change_pct > 0:
      actual_direction = '上涨'
  elif actual_change_pct < 0:
      actual_direction = '下跌'
  else:
      actual_direction = '平盘'
  ```

#### 4.4 预测命中（prediction_hit）
- **判断逻辑**（第2057-2071行）：
  ```python
  hit = '未知'
  if change_val is not None:
  ```

## 数据流程图

```
1. 用户访问历史预测页面
   ↓
2. 前端调用 /api/history?symbol=股票代码
   ↓
3. 后端API自动调用 _update_historical_actual_data()
   ↓
4. 查询需要更新的记录（target_date < 今天 且 actual_price 为空）
   ↓
5. 对每条记录：
   a. 调用数据源获取目标日期的实际数据
      - 从 stock_history_data 表查询 target_date 的收盘价
      - 计算实际涨跌幅 = (实际收盘价 - 预测时价格) / 预测时价格 * 100
      - 判断实际方向（上涨/下跌/平盘）
      - 判断预测命中（命中/未命中）
   b. 调用 update_prediction_actual() 更新数据库
   ↓
6. 从数据库读取所有预测记录（包含已更新的实际数据）
   ↓
7. 返回JSON数据给前端
   ↓
8. 前端渲染显示
```

## 注意事项

1. **数据更新时机**：
   - 每次保存新预测时自动更新所有历史记录
   - 查看历史页面时也会触发更新
   - 双重保障确保数据及时更新

2. **更新条件**：
   - 只更新`target_date < 今天`的记录
   - 只更新`actual_price`为空的记录（避免重复更新）

3. **数据来源**：
   - 实际价格从`stock_history_data`表的`close_price`字段获取
   - 需要确保`stock_history_data`表中有目标日期的数据

4. **预测命中判断**：
   - 上涨预测：实际涨跌幅 > 0 算命中
   - 下跌预测：实际涨跌幅 < 0 算命中
   - 震荡预测：实际涨跌幅在 -0.5% 到 0.5% 之间算命中

5. **可能的问题**：
   - 如果`stock_history_data`表中没有目标日期的数据，实际数据将无法更新
   - 如果目标日期是周末或节假日，可能无法获取实际数据
   - `get_actual_stock_change()`方法可能不存在，需要检查`StockDataSource`类中是否有该方法

## 建议

1. **检查数据源方法**：
   - 确认`StockDataSource`类中是否有`get_actual_stock_change()`方法
   - 如果没有，需要实现该方法，从`stock_history_data`表获取数据

2. **添加日志**：
   - 在更新实际数据时添加详细日志，记录更新成功和失败的记录数

3. **错误处理**：
   - 如果无法获取实际数据，应该记录错误日志，但不影响其他记录的更新

4. **批量更新**：
   - 可以考虑在非预测时间批量更新所有历史记录，而不是每次访问时更新
