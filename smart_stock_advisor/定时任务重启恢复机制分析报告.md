## 一、当前机制分析

### 1.1 ScheduledTaskManager 初始化流程

**文件**：`utils/scheduled_task_manager.py`

**初始化流程**：
```python
def __init__(self):
    # 1. 初始化数据库连接
    self.db = DatabaseConnection()
    
    # 2. 确保表存在
    self._ensure_tables_exist()
    
    # 3. 启动调度器线程
    self.start_scheduler()  # ← 关键：会自动加载任务

def start_scheduler(self):
    # 启动调度器线程
    self.scheduler_thread = threading.Thread(...)
    self.scheduler_thread.start()
    
    # 加载并启动所有启用的任务 ← 关键
    self.load_and_start_tasks()

def load_and_start_tasks(self):
    # 从数据库加载所有 is_active = 1 的任务
    sql = "SELECT * FROM scheduled_tasks WHERE is_active = 1"
    tasks = self.db.execute_query(sql)
    
    # 调度每个任务
    for task in tasks:
```

## 二、服务重启后的行为

### 2.1 重启流程

```
服务停止
    ↓
所有线程停止（包括调度器线程）
    ↓
全局变量重置（scheduled_task_manager = None）
    ↓
服务重启
    ↓
第一次调用 get_scheduled_task_manager()
    ↓
创建新的 ScheduledTaskManager 实例
    ↓
__init__() → start_scheduler() → load_and_start_tasks()
    ↓
从数据库加载 is_active = 1 的任务
    ↓
自动调度并启动这些任务
```

### 2.2 恢复机制

**✅ 会自动恢复的任务**：
- 所有 `is_active = 1` 的任务
- 任务配置保存在数据库中
- 重启后会自动从数据库加载

**❌ 不会恢复的状态**：
- 正在执行的任务会被中断
- 任务的执行状态（running）会丢失
- 下次执行时间会重新计算

## 四、潜在问题

### 4.1 问题1：延迟初始化可能导致任务未及时加载

**问题描述**：
- `get_scheduled_task_manager()` 是延迟初始化的
- 如果服务启动后没有调用相关API，任务管理器可能不会初始化
- 导致任务不会自动加载

**影响**：
- 任务不会自动启动
- 需要手动触发一次API调用（如访问设置页面）

**解决方案**：
在 `web_app.py` 的启动代码中主动初始化：
```python
if __name__ == '__main__':
    # 主动初始化定时任务管理器
    get_scheduled_task_manager()
    
    # 启动Flask应用
    app.run(...)
```

### 4.2 问题2：新闻任务管理器可能不会自动恢复

**问题描述**：
- `NewsTaskManager` 不使用 `ScheduledTaskManager`
- 新闻任务存储在 `news_crawl_tasks` 表中
- `NewsTaskManager` 初始化时不会自动加载任务

**影响**：
- 新闻抓取任务不会自动恢复
- 需要手动启动

**解决方案**：
在 `NewsTaskManager.__init__()` 中添加自动加载逻辑（如果还没有的话）

### 4.3 问题3：任务执行状态丢失

**问题描述**：
- 重启时，正在执行的任务会被中断
- 任务的执行状态不会保存
- 无法知道任务是否正在执行

**影响**：
- 如果任务执行时间很长，重启会中断执行
- 可能导致数据不一致

**解决方案**：
- 在任务执行前记录状态
- 在任务完成后更新状态
- 重启时检查是否有未完成的任务

```python
def load_and_start_tasks(self):
```

## 七、总结

### 7.1 当前状态（改进后）

**✅ 支持自动恢复的任务类型**（存储在 `scheduled_tasks` 表，`is_active = 1`）：

1. **股票数据任务**：

2. **股票分析任务**：
   - `stock_analysis` - 股票分析任务（全量分析/个股分析）

3. **模型训练/学习任务**：
   - `model_evaluation` - 模型评估任务

   - `adaptive_optimization` - 自适应优化任务

   - `news_crawl` - 新闻抓取任务（通过 `ScheduledTaskManager` 创建的任务）

5. **备份任务**：
   - `backup` - 数据备份任务

**❌ 不支持自动恢复**：
- `NewsTaskManager` 管理的新闻抓取任务（存储在 `news_crawl_tasks` 表，需要手动启动）
- `analysis_tasks` 表中的股票分析任务（一次性任务，不会自动恢复）
- 任务的执行状态（正在执行的任务会被中断）

### 7.2 答案

**问题**：服务重启后，定时任务是否可用？是否包含股票分析和模型训练等任务？

**答案**：
- ✅ **完全可用**：所有存储在 `scheduled_tasks` 表中的任务都会自动恢复
- ✅ **包含股票分析**：`stock_analysis` 类型的任务会自动恢复
- ✅ **包含模型训练**：所有模型相关任务（`model_evaluation`、`model_optimization`、`adaptive_optimization`、`comprehensive_evaluation`、`online_learning`、`model_backtest`、`automated_backtest`）都会自动恢复
- ✅ **已改进**：服务启动时会主动初始化，确保任务及时加载
- ⚠️ **部分可用**：`NewsTaskManager` 管理的新闻抓取任务（存储在 `news_crawl_tasks` 表）不会自动恢复（需要手动启动）
