# 股票预测数据查询流程说明

## 一、查询流程概述

主页搜索股票的查询流程如下：

### 1. API入口 (`/api/stocks`)
- **文件**: `web_app.py` 的 `api_get_stocks()` 函数
- **参数**:
  - `prediction_type`: 预测类型（`after_close`=收盘-明日，`before_close`=未收盘-明天）
  - `search`: 搜索关键词（股票代码或名称）
  - `target_date`: 目标日期过滤（可选）
  - `page`: 页码
  - `page_size`: 每页数量

### 2. 数据库查询 (`get_predictions`)
- **文件**: `utils/stock_prediction_db.py` 的 `get_predictions()` 方法
- **功能**: 从 `stock_predictions` 表查询数据
- **映射关系**:
  - `prediction_type='after_close'` → `stock_type='收盘-明日'`
  - `prediction_type='before_close'` → `stock_type='未收盘-明日'`

### 3. SQL查询逻辑

```sql
-- 实际执行的SQL（示例）
SELECT * FROM stock_predictions 
WHERE stock_type = '收盘-明日' AND stock_type IS NOT NULL
ORDER BY prediction_time DESC
LIMIT 1000;
```

### 4. 数据过滤流程

1. **第一步**: 从数据库获取所有 `after_close` 类型的记录（最多1000条，不限制日期）
2. **第二步**: 根据 `target_date` 过滤（默认先尝试今天，如果没有再尝试明天）
3. **第三步**: 去重（每个股票只保留最新的一条）
4. **第四步**: 应用搜索关键词过滤（如果提供了搜索关键词）
5. **第五步**: 应用其他过滤条件（预测方向、置信度等）
6. **第六步**: 分页处理

## 二、可能的问题点

### 问题1: 数据库中没有数据
**检查SQL**:
```sql
-- 检查是否有 after_close 类型的数据
SELECT COUNT(*) 
FROM stock_predictions 
WHERE stock_type = '收盘-明日';
```

### 问题2: target_date 不匹配
**检查SQL**:
```sql
-- 查看最近的数据，看看 target_date 是什么
SELECT 
    symbol,
    name,
    stock_type,
    prediction_date,
    target_date,
    prediction_time
FROM stock_predictions
WHERE stock_type = '收盘-明日'
ORDER BY prediction_time DESC
LIMIT 20;
```

### 问题3: 搜索关键词不匹配
**检查SQL**:
```sql
-- 查看数据中的 symbol 和 name 字段
SELECT 
    symbol,
    name,
    LENGTH(symbol) as symbol_len,
    LENGTH(name) as name_len
FROM stock_predictions
WHERE stock_type = '收盘-明日'
  AND target_date = CURDATE()
LIMIT 10;
```

### 问题4: 数据去重后为空
**可能原因**:
- 所有记录的 `symbol` 字段为空或无效
- 所有记录的 `prediction_time` 字段为空或无效

## 三、调试日志说明

现在代码中添加了详细的调试日志，日志级别为 `INFO` 和 `WARNING`，包括：

1. **【API请求】**: 记录请求参数
2. **【数据加载】**: 记录从数据库获取的记录数
3. **【数据去重】**: 记录去重后的记录数
4. **【搜索过滤】**: 记录搜索过滤过程
5. **【SQL查询】**: 记录实际执行的SQL语句和参数

## 四、排查步骤

### 步骤1: 检查后端日志
查看后端日志，寻找以下关键信息：
- `【API请求】` - 确认请求参数是否正确
- `【数据加载】` - 确认是否从数据库获取到数据
- `【数据去重】` - 确认去重后是否有数据
- `【搜索过滤】` - 确认搜索过滤是否正常工作

### 步骤2: 执行诊断SQL
执行 `database/诊断搜索功能数据的SQL.sql` 中的SQL语句，检查：
- 数据库中是否有数据
- `target_date` 字段的值是什么
- `symbol` 和 `name` 字段是否有值

### 步骤3: 检查前端请求
在浏览器中打开开发者工具（F12），查看：
- Network 标签页中的 `/api/stocks` 请求
- 请求参数是否正确
- 响应数据是什么

## 五、常见问题解决方案

### 问题: 主页没有显示数据
**可能原因**:
1. 数据库中没有 `stock_type='收盘-明日'` 的数据
2. `target_date` 不匹配（数据是明天的，但查询的是今天的）
3. 数据去重后为空

**解决方案**:
1. 执行诊断SQL检查数据
2. 查看后端日志，确认数据加载情况
3. 如果数据存在但日期不匹配，可以手动指定 `target_date` 参数

### 问题: 搜索关键词没有匹配结果
**可能原因**:
1. `symbol` 或 `name` 字段为空
2. 搜索关键词格式不匹配（大小写、空格等）

**解决方案**:
1. 检查数据中的 `symbol` 和 `name` 字段
2. 尝试搜索完整的股票代码（如 `600519`）
3. 查看后端日志中的 `【搜索过滤】` 信息
