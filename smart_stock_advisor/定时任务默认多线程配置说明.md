## 二、默认配置

### 2.1 中国股票增量更新

| 参数 | 默认值 | 说明 |
|-----|--------|------|
| **threads** | **15** | 线程数（多线程模式） |
| batch_size | 1000 | 批次大小 |
| delay | 1.0 | 延迟时间（秒） |

### 2.2 执行模式

**默认模式**：多线程模式（`max_workers = 15 > 1`）

**执行方式**：
- 使用 `ThreadPoolExecutor` 并行处理
- 调用 `_collect_single_cn_stock_worker()` 工作函数
- 每个工作函数调用 `collect_stock_daily_data(symbol, today, fast_mode=True)`

## 三、性能影响

### 3.1 线程数对比

| 线程数 | 100只股票预计耗时 | 说明 |
|-------|------------------|------|
| 1（单线程） | 约42.5分钟 | 串行处理 |
| 10（多线程） | 约4.25分钟 | 并行处理 |
| **15（多线程）** | **约2.8分钟** | **并行处理（更快）** |

### 3.2 性能提升

**从10线程提升到15线程**：
- 性能提升：约 **1.5倍**
- 100只股票：从 4.25分钟 降低到 2.8分钟

## 四、使用说明

### 4.1 设置页面创建任务

**默认行为**：
- 创建增量更新任务时，默认使用15个线程
- 自动使用多线程模式
- 无需手动配置

**手动配置**（可选）：
- 如果需要修改线程数，可以在创建任务时指定
- 但前端界面可能没有提供线程数输入框（使用默认值15）

### 4.2 代码调用

**直接调用**：
```python
# 使用默认15个线程
collector.incremental_update_today(symbols, max_workers=15, batch_size=1000)
```

**通过定时任务**：
```python
# 创建任务时，如果不指定threads，默认使用15
task_config = {
    'collection_type': 'incremental',
    'threads': 15  # 默认值
}
```

## 五、注意事项

### 5.1 线程数建议

**推荐范围**：10-20个线程

**考虑因素**：
- CPU核心数
- 网络带宽
- API速率限制
- 数据库连接数

**当前设置**：15个线程（平衡性能和资源使用）

### 5.2 性能监控

**如果性能仍然慢**：
1. 检查网络连接（API响应速度）
2. 检查数据库性能（查询速度）
3. 检查CPU使用率（是否达到瓶颈）
4. 可以适当增加线程数（但不要超过20）
