# 新闻表创建和时间过滤修复说明

## 问题1：SQL执行错误

### 问题描述
```
错误: (1064, "You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'CREATE TABLE IF NOT EXISTS `news_crawl_tasks` (\n    `id` BIGINT AUTO_INCREMENT P' at line 67")
```

### 原因分析
1. `news_table.sql` 文件包含多个 `CREATE TABLE` 语句：
   - `news_articles` 表（第4-64行）
   - `news_crawl_tasks` 表（第67-87行）
2. `_ensure_news_table_exists` 方法试图一次性执行整个SQL文件
3. MySQL的 `execute_update` 方法可能不支持在一个调用中执行多个CREATE TABLE语句
4. 用户反馈表已经建好了，不需要重复创建

### 修复方案
修改 `smart_stock_advisor/utils/news_storage.py` 中的 `_ensure_news_table_exists` 方法：

1. **先检查表是否存在**：
   ```python
   check_sql = "SHOW TABLES LIKE 'news_articles'"
   result = DBConnection.execute_query(check_sql)
   if result and len(result) > 0:
       # 表已存在，不需要创建
       return
   ```

2. **如果表不存在，只提取 `news_articles` 表的CREATE语句**：
   ```python
   # 使用正则表达式提取 news_articles 表的CREATE语句
   pattern = r'CREATE TABLE IF NOT EXISTS `news_articles`.*?;'
   match = re.search(pattern, sql_content, re.DOTALL | re.IGNORECASE)
   if match:
       create_sql = match.group(0)
       DBConnection.execute_update(create_sql)
   ```

3. **优点**：
   - 避免执行多个CREATE TABLE语句导致的SQL语法错误
   - 如果表已存在，直接跳过，提高效率
   - 只创建需要的表，不影响其他表

## 问题2：时间过滤逻辑优化

### 用户需求
"新闻获取，如果没获取到新闻时间，则不需要存储，避免干扰"

### 修复方案

#### 1. `smart_stock_advisor/utils/news_crawler.py`
在 `crawl_all_news` 方法中，优化时间过滤逻辑：

**时间过滤阶段**：

        # 没有时间信息，跳过，不进行存储

    # 如果有时间信息，再进行时间范围检查

        continue

### 修复效果
1. **没有时间的新闻不会被存储**：避免因为时间信息缺失而存储无效数据

3. **减少干扰**：避免无时间信息的新闻影响时间范围统计和分析
