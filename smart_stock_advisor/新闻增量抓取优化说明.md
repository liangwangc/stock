# 新闻增量抓取优化说明

## 优化内容

### 1. 改为增量获取

**之前**：
- `crawl_all_news()` 获取所有新闻（不限制日期）

**现在**：
- `crawl_all_news()` 改为增量获取，基于上次获取时间
- 计算时间范围：从 `last_fetch_time` 到当前时间
- 首次获取：从当天00:00开始

### 2. 处理凌晨00:00的情况

**逻辑**：
- 如果 `last_fetch_time` 是凌晨00:00，往前推10分钟（到前一天23:50）
- 如果当前时间是凌晨00:00-00:10，首次获取时往前推10分钟到前一天23:50
- 这样可以在凌晨也能获取到数据

### 3. 时间范围过滤

**逻辑**：
- 获取新闻后，按时间范围过滤
- 只保留 `start_time <= 新闻时间 <= end_time` 的新闻
- 确保增量获取，不重复获取旧新闻

### 4. 去重

**逻辑**：
- `unified_news_source.get_market_news()` 已经实现了去重（基于标题）
- `save_news_article()` 也实现了重复检测（基于标题+来源，以及SimHash）
- 确保多个新闻源的新闻不会重复保存

## 使用说明

### 任务创建

1. 在设置页面 -> 新闻数据获取
2. 点击"创建新任务"
3. 选择任务类型：**全部（全量新闻）**
4. 设置执行时间和间隔
5. 创建并启动任务

### 执行逻辑

1. **首次执行**：
   - 如果当前时间不是凌晨00:00-00:10，从当天00:00开始获取
   - 如果当前时间是凌晨00:00-00:10，从前一天23:50开始获取

2. **后续执行**：
   - 从上次执行时间（`last_run_time`）开始获取
   - 如果上次执行时间是凌晨00:00，往前推10分钟
   - 到当前时间结束

3. **时间过滤**：
   - 只保存时间范围内的新闻
   - 确保增量获取，不重复

4. **去重**：
   - 多个新闻源自动去重（基于标题）
   - 数据库保存时再次去重（基于标题+来源，以及SimHash）

## 注意事项

1. **时间范围计算**：
   - 基于 `last_run_time` 和 `interval_minutes`
   - 考虑凌晨00:00的特殊情况

2. **首次执行**：
   - 如果没有 `last_run_time`，从当天00:00开始
   - 如果当前时间是凌晨00:00-00:10，从前一天23:50开始

3. **去重**：
   - 多级去重：新闻源聚合时去重，数据库保存时去重
   - 确保不会重复保存

4. **性能**：
   - 增量获取，减少数据量
   - 提高抓取效率
