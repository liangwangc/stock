# 增量更新数据库锁竞争优化说明

**日期**：2026-01-16  
**问题**：增量更新运行时，查询stock_history_data表很慢

---

## 一、问题分析

### 1.1 问题现象

在定时获取股票数据（增量更新）运行时：
- ❌ 打开`stock_history_data`表查询数据很慢
- ❌ 查询操作被阻塞
- ❌ 影响用户体验

### 1.2 问题原因

**主要原因**：数据库锁竞争

1. **批量写入操作持有锁**
   - 批量INSERT/UPDATE操作时，会检查唯一索引 `uk_symbol_date`
   - 大量并发写入时，锁持有时间较长
   - 查询操作被写入操作阻塞

2. **批次大小过大**
   - 批次大小设置为400-600，单次操作处理大量数据
   - 单次操作锁持有时间过长

3. **不必要的commit操作**
   - 即使`autocommit=True`，代码中仍然调用`conn.commit()`
   - 可能导致不必要的锁竞争

---

## 二、优化方案

### 2.1 优化commit逻辑 ✅

**修改位置**：`utils/db_connection.py`

**问题**：
- `execute_update`和`execute_many`方法中，即使`autocommit=True`，也调用了`conn.commit()`
- 在autocommit模式下，PyMySQL会自动提交，不需要手动commit
- 手动commit可能导致不必要的锁竞争

**修改前**：
```python
if not DB_CONFIG.get('autocommit', True):
    conn.commit()
else:
    conn.commit()  # 确保提交（多余的操作）
```

**修改后**：
```python
# 如果autocommit=True，PyMySQL会自动提交，不需要手动commit
# 手动commit可能导致不必要的锁竞争，影响查询性能
if not DB_CONFIG.get('autocommit', True):
    conn.commit()
# autocommit=True时，不需要手动commit，避免锁竞争
```

**效果**：
- ✅ 减少不必要的commit操作
- ✅ 减少锁竞争
- ✅ 提升查询响应性

---

### 2.2 优化批量保存批次大小 ✅

**修改位置**：`utils/stock_history_storage.py` 第507行

**优化策略**：
- 虽然传入的`batch_size`可能较大（400-600），但实际保存时使用较小的批次（150）
- 这样可以减少单次操作的锁持有时间，让查询操作有机会执行

**修改前**：
```python
for batch_start in range(0, total_count, batch_size):
    batch_end = min(batch_start + batch_size, total_count)
    current_batch = batch_data[batch_start:batch_end]
```

**修改后**：
```python
# 优化：使用较小的批次大小进行实际保存，减少锁持有时间，提升查询性能
# 虽然传入的batch_size可能较大（400-600），但实际保存时使用较小的批次（150）
# 这样可以减少单次操作的锁持有时间，让查询操作有机会执行
actual_save_batch_size = min(batch_size, 150)  # 实际保存批次大小限制为150，减少锁竞争

for batch_start in range(0, total_count, actual_save_batch_size):
    batch_end = min(batch_start + actual_save_batch_size, total_count)
    current_batch = batch_data[batch_start:batch_end]
```

**效果**：
- ✅ 减少单次操作的锁持有时间
- ✅ 让查询操作有机会执行
- ✅ 提升查询响应性

---

### 2.3 添加批量操作间延迟 ✅

**修改位置**：`utils/stock_history_storage.py` 第1091-1095行

**优化策略**：
- 在批量操作之间添加短暂延迟（10毫秒）
- 让查询操作有机会执行

**新增代码**：
```python
# 批量操作后，短暂延迟，让查询操作有机会执行（减少锁竞争）
# 注意：这个延迟很小（0.01秒），不会显著影响性能，但可以提升查询响应性
import time
batch_index = batch_start // actual_save_batch_size
if batch_index > 0 and batch_index % 3 == 0:  # 每3个批次延迟一次（跳过第一个批次）
    time.sleep(0.01)  # 10毫秒延迟，让查询有机会执行
```

**效果**：
- ✅ 每3个批次延迟10毫秒，让查询有机会执行
- ✅ 延迟很小，不会显著影响写入性能
- ✅ 大幅提升查询响应性
