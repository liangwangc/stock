# ML模型训练策略说明

## 一、模型训练对股票预测的影响

### 1.1 权重分配逻辑

**当前权重配置**：
- ML模型权重：**15%**
- 其他8个因子权重：**85%**（技术指标20%、新闻25%、资金流向18%、市场情绪17%、板块轮动5%、历史模式8%、估值指标2%、美股板块5%）

**权重计算流程**：
1. 首先计算8个传统因子的权重（考虑市场状态、历史准确率优化等）
2. 尝试加载激活的ML模型进行预测
3. 如果ML模型可用，将ML权重（15%）加入总权重计算
4. **统一归一化**：所有权重（包括ML权重）归一化，确保总和为100%
5. 计算最终得分：`final_score = Σ(因子得分 × 归一化权重)`

**公式示例**：
```
假设8个因子归一化后权重总和为0.85，ML权重为0.15
归一化后：
- ML权重 = 0.15 / (0.85 + 0.15) = 0.15
- 其他因子权重 = 0.85 / (0.85 + 0.15) = 0.85

最终得分 = ML得分 × 0.15 + 其他因子得分 × 0.85
```

### 1.2 模型预测逻辑

**ML模型预测流程**：
1. 优先使用分类器模型（XGBoost分类器 > LightGBM分类器）
2. 如果没有分类器，使用回归器模型（XGBoost回归器 > LightGBM回归器）
3. 如果ML模型预测失败，自动降级为传统多因子预测（不影响主流程）

**ML模型得分计算**：
- **分类器**：`ml_score = (up_probability - 0.5) × 2`（范围：-1到1）
- **回归器**：`ml_score = predicted_change_pct / 10.0`（归一化到-1到1）

### 1.3 对预测结果的影响

**正面影响**：
- ✅ ML模型基于历史数据学习，能够识别复杂的非线性模式
- ✅ 提升预测准确率（如果模型训练良好）
- ✅ 作为额外的因子，增强预测的稳定性

**潜在风险**：
- ⚠️ 如果模型训练不当，可能引入噪声
- ⚠️ ML模型权重固定为15%，无法根据模型表现动态调整
- ⚠️ 模型预测失败时自动降级，但可能影响预测一致性

**建议**：
- 定期评估ML模型的预测准确率
- 如果ML模型表现不佳，可以暂时停用（不激活模型）
- 根据实际效果调整ML模型权重（需要修改代码）

## 二、训练策略

### 2.1 历史数据训练（基础模型）

**数据来源**：`stock_history_data` 表（近10年历史数据）

**训练目的**：
- 建立稳定的基础模型
- 学习历史价格模式和技术指标规律
- 为后续微调提供基础

**训练频率**：

| 场景 | 建议频率 | 说明 |
|------|---------|------|
| **首次部署** | 必须训练一次 | 建立基础模型，系统才能使用ML预测 |
| **稳定运行** | 每3-6个月重训一次 | 适应市场环境变化，但避免过度训练 |
| **市场变化** | 及时重训 | 如政策调整、市场风格切换等重大变化 |
| **不建议** | 每周/每月频繁训练 | 历史数据相对稳定，频繁训练可能导致过拟合 |

**训练时间**：
- 数据量：10年历史数据，约5000+只股票
- 预计时间：30分钟到2小时（取决于数据量和模型类型）
- 建议时间：非交易时间（晚上或周末）

**训练后操作**：
1. 训练完成后，模型会自动保存到数据库
2. 需要手动激活模型（在"已训练模型列表"中点击"激活"）
3. 激活后立即生效，应用到所有股票预测

---

### 2.2 预测数据训练（模型微调）

**数据来源**：`stock_predictions` 表（有实际结果的预测数据）

**训练目的**：
- 基于实际预测效果微调模型
- 提升预测准确率
- 适应最新的市场特征

**训练频率**：

| 场景 | 建议频率 | 说明 |
|------|---------|------|
| **新系统** | 运行1-2周后开始 | 需要积累至少1000条预测记录 |
| **稳定运行** | 每周1-2次 | 如每周日晚上执行，持续优化模型 |
| **数据充足** | 可适当增加频率 | 如果每天有大量预测数据，可每周2-3次 |
| **不建议** | 每天执行 | 数据变化不大，频繁训练效果有限 |

**最少样本要求**：
- **最少样本数**：1000条有实际结果的预测记录
- **建议样本数**：2000+条（效果更好）
- **数据检查**：训练前会自动检查数据可用性

**训练时间**：
- 数据量：1000-5000条预测记录
- 预计时间：10-30分钟
- 建议时间：非交易时间（晚上或周末）

**训练后操作**：
1. 微调后的模型会替换原基础模型
2. 需要手动激活新模型
3. 可以对比新旧模型的训练指标，选择更好的模型激活

## 三、训练策略建议

### 3.1 新系统部署

**第一阶段（第1周）**：
1. ✅ 执行历史数据训练，建立基础模型
2. ✅ 激活基础模型，开始使用ML预测
3. ✅ 系统正常运行，积累预测数据

**第二阶段（第2-3周）**：
1. ✅ 检查预测数据是否达到1000条
2. ✅ 如果数据充足，执行第一次微调训练
3. ✅ 激活微调后的模型

**第三阶段（第4周及以后）**：
1. ✅ 每周执行1-2次微调训练
2. ✅ 每3-6个月重训基础模型

---

### 3.2 稳定运行阶段

**日常维护**：
- **微调训练**：每周日晚上执行（建议设置定时任务）
- **基础模型重训**：每3-6个月执行一次（如每季度末）

**特殊情况**：
- **市场重大变化**：如政策调整、市场风格切换，及时重训基础模型
- **模型表现下降**：如果ML模型预测准确率明显下降，考虑重训
- **数据异常**：如果预测数据质量下降，暂停微调训练

---

### 3.3 定时任务设置建议

**微调训练定时任务**：
- **任务类型**：自定义任务（调用微调训练API）
- **执行频率**：每周
- **执行时间**：周日晚上20:00
- **执行条件**：检查数据是否达到最少样本数

**基础模型重训定时任务**：
- **任务类型**：自定义任务（调用基础模型训练API）
- **执行频率**：每月（或每季度）
- **执行时间**：月末/季末晚上22:00
- **执行条件**：检查距离上次训练是否超过3个月

## 四、模型评估与优化

### 4.1 模型评估指标

**训练指标**：
- **训练准确率**：模型在训练集上的准确率
- **验证准确率**：模型在验证集上的准确率（更重要）
- **特征重要性**：哪些特征对预测最重要

**预测指标**（在"性能评估"中查看）：
- **方向准确率**：预测方向的准确率
- **总收益率**：使用模型预测进行交易的收益
- **胜率**：盈利交易的比例
- **最大回撤**：最大亏损幅度

### 4.2 模型选择建议

**选择标准**：
1. ✅ **验证准确率高**：优先选择验证准确率高的模型
2. ✅ **特征重要性合理**：重要特征应该符合业务逻辑
3. ✅ **预测表现好**：在实际预测中表现好的模型
4. ⚠️ **避免过拟合**：训练准确率远高于验证准确率的模型可能过拟合

**模型对比**：
- 可以训练多个模型（如XGBoost和LightGBM）
- 对比它们的验证准确率和预测表现
- 选择表现最好的模型激活

## 五、常见问题

### Q1: 历史数据训练是否只需要训练一次？

**A**: 不是。建议每3-6个月重训一次，因为：
- 市场环境会变化
- 新的数据可能包含新的模式
- 定期重训可以保持模型的时效性

### Q2: 预测数据训练是否每天执行？

**A**: 不建议。建议每周1-2次，因为：
- 预测数据变化相对缓慢
- 频繁训练效果有限，且可能过拟合
- 每周训练可以平衡效果和效率

### Q3: ML模型预测失败怎么办？

**A**: 系统会自动降级为传统多因子预测：
- ML模型预测失败不影响主流程
- 预测结果仍然有效，只是不使用ML模型
- 检查模型文件是否存在，模型是否激活

### Q4: 如何判断模型是否需要重训？

**A**: 可以通过以下指标判断：
- 预测准确率明显下降（在"性能评估"中查看）
- 模型预测结果与实际情况偏差较大
- 市场环境发生重大变化

### Q5: 训练时间过长怎么办？

**A**: 
- 历史数据训练：可以缩小训练集时间范围（如只训练最近3年数据）
- 预测数据训练：可以减少样本数要求（但至少1000条）
- 选择更快的模型类型（LightGBM通常比XGBoost快）

## 六、最佳实践

1. **首次部署**：先训练基础模型，运行1-2周后再开始微调

5. **模型对比**：可以训练多个模型，选择表现最好的激活
6. **错误处理**：训练失败时检查日志，排查问题
