# 定时任务日期处理修复说明

**创建日期**：2026-01-26  
**问题描述**：定时任务的增量更新日期处理逻辑错误

---

## 一、问题描述

### 1.1 问题现象

如果用户在创建定时任务时选择了当天日期（例如：2026-01-26），那么：
- ✅ **第一次执行**（2026-01-26）：会获取2026-01-26的数据（正确）
- ❌ **第二次执行**（2026-01-27）：还是会获取2026-01-26的数据（错误！应该获取2026-01-27的数据）

### 1.2 问题原因

在 `scheduled_task_manager.py` 中，定时任务执行时会使用创建任务时指定的 `target_date` 参数，而不是每次执行时都使用当天日期。

**问题代码**：
```python
# 增量更新：使用页面上设置的目标日期（如果指定），否则使用当天日期
target_date = task_config.get('target_date', None)
if target_date:
    # 使用页面上指定的目标日期
    start_date = target_date
    end_date = target_date
    self.logger.info(f"增量更新模式：获取页面上指定的目标日期 {target_date} 的数据")
```

---

## 二、修复方案

### 2.1 修复逻辑

**修复原则**：
- ✅ **定时任务**：增量更新应该总是使用**当天日期**，忽略创建任务时指定的 `target_date`
- ✅ **手动执行**：可以使用指定的 `target_date`（如果需要获取历史数据）

**修复后的代码**：
```python
# 增量更新：定时任务应该总是获取当天数据，而不是使用创建任务时指定的固定日期
# 原因：如果用户在1月26日创建定时任务并选择1月26日，那么1月27日执行时应该获取1月27日的数据，而不是1月26日
# target_date 参数只在手动执行时使用，定时任务执行时应该忽略它
today = datetime.now().strftime('%Y-%m-%d')
start_date = today
end_date = today
self.logger.info(f"增量更新模式（定时任务）：获取当天 {today} 的数据")
```
