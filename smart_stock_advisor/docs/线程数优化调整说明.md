**创建日期**：2026-01-22  
**调整原因**：避免API限流，降低线程数

---

## 一、调整内容

### 1.1 调整前

**默认线程数**：100

**自动调整规则**：
- 超大量股票（>5000）：最多150线程，计算公式 `symbol_count // 40`
- 大量股票（>3000）：最多120线程，计算公式 `symbol_count // 50`
- 中等数量（>1000）：最多80线程，计算公式 `symbol_count // 60`

**示例**：5400只股票 → 135线程

- 大量股票（>3000）：最多60线程，计算公式 `symbol_count // 80`
- 中等数量（>1000）：最多50线程，计算公式 `symbol_count // 100`

**示例**：5400只股票 → 67线程（降低约50%）

## 三、调整原因

### 3.1 避免API限流

- **问题**：线程数过多可能导致API限流
- **风险**：频繁调用API可能被服务器拒绝连接
- **解决**：降低线程数，减少并发请求

### 3.2 网络稳定性

- **问题**：大量并发连接可能导致网络不稳定
- **风险**：连接中断、超时等问题增加
- **解决**：适度降低线程数，提高稳定性

### 3.3 性能平衡

- **考虑**：线程数降低会影响采集速度
- **权衡**：在速度和稳定性之间取得平衡
- **结果**：适度降低线程数，仍保持较高效率

---

## 四、影响分析

### 4.1 性能影响

**采集时间估算**：
- 调整前：5400只股票 × 1秒/股票 ÷ 135线程 ≈ 40秒（理想情况）
- 调整后：5400只股票 × 1秒/股票 ÷ 67线程 ≈ 80秒（理想情况）
- **增加时间**：约40秒（约1倍）

**实际影响**：
- 由于网络延迟和API响应时间，实际增加时间可能更少
- 降低限流风险，减少重试次数，可能反而更快

### 4.2 稳定性提升

- ✅ 降低API限流风险
- ✅ 减少网络连接错误
- ✅ 提高任务成功率
- ✅ 减少重试次数

## 六、使用建议
