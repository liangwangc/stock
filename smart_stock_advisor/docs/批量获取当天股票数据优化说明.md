## 一、功能说明

**新增方法**：`_incremental_update_today_batch()`

**功能**：使用 `ak.stock_zh_a_spot_em()` 批量接口一次性获取所有股票的实时行情数据

**优势**：
- ✅ **速度极快**：1-2秒获取所有股票数据（vs 逐只获取需要1-2小时）

- ✅ **避免限流**：大幅减少API调用频率，避免被限流
- ✅ **数据完整**：一次性获取所有股票，避免遗漏

## 三、实现细节

### 3.1 批量获取流程

1. **查询已存在数据**：
   - 批量查询数据库中今天已存在的数据
   - 跳过已存在的股票，只处理需要更新的股票

2. **批量获取实时行情**：
   - 调用 `ak.stock_zh_a_spot_em()` 一次性获取所有股票
   - 构建股票代码到数据的映射字典

3. **数据转换**：
   - 将API返回的数据转换为标准格式
   - 映射字段名称（如：'今开' → 'open_price'）
   - 计算衍生字段（涨跌额、涨跌幅、涨跌停价等）

4. **数据验证**：
   - 检查是否有必要的价格数据（`close_price` 或 `open_price`）
   - 清理NaN值，确保数据质量

5. **批量保存**：
   - 使用 `save_stock_daily_data_batch()` 批量保存到数据库
   - 批次大小可配置（默认500）

| 涨跌额 | change_amount | 涨跌额 |
| 换手率 | turnover_rate | 换手率 |
| 振幅 | amplitude | 振幅 |
| 市盈率-动态 | pe_ratio | 市盈率 |
| 市净率 | pb_ratio | 市净率 |

| 流通市值 | float_market_cap | 流通市值 |

### 3.3 数据计算

**自动计算的字段**：

1. **涨跌额和涨跌幅**（如果没有）：
   ```python
   change_amount = close_price - pre_close
   change_pct = (change_amount / pre_close) * 100
   ```

2. **成交额**（如果没有）：
   ```python
   amount = close_price * volume * 100  # 1手=100股
   ```

3. **涨跌停价**：
   ```python
   if symbol.startswith('688') or symbol.startswith('300'):
       limit_pct = 0.20  # 科创板/创业板20%
   else:
       limit_pct = 0.10  # 普通股票10%
   limit_up = pre_close * (1 + limit_pct)
   limit_down = pre_close * (1 - limit_pct)
   ```

4. **价格区间和振幅**：
   ```python
   price_range = high_price - low_price
   amplitude = ((high_price - low_price) / pre_close) * 100
   ```

## 五、适用场景

### 5.1 推荐使用批量API的场景

- ✅ **每日收盘后更新**：更新所有股票的当天数据
- ✅ **实时数据同步**：批量同步最新数据
- ✅ **数据补全**：补全缺失的当天数据

### 5.2 不适用批量API的场景

- ❌ **历史数据收集**：批量API只返回当天数据，不包含历史数据
- ❌ **多日期更新**：如果 `additional_dates` 不为空，会回退到逐只获取
- ❌ **特定股票更新**：如果只需要更新少量股票，逐只获取可能更快

## 六、注意事项

### 6.1 API限制

- **数据范围**：`stock_zh_a_spot_em()` 只返回当天数据，不包含历史数据
- **数据时效**：实时行情数据，适合收盘后更新
- **数据完整性**：某些股票可能没有数据（停牌、退市等）

### 6.2 数据质量

- ✅ **自动验证**：检查是否有必要的价格数据
- ✅ **NaN值清理**：自动清理NaN值，确保数据质量
- ✅ **数据转换**：自动转换数据类型和格式

### 6.3 错误处理

- ✅ **API失败处理**：如果批量API失败，会返回错误信息
- ✅ **数据缺失处理**：如果某个股票没有数据，会跳过并记录失败
- ✅ **数据库错误处理**：批量保存失败会记录失败数量
