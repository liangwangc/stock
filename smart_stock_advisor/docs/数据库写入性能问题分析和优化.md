# 数据库写入性能问题分析和优化

## 问题描述

用户报告：
- **6分钟才存了50条数据**
- **API获取只用了60秒**
- 这意味着数据库写入非常慢（平均每条7.2秒）

## 性能瓶颈分析

### 1. 多线程锁竞争（最严重）

**问题**：
- 50个线程同时写入数据库
- 每个线程都有自己的数据库连接（threading.local）
- 但MySQL的`ON DUPLICATE KEY UPDATE`需要检查唯一索引`(symbol, trade_date, period_type)`
- 50个线程同时检查同一张表的唯一索引，导致严重的锁竞争

**影响**：
- 每个线程都在等待其他线程释放锁
- 写入操作串行化，失去了多线程的优势
- 50个线程 × 7.2秒/条 = 360秒（6分钟）

### 2. JSON序列化重复（已优化）

**问题**：
- 即使数据已经预序列化（`*_json`字段），代码仍然会检查并可能重新序列化
- 使用`or`操作符，如果`*_json`字段存在但为空字符串，仍会重新序列化

**优化**：
- 已修改为：如果`*_json`字段存在且不为None，直接使用；否则才序列化

### 3. 批次大小

**当前**：
- 用户已改为500
- 但50个线程同时写入，每个线程可能只处理少量数据

**建议**：
- 减少线程数：从50减少到10-20
- 增大批次大小：从500增加到1000-2000

### 4. 数据库索引过多

**问题**：
- `ON DUPLICATE KEY UPDATE`需要检查唯一索引
- 如果表中有多个索引，写入时会更新所有索引
- 索引更新是串行的，导致写入慢

**建议**：
- 检查表的索引数量
- 只保留查询必需的索引
- 考虑临时禁用非唯一索引（如果数据不重复）

## 优化方案

### ✅ 优化1：减少线程数

**原理**：
- 数据库写入是I/O密集型操作
- 多线程写入会导致锁竞争，反而降低性能
- 建议使用10-20个线程，平衡并发和锁竞争

**实施**：
```bash
# 优化前
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 200 --delay 0.8 --threads 50

# 优化后
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 1000 --delay 0.5 --threads 15
```

### ✅ 优化2：增大批次大小

**原理**：
- 批次越大，单次SQL执行的数据越多
- 减少SQL执行次数，减少锁竞争
- 但批次太大可能导致内存问题

**实施**：
- 将批次大小从500增加到1000-2000
- 平衡性能和内存使用

### ✅ 优化3：优化JSON序列化（已完成）

**原理**：
- 避免重复序列化已预序列化的JSON字段
- 减少CPU和内存使用

**实施**：
- 已修改`stock_history_storage.py`中的JSON序列化逻辑
- 如果`*_json`字段存在且不为None，直接使用

### ✅ 优化4：使用连接池（可选）

**原理**：
- 连接池可以复用数据库连接
- 减少连接创建和销毁的开销

**实施**：
- 如果使用连接池，可以减少连接创建时间
- 但当前使用threading.local，每个线程一个连接，已经比较高效

## 性能预期

### 优化前
- 50个线程，批次500
- 50条数据：6分钟（360秒）
- 平均每条：7.2秒

### 优化后（预期）
- 15个线程，批次1000
- 50条数据：预计30-60秒
- 平均每条：0.6-1.2秒
- **性能提升：6-12倍**

## 建议

1. **立即优化**：
   - 减少线程数：从50减少到15
   - 增大批次大小：从500增加到1000
   - 已优化JSON序列化逻辑

2. **进一步优化**（如果仍有问题）：
   - 检查数据库索引数量
   - 考虑使用`LOAD DATA INFILE`（如果数据不重复）
   - 考虑临时禁用非唯一索引

3. **监控**：
   - 监控数据库锁等待时间
   - 监控线程等待时间
   - 监控批次写入时间

## 总结

主要问题是**多线程锁竞争**。50个线程同时写入导致严重的锁竞争，写入操作串行化，失去了多线程的优势。

优化方案：
1. ✅ 减少线程数：50 → 15
2. ✅ 增大批次大小：500 → 1000
3. ✅ 优化JSON序列化逻辑
4. ⚠️ 检查数据库索引（如果仍有问题）

预期性能提升：**6-12倍**
