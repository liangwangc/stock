## 一、新闻定时获取流程分析

### 1.1 流程概览

**入口**：`utils/scheduled_task_manager.py` → `_execute_news_crawl(task)`

**完整流程**：
```
1. 解析任务配置（task_type, symbol, interval_minutes等）
   ↓
2. 初始化新闻源和存储模块
   ↓
3. 根据任务类型执行不同逻辑：
   - 'all': 增量抓取全部新闻（使用crawl_all_news）
   - 'market': 抓取市场新闻
   - 'stock': 抓取股票新闻
   ↓
4. 内容分析和过滤（NewsContentAnalyzer）
   - 分析发布时间有效性
   - 分析新闻真实性
   - 计算可靠性得分
   - 过滤不可靠新闻
   ↓
5. 保存可靠的新闻到数据库
```

---

### 1.2 当前实现优点

✅ **增量抓取**：`task_type='all'` 时使用增量抓取，避免重复  
✅ **内容分析**：使用 `NewsContentAnalyzer` 分析新闻可靠性  
✅ **时间过滤**：在增量抓取时按时间范围过滤  
✅ **去重机制**：基于标题和SimHash去重  
✅ **内存优化**：执行完成后清理大对象

---

### 1.3 潜在问题

⚠️ **非增量任务的时间过滤**：
- `task_type='market'` 或 `'stock'` 时，没有时间范围过滤
- 可能获取到很旧的新闻

⚠️ **发布时间提取逻辑**：
- 从内容中提取的时间可能是"事件发生时间"而不是"发布时间"
- 可能影响股票预测的准确性

## 二、发布时间处理分析

### 2.1 当前发布时间提取逻辑

**代码位置**：`utils/news_storage.py:148-193`

**提取顺序**：
```
1. 优先从字段获取：
   - news.get('time')
   - news.get('publish_time')
   - news.get('pub_time')
   ↓
2. 如果字段中没有，从内容提取：
   - 使用 NewsTimeExtractor.extract_from_content()
   - 从HTML meta标签提取
   - 从常见位置提取（开头/结尾）
   - 使用正则表达式匹配时间模式
   - 解析相对时间
   ↓
3. 如果提取失败，使用当前时间
```

---

### 2.2 问题分析

#### 问题1：内容中的时间可能是"事件时间"而非"发布时间"

**示例**：
```
新闻标题：某公司2025年12月发布新产品
新闻内容：该公司于2025年12月15日发布了新产品...

提取的时间：2025-12-15（事件发生时间）
实际发布时间：2026-01-22（新闻发布时间）
```

**影响**：
- 如果使用事件时间作为发布时间，会导致：
  - 新闻被误判为"旧新闻"
  - 时间过滤时被过滤掉
  - 股票预测时使用错误的时间

---

#### 问题2：时间提取没有区分"发布时间"和"事件时间"

**当前逻辑**：
- `NewsTimeExtractor` 提取所有时间，不区分类型
- 没有判断提取的时间是"发布时间"还是"事件时间"

**建议**：
- 优先使用meta标签中的时间（通常是发布时间）
- 从内容中提取的时间需要判断是否是"事件时间"
- 如果判断是"事件时间"，应该标记或忽略

---

### 2.3 时间验证逻辑

**代码位置**：`utils/news_time_extractor.py:158-162`

## 三、新闻内容中的时间分析

### 3.1 时间类型识别

**发布时间（Publish Time）**：
- 新闻发布的时间
- 通常在HTML meta标签中：`<meta property="article:published_time">`
- 通常在新闻开头或结尾显示："发布时间：2026-01-22 15:30:00"

**事件时间（Event Time）**：
- 新闻中描述的事件发生的时间
- 通常在新闻内容中间："该公司于2025年12月15日发布了..."
- 关键词：`于`、`在`、`时间`、`日期`、`发布`、`公告`、`披露`

---

### 3.2 识别规则建议

**发布时间特征**：
- 位置：HTML meta标签、新闻开头/结尾
- 格式：通常包含时分秒
- 关键词：`发布时间`、`发布时间`、`发布时间`、`发布时间`

**事件时间特征**：
- 位置：新闻内容中间
- 格式：可能只有日期，没有时分秒
- 关键词：`于`、`在`、`时间`、`日期`、`发布`、`公告`、`披露`
- 上下文：通常描述过去的事件

## 四、优化建议

### 4.1 优化发布时间提取逻辑

#### 建议1：区分"发布时间"和"事件时间"

**修改位置**：`utils/news_time_extractor.py`

**新增方法**：
```python
@staticmethod
def extract_publish_time(content: str, title: str = '') -> Optional[datetime]:
    """
    专门提取发布时间（不是事件时间）
    
    策略：
    1. 优先从HTML meta标签提取（最准确）
    2. 从新闻开头/结尾提取（通常是发布时间）
    3. 如果提取的时间在内容中间，且上下文包含"于"、"在"等关键词，可能是事件时间，忽略
    """
    # 1. 从meta标签提取（最优先）
    publish_time = NewsTimeExtractor._extract_from_meta_tags(text)
    if publish_time:
        return publish_time
    
    # 2. 从常见位置提取（开头/结尾）
    publish_time = NewsTimeExtractor._extract_from_common_positions(text)
    if publish_time:
        # 验证是否是发布时间（不是事件时间）
        if NewsTimeExtractor._is_publish_time(publish_time, text):
            return publish_time
    
    # 3. 使用正则表达式匹配（但要验证不是事件时间）
    publish_time = NewsTimeExtractor._extract_with_patterns(text)
    if publish_time:
        if NewsTimeExtractor._is_publish_time(publish_time, text):
            return publish_time
    
    return None

@staticmethod
def _is_publish_time(time_str: str, text: str) -> bool:
    """
    判断提取的时间是否是发布时间（而不是事件时间）
    
    规则：
    1. 如果时间在meta标签中，肯定是发布时间
    2. 如果时间在开头/结尾500字符内，且附近有"发布时间"关键词，是发布时间
    3. 如果时间在内容中间，且附近有"于"、"在"等关键词，可能是事件时间
    """
    # 查找时间在文本中的位置
    time_pos = text.find(time_str)
    if time_pos == -1:
        return False
    
    # 提取时间前后100字符的上下文
    context_start = max(0, time_pos - 100)
    context_end = min(len(text), time_pos + len(time_str) + 100)
    context = text[context_start:context_end]
    
    # 发布时间关键词
    publish_keywords = ['发布时间', '发布时间', '发布时间', '发布时间', '发布时间']
    # 事件时间关键词
    event_keywords = ['于', '在', '时间', '日期', '发布', '公告', '披露']
    
    # 如果上下文包含发布时间关键词，是发布时间
    if any(keyword in context for keyword in publish_keywords):
        return True
    
    # 如果上下文包含事件时间关键词，且时间在内容中间（不在开头/结尾），可能是事件时间
    if any(keyword in context for keyword in event_keywords):
        # 判断时间是否在开头或结尾（开头500字符或结尾500字符）
        is_at_start = time_pos < 500
        is_at_end = time_pos > len(text) - 500
        if not (is_at_start or is_at_end):
            return False  # 在中间，可能是事件时间
    
    # 默认认为是发布时间
    return True
```

def analyze_publish_time(self, news: Dict) -> Dict:
    """
    分析新闻发布时间
    
    Returns:
        - publish_time: 解析后的发布时间
        - event_time: 事件发生时间（如果存在）

        - time_quality: 时间质量
    """
    result = {
        'publish_time': None,
        'event_time': None,
        'time_type': 'unknown',
        'is_valid': False,
        'time_quality': 'invalid',
        'reason': '',
        'time_delta': None
    }
    
    # ... 现有逻辑 ...
    
    # 新增：尝试提取事件时间
    content = news.get('content', '')
    title = news.get('title', '')
    if content or title:
        try:
            from utils.news_time_extractor import NewsTimeExtractor
            # 提取事件时间（从内容中间）
