# 新闻抓取功能优化说明

## 优化概述

本次优化主要针对全量新闻抓取功能（`crawl_all_news()` 方法），提升了抓取成功率、错误处理能力和统计信息的完整性。

## 主要优化内容

### 1. 重试机制 ✅

**问题**：网络波动或新闻源暂时不可用时，单次抓取可能失败。

**优化**：
- 添加了重试机制，默认重试3次
- 每次失败后等待时间递增（2秒、4秒、6秒），避免频繁请求
- 记录每次重试的结果，便于问题诊断

**代码位置**：`smart_stock_advisor/utils/news_crawler.py` 第157-220行

### 2. 时间解析优化 ✅

**问题**：各个新闻源的时间格式不一致，解析可能失败，导致新闻被错误过滤。

**优化**：
- 提取为独立方法 `_parse_news_time()`，统一处理时间解析
- 支持多种时间格式：
  - `YYYY-MM-DD HH:MM:SS`
  - `YYYY-MM-DD`
  - `YYYY/MM/DD HH:MM:SS`
  - 相对时间（"今天"、"1小时前"等）
- 改进错误处理，解析失败时保留新闻（避免误过滤）

**代码位置**：`smart_stock_advisor/utils/news_crawler.py` 第72-120行

### 3. 时间范围计算优化 ✅

**问题**：时间范围计算逻辑分散，难以维护。

**优化**：
- 提取为独立方法 `_calculate_time_range()`
- 统一处理首次获取和增量获取的逻辑
- 改进凌晨00:00的处理，避免遗漏数据

**代码位置**：`smart_stock_advisor/utils/news_crawler.py` 第122-155行

### 4. 统计信息增强 ✅

**问题**：缺少详细的统计信息，难以了解抓取情况。

**优化**：
- 添加各新闻源的贡献统计（`source_stats`）
- 记录时间范围信息（`time_range`）
- 统计关联到的股票数量（`mapped_stocks_count`）
- 记录时间过滤的详细信息（`time_out_of_range`、`time_parse_failed`）

### 5. 日志优化 ✅

**问题**：日志信息不够详细，难以诊断问题。

**优化**：
- 添加进度信息（`[1/100]`、`[2/100]` 等）
- 记录各新闻源的贡献情况
- 提供问题诊断信息（为什么抓不到新闻）
- 优化日志格式，更易读

## 使用方法

### 基本使用

```python
from utils.news_crawler import NewsCrawler

crawler = NewsCrawler()

# 全量抓取（首次）
result = crawler.crawl_all_news(limit=200)

# 增量抓取（基于上次时间）
last_time = datetime(2024, 1, 13, 9, 0, 0)
result = crawler.crawl_all_news(limit=200, last_fetch_time=last_time)

# 查看结果
print(f"成功: {result['success']}")
print(f"重复: {result['duplicate']}")
print(f"失败: {result['failed']}")
print(f"各新闻源贡献: {result['source_stats']}")
```

### 参数说明

- `limit`: 限制数量（每个新闻源），默认200
- `last_fetch_time`: 上次获取时间（用于增量获取），默认None（首次获取）
- `interval_minutes`: 任务间隔（分钟），默认60.0
- `max_retries`: 最大重试次数，默认3次

## 性能改进

1. **减少重复计算**：时间解析提取为独立方法，避免重复代码
2. **优化过滤逻辑**：改进时间范围过滤，减少不必要的处理
3. **批量处理**：保持批量保存的优势

## 兼容性

## 故障排除

### 问题1：仍然抓不到新闻

**可能原因**：
1. 时间范围内确实没有新闻
2. 所有新闻源都失败（网络问题）
3. 时间解析全部失败（罕见）

**解决方法**：
1. 查看日志中的"未获取到新闻"警告，了解具体原因
2. 检查网络连接
3. 增加重试次数：`crawl_all_news(limit=200, max_retries=5)`
4. 扩大时间范围：检查 `last_fetch_time` 是否正确

### 问题2：时间过滤后新闻数量很少

**可能原因**：
1. 时间范围设置太小
2. 新闻时间解析不准确

**解决方法**：
1. 查看日志中的 `time_out_of_range` 和 `time_parse_failed` 统计
2. 检查时间范围设置
3. 如果 `time_parse_failed` 较大，可能需要改进时间解析逻辑

### 问题3：某些新闻源没有贡献

**可能原因**：
1. 新闻源网站结构变化
2. 网络问题
3. 新闻源暂时不可用

**解决方法**：
1. 查看日志中的 `source_stats`，了解各新闻源的贡献
2. 检查网络连接
3. 查看是否有错误日志
