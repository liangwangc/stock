# 避免唯一索引锁竞争优化方案

## 问题分析

**当前问题**：
- 使用 `INSERT ... ON DUPLICATE KEY UPDATE` 时，MySQL需要检查唯一索引 `(symbol, trade_date, period_type)`
- 50个线程同时写入，导致严重的唯一索引锁竞争
- 写入操作被串行化，失去多线程优势

**性能影响**：
- 50条数据用了6分钟（360秒）
- 平均每条7.2秒（正常应该在0.1-0.5秒）

## 优化方案

### 方案1：分离INSERT和UPDATE（推荐）

**原理**：
1. 先批量查询哪些数据已存在
2. 分离为"需要插入"和"需要更新"两部分
3. INSERT部分使用纯`INSERT`（不需要检查唯一索引）
4. UPDATE部分使用`UPDATE`或`ON DUPLICATE KEY UPDATE`（锁竞争减少）

**优点**：
- INSERT部分不需要检查唯一索引，避免锁竞争
- UPDATE部分数据量少，锁竞争减少
- 性能提升显著

**缺点**：
- 需要额外的查询步骤
- 代码复杂度增加

### 方案2：使用INSERT IGNORE + 单独UPDATE

**原理**：
1. 先使用`INSERT IGNORE`插入所有数据（忽略重复）
2. 然后使用`UPDATE`更新已存在的数据

**优点**：
- 实现简单
- INSERT IGNORE不需要检查唯一索引（如果数据不存在）

**缺点**：
- 需要两次数据库操作
- UPDATE仍然需要检查唯一索引

### 方案3：减少线程数（最简单）

**原理**：
- 减少线程数，减少锁竞争
- 从50减少到15-20

**优点**：
- 实现简单，无需修改代码
- 立即生效

**缺点**：
- 性能提升有限
- 仍然存在锁竞争

## 推荐实施方案

**组合方案**：
1. ✅ **立即实施**：减少线程数（50 → 15）
2. ✅ **立即实施**：增大批次大小（500 → 1000）
3. ⚠️ **可选实施**：分离INSERT和UPDATE（如果仍有性能问题）

## 实施建议

### 立即优化（无需代码修改）

```bash
# 优化前
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 200 --delay 0.8 --threads 50

# 优化后
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 1000 --delay 0.5 --threads 15
```

### 代码优化（如果仍有问题）

实施分离INSERT和UPDATE方案，预计性能提升：
- INSERT部分：避免唯一索引检查，性能提升 **10-50倍**
- UPDATE部分：数据量减少，锁竞争减少，性能提升 **2-5倍**

## 总结

**主要问题**：多线程唯一索引锁竞争

**最佳解决方案**：
1. 减少线程数：50 → 15
2. 增大批次大小：500 → 1000
3. （可选）分离INSERT和UPDATE

**预期性能提升**：6-12倍
