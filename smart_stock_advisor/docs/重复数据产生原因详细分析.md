# 重复数据产生原因详细分析

**创建日期**：2026-01-22  
**问题**：为什么会出现重复数据？

---

## 一、根本原因分析

### 1.1 核心问题：纯INSERT没有唯一约束保护

**代码位置**：`utils/stock_history_storage.py:587-601`

**问题代码**：
```python
if use_separate_insert_update:
    # 1. 先处理INSERT部分（纯INSERT，没有ON DUPLICATE KEY UPDATE）
    insert_sql = """
        INSERT INTO stock_history_data 
        (symbol, name, trade_date, period_type, ...)
        VALUES (%s, %s, %s, %s, ...)
        # ⚠️ 注意：这里没有 ON DUPLICATE KEY UPDATE！
    """
    
    # 执行批量INSERT
    affected_rows = self.db.execute_many(insert_sql, insert_params_list)
```

**问题**：
- ⚠️ **纯INSERT没有唯一约束保护**
- ⚠️ 如果数据库唯一索引不正确，INSERT会成功插入重复数据
- ⚠️ 即使唯一索引正确，如果period_type为NULL，唯一索引可能失效

---

### 1.2 原因1：数据库唯一索引不正确

**问题**：
- 如果唯一索引是 `uk_symbol_date` (`symbol`, `trade_date`)，缺少 `period_type`
- 纯INSERT时，数据库不会检查 `period_type`，可能插入重复数据

**示例**：
```sql
-- 唯一索引：uk_symbol_date (symbol, trade_date)
-- 可以插入：
INSERT INTO stock_history_data (symbol, trade_date, period_type) VALUES ('000001', '2026-01-22', 'daily');
INSERT INTO stock_history_data (symbol, trade_date, period_type) VALUES ('000001', '2026-01-22', 'daily');  -- ❌ 应该失败，但可能成功
```

---

### 1.3 原因2：period_type 字段为 NULL

**问题**：
- 如果 `period_type` 为 NULL，唯一索引可能失效
- MySQL的唯一索引对NULL值的处理：多个NULL值不违反唯一约束

**示例**：
```sql
-- 唯一索引：uk_symbol_date_period (symbol, trade_date, period_type)
-- 如果period_type为NULL：
INSERT INTO stock_history_data (symbol, trade_date, period_type) VALUES ('000001', '2026-01-22', NULL);
INSERT INTO stock_history_data (symbol, trade_date, period_type) VALUES ('000001', '2026-01-22', NULL);  -- ❌ 可能成功
```

---

### 1.4 原因3：增量更新前检查不完整

**代码位置**：`utils/stock_history_collector.py:1461-1476`

**问题代码**：
```python
# 查询已存在的数据
sql = """
    SELECT DISTINCT symbol, trade_date
    FROM stock_history_data 
    WHERE symbol IN (...) 
      AND trade_date IN (...)
      AND period_type = 'daily'  # ✅ 查询时过滤了period_type
"""

# 存储到existing_data_map
existing_data_map[symbol][date] = True  # ⚠️ 只用了symbol和date作为key
```

**问题**：
- ✅ 查询时过滤了 `period_type = 'daily'`
- ⚠️ 但存储时只用了 `(symbol, date)` 作为key
- ⚠️ 如果同一个股票同一天有不同period_type的数据，可能被误判为已存在
- ⚠️ 如果查询失败（第1491-1494行），会回退到处理所有股票的所有日期

---

### 1.5 原因4：并发插入问题

**问题场景**：
1. 线程A检查：数据不存在 → 准备INSERT
2. 线程B检查：数据不存在 → 准备INSERT（此时线程A还未插入）
3. 线程A执行INSERT：成功
4. 线程B执行INSERT：如果唯一索引不正确，也可能成功 → ❌ 重复数据

**代码位置**：`utils/stock_history_collector.py:1526-1536`

```python
def process_task(task: tuple) -> Dict:
    symbol, date = task
    # 采集数据
    data = self.collect_stock_daily_data(symbol, date, fast_mode=True)
    if data:
        # 添加到批量保存列表（多线程并发）
        with data_lock:
            collected_data.append((symbol, date, data))
```

**问题**：
- ⚠️ 多线程并发采集数据
- ⚠️ 增量更新前的检查是在单线程中进行的（第1439-1495行）
- ⚠️ 但数据采集是多线程并发的（第1551-1577行）
- ⚠️ 如果两个线程采集到相同的数据，可能同时添加到 `collected_data`

---

### 1.6 原因5：批量INSERT错误处理不完善

**代码位置**：`utils/stock_history_storage.py:686-700`

**问题代码**：
```python
try:
    affected_rows = self.db.execute_many(insert_sql, insert_params_list)
    if affected_rows > 0:
        success_count += len(current_insert)  # ⚠️ 假设所有记录都成功
except Exception as e_insert:
    # INSERT失败，回退到ON DUPLICATE KEY UPDATE
    current_update.extend(current_insert)
```

**问题**：
- ⚠️ `executemany` 如果部分成功、部分失败，可能不会抛出异常
- ⚠️ 如果唯一索引不正确，`executemany` 可能成功插入部分重复数据
- ⚠️ `affected_rows` 可能不准确（某些数据库驱动可能返回不准确的值）

## 二、具体场景分析

### 2.1 场景1：数据库唯一索引不正确

**步骤**：
1. 数据库唯一索引：`uk_symbol_date` (`symbol`, `trade_date`)
2. 增量更新前检查：查询 `period_type = 'daily'`，但存储时只用了 `(symbol, date)`
3. 批量保存：执行纯INSERT（没有ON DUPLICATE KEY UPDATE）
4. 结果：如果唯一索引不正确，可能插入重复数据

**示例**：
```
股票：000001，日期：2026-01-22，period_type：daily
- 第1次插入：成功（假设）
- 第2次插入：如果唯一索引是 uk_symbol_date，且period_type为NULL或不同，可能成功 → 重复数据
```

---

### 2.2 场景2：period_type 为 NULL

**步骤**：
1. 数据库唯一索引：`uk_symbol_date_period` (`symbol`, `trade_date`, `period_type`)
2. 数据采集：`period_type` 为 NULL（未设置）
3. 批量保存：执行纯INSERT
4. 结果：多个NULL值不违反唯一约束，可能插入重复数据

**示例**：
```
股票：000001，日期：2026-01-22，period_type：NULL
- 第1次插入：成功
- 第2次插入：如果period_type为NULL，MySQL允许多个NULL值 → 重复数据
```

---

### 2.3 场景3：并发插入

**步骤**：
1. 线程A：检查数据不存在 → 采集数据 → 添加到collected_data
2. 线程B：检查数据不存在（此时线程A还未保存） → 采集数据 → 添加到collected_data
3. 批量保存：两个线程的数据都在collected_data中
4. 结果：如果唯一索引不正确，可能插入重复数据

**示例**：
```
时间线：
T1: 线程A检查：000001 2026-01-22 不存在
T2: 线程B检查：000001 2026-01-22 不存在（线程A还未保存）
T3: 线程A采集数据，添加到collected_data
T4: 线程B采集数据，添加到collected_data
T5: 批量保存：两条相同的数据 → 如果唯一索引不正确，可能都成功 → 重复数据
```

## 三、为什么会出现重复数据？

### 3.1 主要原因排序

1. **数据库唯一索引不正确**（最可能）
   - 如果唯一索引是 `uk_symbol_date` (`symbol`, `trade_date`)，缺少 `period_type`
   - 纯INSERT时，数据库不会检查 `period_type`，可能插入重复数据

2. **period_type 字段为 NULL**
   - 如果 `period_type` 为 NULL，唯一索引可能失效
   - MySQL的唯一索引对NULL值的处理：多个NULL值不违反唯一约束

3. **纯INSERT没有唯一约束保护**
   - 当 `use_separate_insert_update=True` 时，执行纯INSERT（没有ON DUPLICATE KEY UPDATE）
   - 如果唯一索引不正确，INSERT会成功插入重复数据

4. **并发插入问题**
   - 多线程并发采集数据
   - 如果两个线程同时检查到数据不存在，可能同时插入

5. **增量更新前检查失败**
   - 如果批量查询失败，会回退到处理所有股票的所有日期
   - 包括已经存在的数据

## 五、解决方案

### 5.1 立即修复：更新数据库唯一索引

**执行SQL脚本**：
```bash
mysql -u root -p stock_data < database/add_period_type_field.sql
```

**关键步骤**：
1. 确保period_type字段存在
2. 设置所有NULL值为'daily'
3. 删除旧唯一索引 `uk_symbol_date`
4. 创建新唯一索引 `uk_symbol_date_period` (`symbol`, `trade_date`, `period_type`)

---

### 5.2 改进代码：纯INSERT改为INSERT ... ON DUPLICATE KEY UPDATE

**修改代码**：`utils/stock_history_storage.py:587-601`

**当前代码**：
```python
insert_sql = """
    INSERT INTO stock_history_data (...)
    VALUES (...)
    # ⚠️ 没有 ON DUPLICATE KEY UPDATE
"""
```

**改进后**：
```python
insert_sql = """
    INSERT INTO stock_history_data (...)
    VALUES (...)
    ON DUPLICATE KEY UPDATE
    name = VALUES(name), period_type = VALUES(period_type), ...
"""
```

**优势**：
- ✅ 即使唯一索引不正确，也能避免重复数据
- ✅ 双重保护：唯一索引 + ON DUPLICATE KEY UPDATE

---

### 5.3 改进代码：增量更新前检查考虑period_type

**修改代码**：`utils/stock_history_collector.py:1461-1476`

**改进后**：
```python
sql = f"""
```
