# 股票数据源综合测试脚本使用说明

## 概述

`test_all_stock_data_sources.py` 是一个综合测试脚本，用于测试所有可用的股票数据API接口，评估它们的稳定性、数据完整性和性能。

## 测试的数据源

1. **akshare.stock_zh_a_hist** - 当前主要使用的接口
2. **Tushare.pro.daily** - 备用数据源（需要token）
3. **Baostock** - 免费A股数据源（需要安装：`pip install baostock`）
4. **akshare其他接口** - stock_zh_a_hist_sina、stock_zh_a_hist_163等

## 测试内容

### 1. 稳定性测试
- 多次调用同一接口，统计成功率
- 记录错误类型和频率
- 评估接口的可靠性

### 2. 数据完整性测试
- 检查返回的字段是否完整
- 对比数据库表需要的字段
- 计算字段覆盖度

### 3. 性能测试
- 测量响应时间
- 统计平均响应速度
- 评估接口效率

### 4. 数据质量评估
- 基于字段覆盖度计算数据质量得分
- 识别缺失的字段
- 评估数据可用性

## 使用方法

### 基本用法（综合测试）

```bash
# 使用默认股票列表和日期范围
python scripts/test_all_stock_data_sources.py

# 指定股票代码
python scripts/test_all_stock_data_sources.py --symbols 000001 600519 000002

# 指定日期范围
python scripts/test_all_stock_data_sources.py --start-date 2026-01-16 --end-date 2026-01-23

# 保存测试报告到文件
python scripts/test_all_stock_data_sources.py --output reports/data_source_test_report.json
```

### 稳定性测试模式

```bash
# 运行稳定性测试（对同一只股票多次调用，统计成功率）
python scripts/test_all_stock_data_sources.py --stability-test --iterations 20

# 指定测试股票和日期范围
python scripts/test_all_stock_data_sources.py --stability-test --symbols 000001 --start-date 2026-01-16 --iterations 20
```

### 压力测试模式（检测API限制）

```bash
# 全量压力测试（测试所有股票，检测API限制）
python scripts/test_all_stock_data_sources.py --pressure-test

# 限制测试股票数量（测试前500只股票）
python scripts/test_all_stock_data_sources.py --pressure-test --max-stocks 500

# 自定义批次大小和延迟
python scripts/test_all_stock_data_sources.py --pressure-test --batch-size 50 --batch-delay 3.0

# 指定日期范围
python scripts/test_all_stock_data_sources.py --pressure-test --start-date 2026-01-16 --end-date 2026-01-23

# 保存压力测试报告
python scripts/test_all_stock_data_sources.py --pressure-test --max-stocks 200 --output reports/pressure_test_report.json
```

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--symbols` | 测试股票代码列表 | `['000001', '600519', '000002', '600036', '000858']` |
| `--start-date` | 开始日期（YYYY-MM-DD） | `2026-01-16` |
| `--end-date` | 结束日期（YYYY-MM-DD） | 今天 |
| `--stability-test` | 运行稳定性测试模式 | False |
| `--pressure-test` | 运行压力测试模式（全量获取股票信息，检测API限制） | False |
| `--iterations` | 稳定性测试迭代次数 | 10 |
| `--max-stocks` | 压力测试最大股票数量（默认：全量，约5000+只） | None |
| `--batch-size` | 压力测试批次大小（默认100只股票/批次） | 100 |
| `--batch-delay` | 压力测试批次间延迟（秒，默认2.0秒） | 2.0 |
| `--output` | 输出报告文件路径（JSON格式） | None |

## 数据库字段要求

脚本会根据数据库表 `stock_history_data` 的字段要求进行评估：

### 核心字段（必须）
- **基本信息**: symbol, name, trade_date
- **价格数据**: open_price, close_price, high_price, low_price, pre_close
- **涨跌数据**: change_amount, change_pct
- **成交数据**: volume, amount

### 技术指标字段
- ma5, ma10, ma20, ma60
- rsi, macd, macd_signal, macd_hist

### 估值字段
- pe_ratio, pb_ratio

### 其他字段
- turnover_rate, volume_ratio, amplitude
- limit_up, limit_down

## 评估标准

### 综合得分计算

```
综合得分 = 成功率 × 50% + 速度得分 × 20% + 数据质量 × 30%

其中：
- 成功率 = 成功次数 / 总测试次数
- 速度得分 = max(0, 1 - 平均响应时间 / 5秒)
- 数据质量 = 可用字段数 / 必需字段总数
```

### 推荐标准

- **综合得分 > 0.8**: 优秀，推荐使用
- **综合得分 0.6-0.8**: 良好，可以作为备用
- **综合得分 < 0.6**: 不推荐，稳定性或数据质量不足

## 注意事项

1. **Tushare需要token**
   - 需要在 `config.py` 中配置 `TUSHARE_TOKEN`
   - 部分接口可能需要积分或VIP权限

2. **Baostock需要安装**
   ```bash
   pip install baostock
   ```

3. **API限制**
   - 测试时会自动添加延迟，避免触发API限制
   - 稳定性测试模式会多次调用，注意API限制

4. **网络环境**
   - 确保网络连接正常
   - 某些接口可能需要特定的网络环境

## 压力测试说明

压力测试模式用于检测各个API接口的速率限制情况，帮助确定：
- 哪些接口会触发速率限制
- 触发限制的阈值（处理多少只股票后开始限制）
- 接口的稳定性（能否处理全量股票）

### 压力测试输出

压力测试会输出以下信息：

1. **实时进度**
   - 批次进度（第X批/共Y批）
   - 成功/失败统计
   - 成功率

2. **限制检测**
   - 速率限制触发次数
   - 首次触发限制的股票数量（阈值）
   - 限制错误详情

3. **测试结果总结**
   - 成功率统计
   - 速率限制情况
   - 建议的批次大小和延迟时间
   - 预计全量获取时间

### 压力测试建议

1. **首次测试**: 使用 `--max-stocks 500` 限制股票数量，快速了解限制情况
2. **调整参数**: 根据首次测试结果，调整 `--batch-size` 和 `--batch-delay`
3. **全量测试**: 确认参数后，运行全量测试（不指定 `--max-stocks`）
4. **保存报告**: 使用 `--output` 保存详细报告，便于后续分析

## 建议

根据测试结果，建议：

1. **主要数据源**: 选择综合得分最高的接口
2. **备用数据源**: 选择得分第二的接口作为备用
3. **避免使用**: 成功率低或频繁出现速率限制的接口
4. **压力测试**: 定期运行压力测试，了解接口限制变化
5. **批次优化**: 根据压力测试结果，优化批量获取的批次大小和延迟时间

## 故障排查

如果测试失败：

1. **检查依赖库**
   ```bash
   pip install akshare tushare baostock pandas
   ```

2. **检查配置**
   - Tushare token是否正确配置
   - 网络连接是否正常

3. **查看详细日志**
   - 脚本会输出详细的错误信息
   - 检查错误类型和频率
