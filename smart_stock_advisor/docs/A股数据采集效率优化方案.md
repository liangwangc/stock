# A股数据采集效率优化方案（不减少指标）

## 一、当前性能瓶颈分析

### 1.1 API调用瓶颈

#### 瓶颈1：`get_stock_info()` 重复调用 `ak.stock_zh_a_spot_em()`

**问题**：
- 每个股票调用 `get_stock_info()` 时，内部会调用 `ak.stock_zh_a_spot_em()` 获取所有股票的实时行情
- 如果收集1000只股票，会重复调用1000次 `ak.stock_zh_a_spot_em()`
- 每次调用耗时约100-500ms

**代码位置**：`data_source/stock_data_source.py` 第317行、第378行

**影响**：
- 1000只股票 × 300ms = 300秒（5分钟）纯API调用时间

#### 瓶颈2：股票名称获取逻辑

**问题**：
- 如果 `get_stock_info()` 获取名称失败，会调用 `get_all_stock_list()`
- 虽然已缓存，但如果缓存未命中，会获取整个股票列表（5000+只股票）
- 然后遍历查找目标股票

**代码位置**：`utils/stock_history_collector.py` 第554-563行

### 1.2 计算性能瓶颈

#### 瓶颈3：X2指标计算使用循环

**问题**：
- X2指标计算使用了 `for idx in kline_data.index:` 循环
- 对于2500天的数据，需要循环2500次
- 可以向量化优化

**代码位置**：`utils/stock_history_collector.py` 第740-745行

**影响**：
- 单股票：约10-50ms
- 1000只股票：约10-50秒

#### 瓶颈4：技术指标重复计算

**问题**：
- 技术指标在每批100条时计算一次
- 如果一只股票有2500天数据，会计算25次
- 实际上只需要计算一次

**代码位置**：`utils/stock_history_collector.py` 第699-789行

**影响**：
- 重复计算浪费CPU时间

### 1.3 数据构建瓶颈

#### 瓶颈5：逐个构建数据字典

**问题**：
- 在循环中逐个构建数据字典
- 每个日期都要查找前一日数据计算涨跌幅
- 可以批量优化

**代码位置**：`utils/stock_history_collector.py` 第591-683行

## 二、优化方案

### 2.1 优化1：缓存 `ak.stock_zh_a_spot_em()` 结果

**方案**：
- 在 `StockDataSource` 中添加全局缓存
- 缓存 `ak.stock_zh_a_spot_em()` 的结果
- 缓存有效期：5-10分钟

**预期效果**：
- API调用从1000次减少到1次
- **性能提升：100-1000倍**

**实施难度**：低

### 2.2 优化2：优化股票名称获取

**方案**：
- 优先从缓存的股票列表中获取名称（已实现）
- 如果缓存未命中，先构建字典索引，避免重复遍历
- 将股票列表转换为字典：`{symbol: name}`

**预期效果**：
- 名称查找从O(n)优化到O(1)
- **性能提升：10-100倍**

**实施难度**：低

### 2.3 优化3：向量化X2指标计算

**方案**：
- 使用numpy的向量化操作替代循环
- 使用 `np.where()` 处理条件判断

**代码优化**：
```python
# 优化前（循环）
x2_series = pd.Series(index=kline_data.index, dtype=float)
for idx in kline_data.index:
    if range_width.loc[idx] > 0:
        x2_series.loc[idx] = (closes.loc[idx] - llv_low.loc[idx]) / range_width.loc[idx] * 100
    else:
        x2_series.loc[idx] = 50.0

# 优化后（向量化）
import numpy as np
x2_series = pd.Series(
    np.where(range_width > 0,
             (closes - llv_low) / range_width * 100,
             50.0),
    index=kline_data.index
)
```

**预期效果**：
- X2计算时间从10-50ms降低到1-5ms
- **性能提升：10-50倍**

**实施难度**：低

### 2.4 优化4：一次性计算所有技术指标

**方案**：
- 在处理所有日期之前，一次性计算所有日期的技术指标
- 然后直接赋值，避免重复计算

**预期效果**：
- 技术指标计算从25次减少到1次
- **性能提升：10-25倍**

**实施难度**：中

### 2.5 优化5：批量构建数据字典

**方案**：
- 使用pandas的向量化操作批量计算涨跌幅
- 批量构建数据字典

**预期效果**：
- 数据构建时间减少50-80%
- **性能提升：2-5倍**

**实施难度**：中
