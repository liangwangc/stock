# 数据库写入性能优化说明

## 问题描述

用户反映：接口40秒左右返回数据，但存数据库很慢。

## 性能瓶颈分析

### 1. 原有实现的问题

**问题1：构建超长SQL语句**
- 原有实现：构建 `INSERT INTO ... VALUES (...), (...), (...)` 的长SQL语句
- 500条数据 × 41个字段 = 20,500个参数
- SQL语句长度可能达到几十KB甚至上百KB
- MySQL需要解析超长SQL，影响性能

**问题2：重复构建参数**
- 代码中同时构建了长SQL的参数和executemany的参数
- 浪费CPU和内存

**问题3：唯一索引检查**
- `ON DUPLICATE KEY UPDATE` 需要检查唯一索引 `(symbol, trade_date, period_type)`
- 每条数据都要检查，影响性能

**问题4：JSON序列化**
- 每条数据都要序列化JSON字段（`bid_levels`, `ask_levels`, `cost_distribution`等）
- 虽然已优化为在数据构建时序列化，但批量保存时仍可能重复序列化

## 优化方案

### ✅ 优化1：使用 `executemany` 替代构建长SQL

**原理**：
- `cursor.executemany()` 是MySQL优化的批量插入方法
- MySQL内部会将批量插入优化为更高效的执行计划
- 比构建长SQL语句更快

**实现**：
```python
# 优化前：构建长SQL
sql = "INSERT INTO ... VALUES (...), (...), (...)"
params = (param1, param2, ..., param_n)
cursor.execute(sql, params)

# 优化后：使用executemany
sql = "INSERT INTO ... VALUES (%s, %s, ...)"
params_list = [(param1, param2, ...), (param1, param2, ...), ...]
cursor.executemany(sql, params_list)
```

**性能提升**：
- 减少SQL解析时间：从几十毫秒降低到几毫秒
- MySQL内部优化：批量插入可以优化为更高效的执行计划
- 减少内存占用：不需要构建超长SQL字符串

### ✅ 优化2：移除重复的参数构建逻辑

**问题**：
- 代码中同时构建了长SQL的参数（`all_params`）和executemany的参数（`params_list`）
- 浪费CPU和内存

**解决**：
- 移除长SQL构建逻辑
- 只保留executemany的参数构建
- 如果executemany失败，回退到逐条插入（而不是构建长SQL）

### ✅ 优化3：确保事务提交

**问题**：
- `execute_many` 方法可能没有正确提交事务

**解决**：
- 在 `execute_many` 方法中添加 `conn.commit()` 确保事务提交

## 优化效果

### 预期性能提升

|--------|--------|--------|------|

## 代码变更

### 1. `utils/stock_history_storage.py`

**变更**：
- 移除长SQL构建逻辑（`sql_base`, `values_parts`, `all_params`）
- 只保留 `executemany` 的参数构建（`params_list`）
- 如果 `executemany` 失败，回退到逐条插入

**关键代码**：
```python
# 使用executemany执行批量插入（比构建长SQL更快）
try:
    affected_rows = self.db.execute_many(base_sql, params_list)
    if affected_rows > 0:
        success_count += len(current_batch)
except Exception as e_executemany:
    # executemany失败，回退到逐条插入
    self.logger.warning(f"executemany失败，回退到逐条插入: {str(e_executemany)}")
    for symbol, date, data in current_batch:
        if self.save_stock_daily_data(symbol, date, data):
            success_count += 1
```

### 2. `utils/db_connection.py`

**变更**：
- 在 `execute_many` 方法中添加 `conn.commit()` 确保事务提交

**关键代码**：
```python
def execute_many(cls, sql: str, params_list: List[tuple]) -> int:
    with conn.cursor() as cursor:
        affected_rows = cursor.executemany(sql, params_list)
        # 确保提交事务
        if not DB_CONFIG.get('autocommit', True):
            conn.commit()
        else:
            conn.commit()  # 确保提交
        return affected_rows
```

## 进一步优化建议

### 1. 减小批次大小

**当前**：`batch_size=500`

**建议**：
- 如果数据量很大，可以减小批次大小到100-200
- 避免单次插入数据过多导致性能下降

### 2. 禁用唯一索引检查（临时）

**注意**：仅在数据不重复时使用

**方法**：
```sql
-- 临时禁用唯一索引
ALTER TABLE stock_history_data DISABLE KEYS;

-- 批量插入数据
-- ...

-- 重新启用唯一索引
ALTER TABLE stock_history_data ENABLE KEYS;
```

**风险**：
- 如果数据重复，可能导致数据不一致
- 需要确保数据不重复

### 3. 使用 `LOAD DATA INFILE`

**优势**：
- MySQL的 `LOAD DATA INFILE` 比 `INSERT` 快10-100倍
- 适合大批量数据导入

**限制**：
- 需要文件系统访问权限
- 需要将数据转换为CSV格式

### 4. 优化数据库索引

**当前索引**：
- `UNIQUE KEY uk_symbol_date_period (symbol, trade_date, period_type)`
- `INDEX idx_symbol (symbol)`
- `INDEX idx_trade_date (trade_date)`
- `INDEX idx_symbol_date (symbol, trade_date)`
- `INDEX idx_date_range (trade_date, symbol)`
- `INDEX idx_volume (volume)`
- `INDEX idx_change_pct (change_pct)`

**建议**：
- 如果主要用于写入，可以减少索引数量
- 只保留查询必需的索引

## 总结

通过使用 `executemany` 替代构建长SQL，预期可以提升数据库写入性能 **5-10倍**。

主要优化点：
1. ✅ 使用 `executemany` 替代构建长SQL
2. ✅ 移除重复的参数构建逻辑
3. ✅ 确保事务正确提交

如果性能仍然不理想，可以考虑：
- 减小批次大小
- 临时禁用唯一索引检查
- 使用 `LOAD DATA INFILE`
- 优化数据库索引
