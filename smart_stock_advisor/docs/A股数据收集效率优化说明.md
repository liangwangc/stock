# A股数据收集效率优化说明

## 优化概述

针对批量收集A股历史数据效率低的问题，进行了全面优化，预计可提升 **10-50倍** 的收集速度。

## 主要优化内容

### 1. 批量获取历史数据 ✅

**问题**：之前逐日采集，每个日期都要调用多个API，效率极低。

**优化**：
- 一次性获取整个日期范围的历史K线数据（如10年数据一次获取）
- 从逐日模式改为批量模式
- 大幅减少API调用次数

**性能提升**：
- 之前：10年数据（约2500个交易日）× 每个日期多次API调用 = 数千次API调用
- 现在：10年数据 = **1次API调用**（获取K线数据）

**代码位置**：`smart_stock_advisor/utils/stock_history_collector.py` 第349-628行

### 2. 减少不必要的API调用 ✅

**问题**：历史数据采集时调用了实时行情、买卖盘、成本分布等实时数据API，这些对历史数据不必要。

**优化**：
- 批量模式下只获取基本K线数据（开盘、收盘、最高、最低、成交量）
- 历史数据不需要实时行情、买卖盘、成本分布等
- 减少API调用次数和延迟

**性能提升**：
- 之前：每个日期调用5-8个API
- 现在：整个日期范围只调用1个API

### 3. 批量保存数据 ✅

**问题**：之前逐条保存数据，数据库操作频繁。

**优化**：
- 批量处理数据，每批100条
- 减少数据库写入次数
- 提升数据库写入效率

**性能提升**：
- 之前：2500条数据 = 2500次数据库写入
- 现在：2500条数据 = 25次数据库写入（每批100条）

### 4. 优化延迟策略 ✅

**问题**：多线程模式下延迟过大，影响并发效率。

**优化**：
- 多线程模式下减少延迟（从0.5-1.5秒减少到0.2-0.5秒）
- 批量模式下不需要每个日期都延迟
- 智能延迟策略

**性能提升**：
- 之前：每个日期延迟0.5秒，2500个日期 = 1250秒（约21分钟）纯延迟时间
- 现在：批量模式几乎无延迟，只有少量API调用延迟

### 5. 减少进度保存频率 ✅

**问题**：每只股票后都保存进度，文件IO频繁。

**优化**：
- 多线程模式下每10只股票保存一次进度
- 减少文件IO操作
- 提升整体效率

**性能提升**：
- 之前：50只股票 = 50次文件写入
- 现在：50只股票 = 5次文件写入

### 6. 优化日志输出 ✅

**问题**：日志输出过于频繁，影响性能。

**优化**：
- 减少日志输出频率（每50条或每批输出一次）
- 批量模式下只输出关键进度信息
- 提升日志处理效率

## 使用方法

### 基本使用（自动使用批量模式）

```cmd
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 50 --delay 1.0 --threads 30
```

### 参数说明

- `--market cn`: 市场类型（A股）
- `--years 10`: 收集10年数据
- `--batch-size 50`: 每批处理50只股票
- `--delay 1.0`: 每只股票之间的延迟（秒，批量模式下影响较小）
- `--threads 30`: 使用30个线程并行处理

### 推荐配置

**高效配置**（网络条件良好）：
```cmd
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 50 --delay 0.5 --threads 30
```

**平衡配置**（一般情况）：
```cmd
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 50 --delay 1.0 --threads 20
```

**保守配置**（API限制较严格）：
```cmd
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 30 --delay 1.5 --threads 10
```

## 技术实现

### 批量模式工作流程

1. **获取缺失日期列表**
   - 查询数据库，找出缺失的日期
   - 计算需要采集的日期范围

2. **批量获取K线数据**
   - 一次性调用 `get_stock_data()` 获取整个日期范围的数据
   - 扩展日期范围（前后各加5天）确保数据完整

3. **批量处理数据**
   - 从批量数据中提取缺失日期的数据
   - 构建数据字典（只包含基本K线数据）
   - 计算涨跌幅、振幅等衍生指标

4. **批量保存数据**
   - 每批100条数据批量保存
   - 减少数据库写入次数

5. **自动回退机制**
   - 如果批量模式失败，自动回退到逐日模式
   - 确保数据采集的可靠性

## 注意事项

1. **API限制**：
   - 批量模式大幅减少了API调用次数，但仍需注意API频率限制
   - 如果遇到API限制，会自动回退到逐日模式

2. **数据完整性**：
   - 批量模式只获取基本K线数据
   - 如果需要实时行情、买卖盘等数据，需要在增量更新时获取

3. **内存使用**：
   - 批量模式会一次性加载多年数据到内存
   - 确保系统有足够内存（10年数据约几MB到几十MB）

4. **数据库性能**：
   - 批量保存减少了数据库写入次数
   - 确保数据库连接池配置合理

## 故障排除

### 问题1：批量模式失败，回退到逐日模式

**可能原因**：
1. API返回数据不完整
2. 日期范围过大，API超时
3. 网络问题

**解决方法**：
1. 检查日志，查看具体错误信息
2. 减少日期范围（减少years参数）
3. 检查网络连接

### 问题2：数据不完整

**可能原因**：
1. 批量数据中缺少某些日期
2. 日期范围扩展不够

**解决方法**：
1. 检查日志中的"在批量数据中未找到"警告
2. 增加日期范围扩展（修改代码中的前后天数）

### 问题3：性能提升不明显

**可能原因**：
1. 网络延迟较大
2. API响应慢
3. 数据库写入慢

**解决方法**：
1. 检查网络连接
2. 优化数据库配置（添加索引、优化连接池）
3. 减少线程数，避免资源竞争
