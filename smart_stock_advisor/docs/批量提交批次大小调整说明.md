# 批量提交批次大小调整说明

**创建日期**：2026-01-22  
**调整内容**：将数据库批量提交批次大小从150条调整为300条

---

## 一、调整内容

### 1.1 调整前

**实际保存批次大小**：150条/次

**代码位置**：`utils/stock_history_storage.py:511`

```python
actual_save_batch_size = min(batch_size, 150)  # 实际保存批次大小限制为150，减少锁竞争
```

**提交次数**：
- 5400条数据 ÷ 150 = 36次提交

---

### 1.2 调整后

**实际保存批次大小**：300条/次

**代码位置**：`utils/stock_history_storage.py:511`

```python
actual_save_batch_size = min(batch_size, 300)  # 实际保存批次大小限制为300，提升批量保存效率
```

**提交次数**：
- 5400条数据 ÷ 300 = 18次提交（减少50%）

---

## 二、影响分析

### 2.1 性能提升

**提交次数减少**：
- 调整前：36次提交
- 调整后：18次提交
- **减少**：50%的提交次数

**优势**：
- ✅ 减少数据库连接次数
- ✅ 减少SQL执行次数
- ✅ 提升批量保存效率
- ✅ 减少网络往返时间

### 2.2 锁持有时间

**考虑因素**：
- 批次大小增加，单次锁持有时间可能略微增加
- 但提交次数减少，总体锁持有时间可能减少
- 对于5400条数据，总体影响较小

**建议**：
- 如果遇到锁竞争问题，可以适当降低批次大小
- 监控数据库性能指标，根据实际情况调整

## 三、配置说明

### 3.1 完整流程

```
1. 数据收集阶段
   - 所有数据收集到内存（collected_data列表）
   - 无批次限制

2. 批量保存阶段
   - 传入参数：batch_size = 500-600（根据股票数量自动调整）
   - 实际提交：actual_save_batch_size = min(batch_size, 300) = 300条/次
   - 分批提交到数据库
```

### 3.2 批次大小层级

| 层级 | 批次大小 | 说明 |

## 五、注意事项

### 5.1 数据库性能

**监控指标**：
- 数据库连接数
- SQL执行时间
- 锁等待时间
- 事务提交时间

**如果遇到问题**：
- 可以适当降低批次大小（例如200或250）
- 或者增加数据库连接池大小

### 5.2 内存使用

**影响**：
- 批次大小增加，单次SQL参数可能更大
- 但总体内存占用不变（数据已收集到内存）

**建议**：
- 当前300条批次大小，内存占用可控
- 如果数据字段很多，可以适当降低

## 六、后续优化建议

### 6.1 动态调整

可以考虑根据数据量动态调整批次大小：
- 小批量数据（<1000条）：使用较小批次（200）
- 中批量数据（1000-5000条）：使用中等批次（300）
- 大批量数据（>5000条）：使用较大批次（400-500）

建议添加性能监控：
- 记录每次批量保存的耗时
