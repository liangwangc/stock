# 成本分布批量计算说明

## 概述

由于历史数据收集时跳过了成本分布计算（以提升性能），现在提供了批量计算成本分布的脚本，用于后续补充历史数据的成本分布。

## 成本分布计算原理

### 计算方法

成本分布基于历史K线数据计算：
- **数据来源**：最近N天（默认60天）的日线收盘价和成交量
- **计算方式**：将价格区间划分为若干档位（默认20档），统计每个档位的成交量占比
- **结果**：每个档位的价格、成交量、成交量占比

### 计算逻辑

对于每个交易日期，成本分布应该基于**该日期之前**的历史数据计算。

例如：
- 计算 `2024-01-15` 的成本分布，使用 `2024-01-15` 之前60天的数据
- 计算 `2024-01-16` 的成本分布，使用 `2024-01-16` 之前60天的数据

这样可以确保成本分布反映的是该日期之前的持仓成本情况。

## 脚本使用方法

### 基本用法

#### 1. 计算单只股票的成本分布

```bash
python scripts/batch_calculate_cost_distribution.py --symbol 000001
```

#### 2. 批量计算所有股票的成本分布

```bash
python scripts/batch_calculate_cost_distribution.py --all
```

#### 3. 批量计算指定股票列表的成本分布

```bash
python scripts/batch_calculate_cost_distribution.py --symbols 000001,600519,000002
```

#### 4. 计算指定日期范围的数据

```bash
python scripts/batch_calculate_cost_distribution.py --all --start-date 2024-01-01 --end-date 2024-12-31
```

#### 5. 多线程模式（推荐，提升速度）

```bash
python scripts/batch_calculate_cost_distribution.py --all --threads 5
```

#### 6. 仅扫描缺失数据，不进行计算

```bash
python scripts/batch_calculate_cost_distribution.py --all --scan-only
```

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--symbol` | 单只股票代码 | - |
| `--symbols` | 股票代码列表（逗号分隔） | - |
| `--all` | 处理所有股票 | False |
| `--start-date` | 开始日期（格式：YYYY-MM-DD） | 所有数据 |
| `--end-date` | 结束日期（格式：YYYY-MM-DD） | 所有数据 |
| `--days` | 计算成本分布使用的历史天数 | 60 |
| `--bins` | 价格分档数量 | 20 |
| `--threads` | 最大线程数 | 1 |
| `--scan-only` | 仅扫描缺失数据，不进行计算 | False |

### 使用示例

#### 示例1：计算单只股票最近1年的成本分布

```bash
python scripts/batch_calculate_cost_distribution.py \
    --symbol 000001 \
    --start-date 2024-01-01 \
    --end-date 2024-12-31 \
    --days 60 \
    --bins 20
```

#### 示例2：批量计算所有股票的成本分布（多线程）

```bash
python scripts/batch_calculate_cost_distribution.py \
    --all \
    --threads 5 \
    --days 60 \
    --bins 20
```

#### 示例3：先扫描缺失数据，再批量计算

```bash
# 1. 扫描缺失数据
python scripts/batch_calculate_cost_distribution.py --all --scan-only

# 2. 批量计算（根据扫描结果决定是否计算）
python scripts/batch_calculate_cost_distribution.py --all --threads 5
```

## 脚本功能

### 1. 扫描缺失成本分布

脚本会自动扫描数据库中缺失成本分布的数据：
- 检查 `cost_distribution` 和 `cost_distribution_history` 字段
- 如果两个字段都为空，则标记为缺失
- 返回缺失成本分布的股票和日期列表

### 2. 批量计算成本分布

对于每个缺失的日期：
- 获取该日期之前N天的历史K线数据
- 计算成本分布（价格分档、成交量占比）
- 更新数据库中的成本分布字段

### 3. 多线程支持

支持多线程模式，可以并行处理多只股票：
- 每个线程处理一只股票
- 线程间互不干扰
- 大幅提升批量计算速度

### 4. 进度跟踪

脚本会实时输出进度信息：
- 每只股票的处理进度
- 成功/失败统计
- 总体进度和耗时

## 性能说明

### 计算时间估算

- **单只股票**：约 0.5-2 秒/天（取决于历史数据量）
- **1000只股票，每只2500天**：约 12-50 小时（单线程）
- **1000只股票，每只2500天，5线程**：约 2.5-10 小时

### 优化建议

1. **使用多线程**：推荐使用 `--threads 5` 或更多
2. **分批处理**：如果数据量很大，可以分批处理（使用 `--start-date` 和 `--end-date`）
3. **调整参数**：根据实际情况调整 `--days` 和 `--bins` 参数

## 注意事项

### 1. 数据要求

- 需要确保数据库中有足够的历史K线数据
- 每个日期至少需要10天的历史数据才能计算成本分布
- 如果历史数据不足，该日期的成本分布将无法计算

### 2. 计算逻辑

- 成本分布是基于历史数据计算的，每个日期的成本分布反映的是该日期之前的持仓成本
- 计算时会自动排除该日期当天的数据，只使用之前的数据

### 3. 数据库更新

- 脚本会更新 `cost_distribution`、`cost_distribution_history` 字段
- `cost_distribution_intraday` 字段保持为空（历史数据无法获取当日分时数据）

### 4. 错误处理

- 如果某个日期的成本分布计算失败，脚本会继续处理其他日期
- 失败的原因会记录在日志中
- 可以重新运行脚本，已计算的数据不会重复计算

## 常见问题

### Q1: 为什么有些日期的成本分布无法计算？

**A**: 可能的原因：
- 历史数据不足（需要至少10天的历史数据）
- 价格数据异常（价格为0或负数）
- 成交量数据异常（全部为0）

### Q2: 可以重复运行脚本吗？

**A**: 可以。脚本会自动跳过已有成本分布的数据，只计算缺失的数据。

### Q3: 如何提高计算速度？

**A**: 
- 使用多线程模式（`--threads 5`）
- 减少历史天数（`--days 30`）
- 减少价格分档数（`--bins 10`）

### Q4: 成本分布数据会占用多少存储空间？

**A**: 
- 每个日期的成本分布约占用 1-2 KB
- 1000只股票，每只2500天，约占用 2.5-5 GB
