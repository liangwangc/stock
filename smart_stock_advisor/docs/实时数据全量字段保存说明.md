# 实时数据全量字段保存说明

## 一、概述

在预测明日股票时，实时获取的股票数据需要保存全量字段（58个字段），而历史数据收集时只需要保存41个字段（已注释掉16个历史数据不可用的字段）。

## 二、实现方案

### 2.1 自动判断机制

`save_stock_daily_data` 方法现在支持自动判断是否使用全量字段：

- **参数**：`use_full_fields`（可选）
  - `None`（默认）：自动判断
  - `True`：强制使用全量字段（58个字段）
  - `False`：强制使用41个字段（历史数据模式）

### 2.2 自动判断逻辑

当 `use_full_fields=None` 时，系统会自动判断：

1. **日期判断**：数据日期是否是今天或最近3天
2. **字段判断**：数据字典中是否包含以下实时数据字段：
   - `turnover_rate`（换手率）
   - `outer_volume`（外盘）
   - `inner_volume`（内盘）
   - `bid_levels`（五档买盘）
   - `ask_levels`（五档卖盘）
   - `main_net_inflow`（主力净流入）
   - `total_market_cap`（总市值）
   - `float_market_cap`（流通市值）

**判断条件**：如果数据日期是今天或最近3天，**且**数据中包含上述任一实时数据字段，则使用全量字段（58个字段）。

### 2.3 字段对比

#### 历史数据模式（41个字段）

已注释掉的16个字段：
1. `turnover_rate`（换手率）
2. `outer_volume`（外盘）
3. `inner_volume`（内盘）
4. `bid_ask_ratio`（委比）
5. `bid_levels`（五档买盘）
6. `ask_levels`（五档卖盘）
7. `bid_total_volume`（买盘总量）
8. `ask_total_volume`（卖盘总量）
9. `cost_distribution_intraday`（当日成本分布）
10. `total_market_cap`（总市值）
11. `float_market_cap`（流通市值）
12. `main_net_inflow`（主力净流入）
13. `super_large_inflow`（超大单流入）
14. `large_inflow`（大单流入）
15. `medium_inflow`（中单流入）
16. `small_inflow`（小单流入）

#### 实时数据模式（58个字段）

包含上述16个字段，共58个字段。

## 三、使用方法

### 3.1 单条保存（自动判断）

```python
from utils.stock_history_storage import StockHistoryStorage

storage = StockHistoryStorage()

# 自动判断：如果是实时数据，使用全量字段；如果是历史数据，使用41个字段
storage.save_stock_daily_data(symbol, date, data)
```

### 3.2 单条保存（强制全量字段）

```python
# 强制使用全量字段（用于实时数据）
storage.save_stock_daily_data(symbol, date, data, use_full_fields=True)
```

### 3.3 单条保存（强制历史数据模式）

```python
# 强制使用41个字段（用于历史数据）
storage.save_stock_daily_data(symbol, date, data, use_full_fields=False)
```

### 3.4 批量保存

批量保存方法 `save_stock_daily_data_batch` 也支持自动判断：

- 如果批次中的第一条数据是实时数据，整批都使用全量字段SQL模板
- 如果批次中的第一条数据是历史数据，整批都使用41个字段SQL模板
- **注意**：批量保存主要用于历史数据收集，实时数据通常使用单条保存

## 五、注意事项

1. **自动判断**：默认情况下，系统会自动判断数据是否是实时数据，无需手动指定 `use_full_fields` 参数。

2. **批量保存限制**：批量保存方法主要用于历史数据收集，如果批次中混合了历史数据和实时数据，可能会导致SQL语句字段数量不一致。建议：
   - 历史数据收集：使用批量保存方法
   - 实时数据保存：使用单条保存方法（自动判断）

3. **字段完整性**：实时数据保存时，确保数据字典中包含所有需要的实时数据字段，否则可能无法正确判断为实时数据。

4. **性能考虑**：全量字段保存会增加数据库写入量，但对于实时数据（通常每天只保存一次），性能影响可以忽略。
