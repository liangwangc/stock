# 新闻系统融合总结

**创建日期**：2026-01-23  
**项目**：news-analysis-system-main + smart_stock_advisor 新闻系统融合

---

## 一、融合方案概述

### 1.1 目标

将 `news-analysis-system-main` 的财联社新闻获取和LLM深度分析功能融合到 `smart_stock_advisor` 中，实现：
- ✅ 多源新闻覆盖（13个新闻源 + 财联社）
- ✅ LLM深度分析（分类、关键词、情感、总结）
- ✅ 统一数据管理（所有新闻存储在 `news_articles` 表）
- ✅ 保持独立性（news-analysis-system-main 可独立运行）

### 1.2 架构设计

```
news-analysis-system-main (独立项目)
    ↓ 定时获取财联社新闻
    ↓ LLM分析（Qwen3-4B）
    ↓ 存储到 cls_news_db
    ↓
    [数据同步接口]
    ↓
smart_stock_advisor (主系统)
    ↓ 同步到 news_articles 表
    ↓ 使用融合后的新闻数据
    ↓ 股票预测
```

## 三、新增数据库字段

### 3.1 LLM分析字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `llm_category` | VARCHAR(50) | LLM分类（6大类） |
| `llm_subcategory` | VARCHAR(100) | LLM子分类 |
| `llm_keywords` | TEXT | LLM提取的关键词 |
| `llm_sentiment_score` | DECIMAL(8,4) | LLM情感得分（-1到1） |
| `llm_summary` | TEXT | LLM生成的总结 |
| `llm_impact_markets` | VARCHAR(200) | 影响的市场/品种 |
| `llm_is_market_relevant` | TINYINT(1) | 是否与金融市场相关 |
| `llm_analyzed_at` | DATETIME | LLM分析时间 |
| `content_hash` | VARCHAR(64) | 内容哈希（用于去重和同步） |

### 3.2 新增索引

- `idx_content_hash`：内容哈希索引（用于快速查找和去重）
- `idx_llm_category`：LLM分类索引（用于分类查询）
- `idx_llm_analyzed_at`：分析时间索引（用于时间范围查询）

## 四、数据流程

### 4.1 新闻获取流程

```
1. news-analysis-system-main 定时获取财联社新闻
   ↓
2. 保存到 cls_news_db.news（带 content_hash）
   ↓
3. sync_cls_news.py 检测新新闻（通过 content_hash）
   ↓
4. 同步到 smart_stock_advisor.news_articles
   - 映射字段：title, content, publish_time, source='财联社'
   - 生成 content_hash（如果缺失）
```

### 4.2 LLM分析流程

```
1. news-analysis-system-main LLM分析新闻
   ↓
2. 保存到 cls_news_db.analysis_results
   ↓
3. sync_cls_news.py 同步分析结果
   ↓
4. 通过 content_hash 关联到 news_articles
   ↓
5. 更新 LLM 分析字段
```

### 4.3 使用融合数据

```
1. 股票预测时查询 news_articles
   ↓
2. 优先使用 LLM 分析结果（如果存在）
   ↓
3. 降级使用关键词分析（如果LLM结果缺失）
   ↓
4. 结合两种分析结果增强预测准确性
```

## 六、使用示例

### 6.1 手动同步

```python
from utils.news_sync_from_cls import NewsSyncFromCls

# 创建同步器
sync = NewsSyncFromCls()

# 同步新闻（最近1小时）
from datetime import datetime, timedelta
since = datetime.now() - timedelta(hours=1)
result = sync.sync_news(since=since, limit=100)

# 同步分析结果
analysis_result = sync.sync_analysis_results(limit=100)

# 同步所有数据
all_result = sync.sync_all(news_limit=500, analysis_limit=500)
```

### 6.2 定时同步

```bash
# 运行定时同步脚本
python scripts/sync_cls_news.py

# 或后台运行（Linux/Mac）
nohup python scripts/sync_cls_news.py > sync_cls_news.log 2>&1 &
```

### 6.3 查询融合后的数据

```sql
-- 查询有LLM分析的财联社新闻
SELECT id, title, llm_category, llm_sentiment_score, llm_summary
FROM news_articles
WHERE source = '财联社' 
  AND llm_analyzed_at IS NOT NULL
ORDER BY llm_analyzed_at DESC
LIMIT 10;

-- 查询特定分类的新闻
SELECT id, title, llm_subcategory, llm_summary
FROM news_articles
WHERE llm_category = '宏观经济类'
ORDER BY publish_time DESC
LIMIT 10;
```

## 九、注意事项

### 9.1 数据一致性

⚠️ **去重机制**：
- 确保 `content_hash` 正确生成
- 同步前检查是否已存在

⚠️ **时间同步**：
- 确保两个系统的时区一致
- 发布时间字段正确映射

### 9.2 性能考虑

⚠️ **同步频率**：
- 建议每5-10分钟同步一次
- 避免过于频繁的数据库操作

⚠️ **批量操作**：
- 使用批量插入/更新提高性能
- 避免逐条同步

### 9.3 错误处理

⚠️ **同步失败**：
- 记录同步失败的新闻
- 支持重试机制
- 查看日志排查问题
