# 新闻系统现状与迁移总结

**创建日期**：2026-01-23  
**分析范围**：news-analysis-system-main 和 smart_stock_advisor 新闻系统

---

## 一、现状分析总结

### 1.1 news-analysis-system-main 现状

**✅ 已有功能**：
1. **新闻获取**：
   - 使用 `ak.stock_info_global_cls()` 获取财联社新闻
   - 定时获取（每1分钟）
   - 基于 `content_hash` 去重

2. **数据存储**：
   - 存储到 `news` 表（title, content, publish_date, publish_time, content_hash）
   - 数据库：`cls_news_db`

3. **LLM分析**：
   - 使用 Qwen3-4B（本地/API）进行深度分析
   - 分析结果存储到 `analysis_results` 表
   - 包含：category, subcategory, keywords, sentiment, summary, impact_markets

**❌ 缺失功能**：
1. **无股票关联**：
   - `news` 表没有 symbol, sector, industry 字段
   - `analysis_results` 表也没有股票关联字段
   - 无法知道新闻关联哪些股票

2. **单一新闻源**：
   - 只支持财联社
   - 无法扩展其他新闻源

3. **无股票匹配逻辑**：
   - 没有自动识别新闻关联股票的功能

---

### 1.2 smart_stock_advisor 新闻系统现状

**✅ 已有功能**：
1. **多源新闻获取**：
   - 13个新闻源（金十、财新、同花顺、东方财富、雪球、TuShare等）
   - 支持市场新闻和股票新闻

2. **股票关联**：
   - `news_articles` 表有 symbol, sector, industry, concept 字段
   - 支持自动关联股票（`NewsStockMapper`）
   - 支持股票名称匹配、代码提取

3. **情感分析**：
   - 基于关键词的情感分析
   - 标记利好/利空

4. **新闻去重**：
   - 基于 SimHash 去重
   - 基于标题和来源的唯一索引

**⚠️ 局限性**：
1. **分析深度不足**：
   - 仅关键词匹配，无LLM深度分析
   - 分类简单，无专业分类体系

2. **无自动总结**：
   - 不支持分类汇总和深度总结

## 二、融合方案总结

### 2.1 架构设计

```
news-analysis-system-main（统一新闻处理中心）
    ↓
    1. 获取财联社新闻
    ↓
    2. 股票关联（新增功能）
    ↓
    3. LLM深度分析
    ↓
    4. 存储到 cls_news_db

    ↓
```

## 四、数据流程

### 4.1 完整流程

```
1. news-analysis-system-main 获取财联社新闻
   ↓
2. 股票匹配（新增）
   - 提取股票代码
   - 匹配股票名称
   - 识别板块/行业
   ↓
3. 保存到 news 表（带股票关联信息）
   ↓
4. LLM分析新闻
   ↓
5. 保存分析结果到 analysis_results 表
   ↓
6. 同步到 smart_stock_advisor
   - 同步新闻（带股票关联）
   - 同步分析结果
   ↓
7. smart_stock_advisor 使用融合后的新闻数据
   - 股票预测
   - 新闻分析
```

## 五、优势总结

### 5.1 统一处理优势

✅ **单一数据源**：
- 所有新闻处理逻辑集中在 news-analysis-system-main
- 避免重复代码和逻辑不一致

✅ **深度分析**：
- LLM提供更准确的分类和情感分析
- 结合股票关联，提供更精准的预测信号

✅ **易于维护**：
- 新闻处理逻辑集中，便于维护和优化
- smart_stock_advisor 专注于股票预测
