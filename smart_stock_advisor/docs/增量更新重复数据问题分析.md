**创建日期**：2026-01-22

## 一、当前代码逻辑分析

### 1.1 增量更新前的检查（第1439-1495行）

**代码位置**：`utils/stock_history_collector.py:1439-1495`

**逻辑**：
```python
# 1. 批量查询已存在的数据
sql = """
    SELECT DISTINCT symbol, trade_date
    FROM stock_history_data 
    WHERE symbol IN (...) 
      AND trade_date IN (...)
      AND period_type = 'daily'  # ✅ 查询时过滤了period_type
"""

# 2. 存储到existing_data_map
existing_data_map[symbol][date] = True  # ⚠️ 只用了symbol和date作为key

# 3. 检查是否需要处理
if existing_data_map.get(symbol_str, {}).get(date, False):
    skip_count += 1  # 跳过
else:
    pending_tasks.append((symbol_str, date))  # 需要处理
```

**问题**：
- ✅ 查询时过滤了 `period_type = 'daily'`
- ⚠️ 但存储时只用了 `(symbol, date)` 作为key，没有考虑period_type
- ⚠️ 如果同一个股票同一天有不同period_type的数据，可能被误判为已存在

**影响**：
- 对于 `period_type = 'daily'` 的数据，逻辑是正确的
- 但如果未来有其他period_type的数据，可能会有问题

### 1.2 批量保存时的处理（第1582-1586行）

**代码位置**：`utils/stock_history_collector.py:1582-1586`

### 1.4 ON DUPLICATE KEY UPDATE（第733行）

**代码位置**：`utils/stock_history_storage.py:733`

**逻辑**：
```sql
INSERT INTO stock_history_data (...)
VALUES (...)
ON DUPLICATE KEY UPDATE ...
```

**问题**：
- ⚠️ `ON DUPLICATE KEY UPDATE` 依赖数据库唯一索引
- ⚠️ 如果唯一索引是 `uk_symbol_date` (`symbol`, `trade_date`)，缺少 `period_type`
- ⚠️ 那么同一个股票同一天可以有多条记录（如果period_type不同）
- ⚠️ 或者如果period_type都是'daily'，就会产生真正的重复数据

## 三、解决方案

### 3.1 方案1：修复数据库唯一索引（推荐）

**执行SQL脚本**：
```bash
mysql -u root -p stock_data < database/add_period_type_field.sql
```

**或者手动执行**：
```sql
-- 1. 确保period_type字段存在
ALTER TABLE `stock_history_data` 
ADD COLUMN IF NOT EXISTS `period_type` VARCHAR(10) DEFAULT 'daily' 
AFTER `trade_date`;

-- 2. 设置所有NULL值为'daily'
UPDATE `stock_history_data` 
SET `period_type` = 'daily' 
WHERE `period_type` IS NULL OR `period_type` = '';

-- 3. 删除旧唯一索引
ALTER TABLE `stock_history_data` 
DROP INDEX IF EXISTS `uk_symbol_date`;

-- 4. 创建新唯一索引
ALTER TABLE `stock_history_data` 
ADD UNIQUE KEY `uk_symbol_date_period` (`symbol`, `trade_date`, `period_type`);
```

**优势**：
- ✅ 从根本上解决问题
- ✅ `ON DUPLICATE KEY UPDATE` 可以正确工作
- ✅ 数据库层面保证数据唯一性
