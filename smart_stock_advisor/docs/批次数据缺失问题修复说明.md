# 批次数据缺失问题修复说明

**创建日期**：2026-01-22  
**问题**：设置页面定时任务数据获取，第一批次数据完整，第二批次开始很多数据缺失（如开盘价、收盘价等）

---

## 一、问题分析

### 1.1 问题现象

- **第一批次**：股票数据完整，所有字段（开盘价、收盘价等）都有数据
- **第二批次开始**：很多数据字段缺失，特别是价格相关字段（开盘价、收盘价等）

### 1.2 问题原因

**根本原因**：批量保存时，部分代码路径没有使用 `clean_nan_value()` 函数清理NaN值

**具体位置**：
1. **批量INSERT部分**（实时数据模板，第682-701行）
   - 问题：参数构建时直接使用 `data.get('open_price')` 等，没有使用 `clean_nan_value()`
   - 影响：当数据中包含NaN值时，MySQL无法处理，导致数据保存失败或字段丢失

2. **原方案（ON DUPLICATE KEY UPDATE）部分**（第1040-1077行）
   - 问题：实时数据模板和历史数据模板的参数构建都没有使用 `clean_nan_value()`
   - 影响：当使用原方案时，NaN值会导致MySQL报错或数据丢失

---

## 二、解决方案

### 2.1 修复内容

**修复位置1**：批量INSERT部分（实时数据模板）

**文件**：`utils/stock_history_storage.py`

**修改前**（第682-701行）：
```python
if use_full_fields_batch:
    params = (
        str(symbol).zfill(6), data.get('name'), date, period_type,
        data.get('open_price'), data.get('close_price'), ...
    )
```

**修改后**：
```python
if use_full_fields_batch:
    params = (
        str(symbol).zfill(6), clean_nan_value(data.get('name')), date, period_type,
        clean_nan_value(data.get('open_price')), clean_nan_value(data.get('close_price')), ...
    )
```

## 三、为什么第一批次正常，第二批次开始出问题？

### 3.1 可能的原因

1. **数据获取时机不同**：
   - 第一批次：数据可能从数据库获取（已有完整数据）
   - 第二批次：数据从API获取（可能包含NaN值）

2. **批次判断逻辑**：
   - 第一批次可能使用历史数据模板（已使用clean_nan_value）
   - 第二批次可能使用实时数据模板（之前没有使用clean_nan_value）

3. **API返回数据质量**：
   - 第一批次：API返回的数据质量较好
   - 第二批次：API返回的数据可能包含NaN值（某些字段缺失）

### 3.2 修复后的效果

- ✅ 所有批次都使用 `clean_nan_value()` 清理NaN值
- ✅ 确保所有数据都能正确保存到数据库
- ✅ 避免因NaN值导致的数据丢失
