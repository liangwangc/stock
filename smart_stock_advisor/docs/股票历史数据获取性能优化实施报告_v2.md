## 一、优化内容

### 1.1 ✅ 优化1：技术指标预计算向量化

**问题**：
- 预计算时遍历所有`missing_dates`，每个日期都要多次执行`.loc[]`访问
- 对于2500天数据，需要执行约15000次索引访问
- 耗时：50-200ms/股票

**解决方案**：
- 使用pandas的`reindex()`方法，一次性提取所有日期的指标值
- 创建DataFrame，批量提取所有指标
- 避免循环和多次`.loc[]`访问

**代码位置**：
- `utils/stock_history_collector.py` 第643-710行

**优化前**：
```python
for date_str in missing_dates:
    date_obj = pd.to_datetime(date_str)
    if date_obj in kline_data.index:
        indicators = {}
        if date_obj in ma5_series.index and pd.notna(ma5_series.loc[date_obj]):
            indicators['ma5'] = float(ma5_series.loc[date_obj])
        # ... 每个指标都要多次访问.loc[]
```

**优化后**：
```python
# 一次性提取所有日期的指标值
missing_dates_in_kline = [pd.to_datetime(d) for d in missing_dates if pd.to_datetime(d) in kline_data.index]
indicators_df = pd.DataFrame(index=missing_dates_in_kline)
indicators_df['ma5'] = ma5_series.reindex(missing_dates_in_kline)
indicators_df['ma10'] = ma10_series.reindex(missing_dates_in_kline)
# ... 批量提取所有指标
```

**预期效果**：
- 技术指标预计算时间从50-200ms降低到5-20ms
- **性能提升：10倍**

### 1.2 ✅ 优化2：涨跌幅计算使用shift()

**问题**：
- 每个日期都要查找前一日数据计算涨跌幅
- 使用`prev_idx = kline_data.index[kline_data.index < date_obj]`查找
- 对于2500天数据，需要执行2500次查找操作
- 耗时：20-50ms/股票

**解决方案**：
- 使用pandas的`shift()`方法，一次性计算所有日期的前一日收盘价
- 避免循环中的重复查找

**代码位置**：
- `utils/stock_history_collector.py` 第712-713行（预计算）
- `utils/stock_history_collector.py` 第760-765行（使用预计算的值）

**优化前**：
```python
if date_obj > kline_data.index.min():
    prev_idx = kline_data.index[kline_data.index < date_obj]
    if len(prev_idx) > 0:
        prev_close = kline_data.loc[prev_idx[-1], 'close']
```

**优化后**：
```python
# 一次性计算所有日期的前一日收盘价
pre_close_series = closes.shift(1)

# 在循环中直接使用
if date_obj in pre_close_series.index and pd.notna(pre_close_series.loc[date_obj]):
    prev_close = pre_close_series.loc[date_obj]
```

**预期效果**：
- 涨跌幅计算时间从20-50ms降低到5-10ms
- **性能提升：4倍**

### 1.3 ✅ 优化3：批量保存逻辑优化

**问题**：
- 外层循环：每100条保存一次
- 内层方法：`save_stock_daily_data_batch`内部再分批，每500条
- 如果一只股票有2500天数据，会调用25次`save_stock_daily_data_batch`
- 每次调用都要构建SQL语句、序列化JSON等
- 耗时：100-300ms/股票

**解决方案**：
- 增大外层批次大小（从100改为1000）
- 收集完所有数据后再一次性保存
- 减少SQL构建和执行次数

**代码位置**：
- `utils/stock_history_collector.py` 第717-718行（批次大小）
- `utils/stock_history_collector.py` 第826-846行（统一保存）

**优化前**：
```python
batch_size = 100  # 每批保存100条

for date_str in missing_dates:
    # ... 构建数据
    batch_data.append((date_str, data))
    
    if len(batch_data) >= batch_size:
        # 立即保存
        save_result = self.storage.save_stock_daily_data_batch(batch_data, batch_size=500)
```

**优化后**：
```python
batch_size = 1000  # 每批保存1000条（增大批次）

for date_str in missing_dates:
    # ... 构建数据
    batch_data.append((date_str, data))
    # 不立即保存，继续收集数据

# 循环结束后统一保存
if batch_data:
    save_result = self.storage.save_stock_daily_data_batch(batch_data, batch_size=500)
```

**预期效果**：
- 批量保存时间从100-300ms降低到20-50ms
- **性能提升：5倍**
