# 数据库扫描和增量获取说明

## 功能概述

批量收集脚本现在会在开始收集前自动扫描数据库，统计已有数据情况，然后根据数据情况继续获取缺失的数据。

## 主要功能

### 1. 数据库扫描 ✅

**功能**：在开始收集前，扫描数据库统计已有数据情况。

**扫描内容**：
- 总股票数
- 已有数据的股票数量
- 无数据的股票数量
- 数据完整度（已有数据/总数据）
- 总缺失天数
- 每只股票的数据范围（最早日期、最晚日期）

**实现位置**：`smart_stock_advisor/utils/stock_history_storage.py` - `scan_stock_data_status()` 方法

### 2. 增量获取 ✅

**功能**：自动识别缺失的数据，只获取缺失的部分。

**工作原理**：
1. 扫描数据库，找出每只股票的缺失日期
2. 只获取缺失日期的数据
3. 跳过已有数据，避免重复获取

**实现位置**：`smart_stock_advisor/utils/stock_history_collector.py` - `collect_stock_history_data()` 方法

### 3. 统计信息显示 ✅

**功能**：在开始收集前显示数据统计信息。

**显示内容**：
```
============================================================
正在扫描数据库，统计已有数据情况...
============================================================
扫描前 10 只股票的数据状态（示例）...
  000001: 已有 2500/2500 天 (100.00%), 缺失 0 天, 最早: 2014-01-13, 最晚: 2024-01-13
  000002: 已有 2000/2500 天 (80.00%), 缺失 500 天, 最早: 2015-01-13, 最晚: 2024-01-13
  600000: 无数据

数据库扫描完成:
  总股票数: 5000
  已有数据: 3000 只（估算）
  无数据: 2000 只（估算）
  数据完整度: 85.50%
  总缺失天数: 500000 天（估算）
============================================================
```

## 使用方法

### 基本使用（自动扫描和增量获取）

```cmd
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 50 --delay 1.0 --threads 30
```

**工作流程**：
1. 自动扫描数据库，统计已有数据
2. 显示统计信息
3. 根据数据情况，只获取缺失的数据
4. 继续收集，直到数据完整

### 继续之前的进度

```cmd
py scripts\batch_collect_10years_data.py --market cn --years 10 --batch-size 50 --delay 1.0 --threads 30 --resume
```

**工作流程**：
1. 加载之前的进度文件
2. 扫描数据库，统计已有数据
3. 跳过已完成和失败的股票
4. 继续收集剩余股票

### 强制刷新（重新获取所有数据）

如果需要强制刷新所有数据，可以修改代码中的 `force_refresh` 参数：

```python
# 在 collect_single_stock 方法中
result = collector.collect_stock_history_data(
    symbol=symbol,
    years=years,
    force_refresh=True  # 强制刷新
)
```

## 性能优化

### 1. 扫描优化

- **样本扫描**：只扫描前10只股票，避免扫描所有股票耗时过长
- **估算统计**：基于样本估算所有股票的情况
- **快速查询**：使用索引优化数据库查询

### 2. 增量获取优化

- **批量获取**：使用批量模式一次性获取多年数据
- **跳过已有数据**：自动跳过已有数据，只获取缺失部分
- **智能回退**：批量模式失败时自动回退到逐日模式

## 注意事项

1. **扫描时间**：
   - 扫描前10只股票通常需要几秒到几十秒
   - 如果股票数量很大，可以考虑增加样本数量

2. **数据完整性**：
   - 扫描结果基于样本估算，实际数据可能略有差异
   - 建议定期检查数据完整性

3. **增量获取**：
   - 默认只获取缺失的数据
   - 如果需要强制刷新，需要修改代码

4. **数据库性能**：
   - 确保数据库有适当的索引（symbol, trade_date, period_type）
   - 如果数据量很大，扫描可能需要一些时间

## 故障排除

### 问题1：扫描时间过长

**可能原因**：
1. 股票数量很大
2. 数据库查询慢
3. 缺少索引

**解决方法**：
1. 减少样本数量（修改代码中的 `sample_size`）
2. 优化数据库索引
3. 检查数据库连接性能

### 问题2：扫描结果不准确

**可能原因**：
1. 样本数量太少
2. 数据分布不均匀

**解决方法**：
1. 增加样本数量
2. 使用随机采样而不是前N只股票

### 问题3：增量获取失败

**可能原因**：
1. 数据库查询失败
2. 日期格式不匹配

**解决方法**：
1. 检查数据库连接
2. 检查日期格式（应为 YYYY-MM-DD）
3. 查看日志中的错误信息
