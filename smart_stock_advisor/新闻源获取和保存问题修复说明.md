# 新闻源获取和保存问题修复说明

## 一、问题

用户反馈：
1. **新闻源获取的数据太少**：理论上不可能这么少
2. **日志显示获取了几条新闻，但都没存储到数据库中**

## 二、问题分析

### 1. 新闻源获取数量问题

**`UnifiedNewsSource.get_market_news()` 方法**（`unified_news_source.py` 第358行）：

**原逻辑**：
```python
news = source.get_market_news(limit // len(self.sources) + 1)
```

**问题**：
- 如果 `limit=30`，有6个新闻源，每个新闻源只获取 `30 // 6 + 1 = 6` 条
- 总共最多36条，但去重后可能更少
- **每个新闻源的获取数量太少**

**示例**：
- 配置的新闻源：金十数据、财新、证券公司、同花顺、东方财富、雪球（6个）
- `limit=15`（每个新闻源限制）
- 实际调用：`limit * 2 = 30`
- 每个新闻源获取：`30 // 6 + 1 = 6` 条
- 总共：6个源 × 6条 = 36条（去重后可能更少）

### 2. 新闻保存问题

**`save_news_article()` 返回 `None` 的情况**：
1. 数据库未启用
2. 标题为空
3. 新闻已存在（重复）
4. 保存失败（异常）

**`crawl_all_news()` 中的处理**（第411-415行）：
```python
if news_id:
    total_success += 1
else:
    # news_id 为 None 表示新闻已存在（重复）
    total_duplicate += 1
```

**问题**：
- 如果 `news_id` 为 `None`，可能是保存失败，但代码中计入 `total_duplicate`
- **无法区分保存失败和重复**
- 如果保存失败，日志中会显示为"重复"，但实际上没有保存

### 3. 日志输出问题

**缺少详细的保存日志**：
- 成功保存的新闻没有详细日志
- 保存失败的新闻没有详细日志
- 无法追踪哪些新闻保存成功，哪些失败

## 三、修复方案

### 1. 优化新闻源获取数量

**修改 `UnifiedNewsSource.get_market_news()`**：
```python
# 优化：增大每个新闻源的获取数量，确保有足够的新闻
source_limit = max(limit, limit * 2 // max(len(self.sources), 1))
# 至少每个源获取 limit 条，或者 limit*2/源数量
```

**修改 `crawl_all_news()`**：
```python
# 优化：使用更大的limit，确保每个源都能获取足够的新闻
effective_limit = max(limit * 5, 100)  # 至少100条，或者limit*5
news_list = self.news_source.get_market_news(limit=effective_limit, only_today=False)
```

### 2. 改进保存失败检测

**修改 `crawl_all_news()` 中的保存逻辑**：
```python
news_id = self.news_storage.save_news_article(news, ...)
if news_id:
    total_success += 1
elif news_id is None:
    # 需要区分：保存失败 vs 重复
    if not title:
        total_failed += 1  # 标题为空，保存失败
    else:
        # 检查是否是重复（通过查询数据库）
        check_result = DBConnection.execute_query(...)
        if check_result:
            total_duplicate += 1  # 已存在，重复
        else:
            total_failed += 1  # 保存失败
```

### 3. 增强日志输出

**添加详细的保存日志**：
- 成功保存：记录前5条成功保存的新闻
- 保存失败：记录详细的错误信息
- 重复检测：记录前5条重复的新闻

## 四、修复后的行为

### 1. 新闻源获取

**修复前**：
- `limit=15` → 每个源获取 `30 // 6 + 1 = 6` 条
- 总共：36条（去重后可能更少）

**修复后**：
- `limit=15` → `effective_limit = max(15*5, 100) = 100`
- 每个源获取：`max(100, 100*2/6) = 100` 条
- 总共：6个源 × 100条 = 600条（去重后可能200-300条）

**提升：10-20倍**

### 2. 保存失败检测

**修复前**：
- 保存失败 → 计入 `total_duplicate`
- 无法区分失败和重复

**修复后**：
- 保存失败 → 计入 `total_failed`
- 重复 → 计入 `total_duplicate`
- 可以准确统计

### 3. 日志输出

**修复后**：
- 记录前5条成功保存的新闻
- 记录保存失败的详细错误
- 记录重复检测的结果
