# 新闻时间过滤逻辑说明与优化

## 一、问题

用户看到日志：
```
2026-01-14 16:30:03 - utils.news_crawler - INFO - 获取到 5 条新闻，时间过滤后 0 条 （时间范围外: 5 条，时间解析失败: 0 条）
```

**疑问**：
1. 根据什么时间过滤的？
2. 过滤后是不是就没有存在数据库中？

## 二、时间过滤逻辑

### 1. 时间范围计算

**`_calculate_time_range()` 方法**（`news_crawler.py` 第208行）：

**逻辑**：
- 如果有 `last_fetch_time`（上次获取时间）：
  - `start_time = last_fetch_time`（从上次获取时间开始）
  - `end_time = now`（到现在）
- 如果没有 `last_fetch_time`（首次获取）：
  - `start_time = 当天00:00`（从当天开始）
  - `end_time = now`（到现在）

**示例**：
- 上次获取时间：`2026-01-14 16:30:33`
- 当前时间：`2026-01-14 16:35:33`
- 时间范围：`2026-01-14 16:30:33` 到 `2026-01-14 16:35:33`（5分钟）

### 2. 时间过滤

**`crawl_all_news()` 方法**（`news_crawler.py` 第315-338行）：

**过滤逻辑**：
```python
for news in news_list:
    news_time = news.get('time') or news.get('publish_time') or news.get('pub_time')
    news_datetime = self._parse_news_time(news_time)
    
    if news_datetime:
        # 检查时间是否在范围内
        if start_time <= news_datetime <= end_time:
            filtered_news.append(news)  # ✅ 保留
        else:
            time_out_of_range += 1  # ❌ 过滤掉
    else:
        # 没有时间信息或解析失败，默认保留（可能是实时新闻）
        filtered_news.append(news)  # ✅ 保留
```

**过滤规则**：
- ✅ **保留**：新闻发布时间在 `[start_time, end_time]` 范围内
- ✅ **保留**：新闻没有时间信息（可能是实时新闻）
- ✅ **保留**：新闻时间解析失败（避免误过滤）
- ❌ **过滤掉**：新闻发布时间不在时间范围内

### 3. 保存到数据库

**只有 `filtered_news` 中的新闻才会保存**（`news_crawler.py` 第369行）：

```python
for idx, news in enumerate(filtered_news, 1):  # 只处理过滤后的新闻
    # ...
    news_id = self.news_storage.save_news_article(news, ...)  # 保存到数据库
```

**结论**：
- ✅ **只有过滤后的新闻才会保存到数据库**
- ❌ **被过滤掉的新闻（时间范围外的）不会保存到数据库**

## 三、问题分析

### 1. 用户的情况

**日志显示**：
- 获取到 5 条新闻
- 时间过滤后 0 条
- 时间范围外: 5 条

**原因**：
- 这5条新闻的发布时间都不在时间范围内
- 例如：时间范围是 `16:30:33` 到 `16:35:33`（5分钟）
- 但新闻的发布时间可能是 `16:25:00`（早于start_time）或 `16:40:00`（晚于end_time）

### 2. 可能的问题

**问题1：时间范围太窄**
- 增量抓取的时间范围只有5分钟
- 如果新闻发布时间不在这个5分钟窗口内，会被过滤掉

**问题2：新闻时间不准确**
- 新闻源的发布时间可能不准确
- 或者时间格式解析有问题

**问题3：首次抓取时间范围问题**
- 如果是首次抓取，时间范围是从当天00:00开始
- 但如果当前时间是16:30，而新闻发布时间是16:25，会被过滤掉

## 四、优化方案

### 方案1：放宽时间范围（推荐）

**修改 `_calculate_time_range()` 方法**：
- 增量抓取时，往前多推一些时间（例如：往前推30分钟）
- 确保不会漏掉新闻

**代码修改**：
```python
if last_fetch_time:
    # 增量获取：从上次获取时间往前推30分钟到现在
    start_time = last_fetch_time - timedelta(minutes=30)  # 往前推30分钟
    end_time = now
```

### 方案2：保存所有新闻（不推荐）

**修改过滤逻辑**：
- 不进行时间过滤，保存所有获取到的新闻
- 但这样会导致重复抓取和存储大量旧新闻

### 方案3：记录被过滤的新闻（推荐）

**修改保存逻辑**：
- 即使被时间过滤，也保存到数据库，但标记为"时间范围外"
- 这样不会丢失数据，但可以区分

## 五、推荐的修复方案

### 方案：放宽时间范围 + 记录被过滤的新闻

**修改 `_calculate_time_range()`**：
```python
if last_fetch_time:
    # 增量获取：从上次获取时间往前推30分钟到现在（避免漏掉新闻）
    start_time = last_fetch_time - timedelta(minutes=30)
    end_time = now
```

**修改保存逻辑**：
```python
# 保存所有新闻（包括时间范围外的），但标记时间范围外的新闻
for news in news_list:
    news_time = news.get('time') or news.get('publish_time') or news.get('pub_time')
    news_datetime = self._parse_news_time(news_time)
    
    is_in_range = True
    if news_datetime:
        if not (start_time <= news_datetime <= end_time):
            is_in_range = False
    
    # 保存新闻，标记是否在时间范围内
    news['is_in_time_range'] = is_in_range
    news_id = self.news_storage.save_news_article(news, ...)
```

## 六、当前行为总结

### 1. 时间过滤依据

**根据新闻的发布时间（`publish_time`）过滤**：
- 如果新闻发布时间在 `[start_time, end_time]` 范围内 → ✅ 保留
- 如果新闻发布时间不在范围内 → ❌ 过滤掉
- 如果新闻没有时间信息 → ✅ 保留（可能是实时新闻）

### 2. 保存到数据库

**只有过滤后的新闻才会保存**：
- ✅ `filtered_news` 中的新闻 → 保存到数据库
- ❌ 被过滤掉的新闻（时间范围外的）→ **不会保存到数据库**

### 3. 用户的情况

**获取到5条新闻，但都被过滤掉了**：
- 原因：这5条新闻的发布时间都不在时间范围内
- 结果：**这5条新闻都没有保存到数据库**

## 七、建议

### 1. 短期方案

**放宽时间范围**：
- 增量抓取时，往前推30分钟，避免漏掉新闻
- 这样可以确保不会因为时间范围太窄而漏掉新闻

### 2. 长期方案

**保存所有新闻，但标记时间范围**：
- 保存所有获取到的新闻
- 添加字段标记是否在时间范围内
- 这样不会丢失数据，但可以区分
