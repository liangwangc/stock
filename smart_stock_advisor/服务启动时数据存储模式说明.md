## 启动时的初始化顺序

### 1. 模块导入阶段（在 `web_app.py` 文件加载时）

#### 1.1 配置读取
```python

```
- **操作**：从 `config_db.py` 读取 `USE_DATABASE` 配置
- **默认值**：如果导入失败，`USE_DATABASE = False`
- **当前设置**：`USE_DATABASE = True`（使用数据库模式）

#### 1.2 数据库连接模块导入
```python
from utils.db_connection import DatabaseConnection
```
- **操作**：导入 `DatabaseConnection` 类
- **行为**：
  - 读取 `config_db.py` 中的 `DB_CONFIG` 和 `USE_DATABASE`
  - **不会**创建数据库连接
  - **不会**执行任何数据库操作
  - 只是定义类，准备使用

#### 1.3 股票预测数据库模块导入
```python
from utils.stock_prediction_db import StockPredictionDB
```
- **操作**：导入 `StockPredictionDB` 类
- **行为**：
  - 读取 `USE_DATABASE` 配置
  - **不会**实例化类
  - **不会**创建数据库连接
  - 只是导入类定义

#### 1.4 其他存储模块导入（延迟导入）
- `NewsStorage` - 新闻存储（可选，导入失败不影响主功能）
- `NewsTaskManager` - 新闻任务管理（可选）
- **行为**：只是导入类，不实例化

#### 1.5 数据源和预测器模块导入
```python

from predictor.stock_predictor import StockPredictor
from visualizer.prediction_visualizer import PredictionVisualizer
```
- **行为**：
  - `StockDataSource.__init__` 会检查 `USE_DATABASE`，如果为True则创建 `DataStorage` 实例
  - `StockPredictor.__init__` 会创建 `DataStorage` 实例（如果配置启用）

### 2. DataStorage 初始化（当 StockDataSource 或 StockPredictor 被导入时）

#### 2.1 初始化过程
```python
class DataStorage:
    def __init__(self, base_dir: str = "data"):
        self.use_database = USE_DATABASE  # 读取配置
        
        if self.use_database:
            try:
                self.db_storage = DatabaseStorage()  # 创建数据库存储实例
                self.logger.info("数据存储模式：数据库")
            except Exception as e:
                self.logger.warning(f"数据库初始化失败，回退到CSV模式: {str(e)}")
                self.use_database = False
        else:
            self.db_storage = None
            self.logger.info("数据存储模式：CSV文件")
```

#### 2.2 具体行为
- ✅ **检查配置**：读取 `USE_DATABASE` 配置
- ✅ **创建 DatabaseStorage 实例**（如果 `USE_DATABASE = True`）
- ✅ **记录日志**：输出 "数据存储模式：数据库" 或 "数据存储模式：CSV文件"
- ❌ **不会**连接数据库
- ❌ **不会**创建或检查表
- ❌ **不会**执行任何数据库操作
- ❌ **不会**读写任何数据

### 4. DatabaseConnection 初始化（延迟连接）

#### 4.1 类定义
```python
class DatabaseConnection:
    """数据库连接管理器（线程安全）"""
    _local = threading.local()  # 线程本地存储
```

#### 4.2 具体行为
- ✅ **使用线程本地存储**：确保每个线程有独立的连接
- ✅ **定义连接方法**：`get_connection()` 方法会在首次调用时创建连接
- ❌ **启动时不会创建连接**：连接是延迟创建的（lazy initialization）
- ❌ **不会**主动连接数据库

#### 4.3 连接创建时机
数据库连接只在以下情况才会创建：
1. 首次调用 `DatabaseConnection.get_connection()`
2. 首次执行 SQL 查询（`execute_query`）
3. 首次执行 SQL 更新（`execute_update`）
4. 首次访问数据库功能（如用户登录、查询股票列表等）

## 数据库连接的创建时机

数据库连接使用**延迟初始化（Lazy Initialization）**策略：

### 首次连接时机

1. **用户登录时**：
   - 验证用户名密码
   - 查询 `users` 表
   - 验证会话（查询 `user_sessions` 表）

2. **访问股票列表时**：
   - `/api/stocks` API调用
   - 查询 `stock_predictions` 表

3. **执行股票分析时**：
   - 保存预测结果到 `stock_predictions` 表
   - 保存指标数据到各个表

4. **访问新闻功能时**：
   - 查询 `news_articles` 表
   - 保存新闻数据

5. **访问任务历史时**：
   - 查询 `analysis_tasks` 表

## 当前数据存储模式

### 配置位置
`smart_stock_advisor/config_db.py`

```python
USE_DATABASE = True  # 当前使用数据库模式
```

### 存储方式
- **数据库模式**（`USE_DATABASE = True`）：
  - 所有数据存储在 MySQL 数据库
  - 表名：`stock_data` 数据库
  - 主要表：
    - `stock_predictions` - 股票预测记录
    - `users` - 用户表
    - `user_sessions` - 用户会话表
    - `news_articles` - 新闻文章表
    - `analysis_tasks` - 分析任务历史表
    - `north_bound_capital` - 北向资金数据
    - `margin_trading` - 融资融券数据
    - `main_force_capital` - 主力资金数据
    - `sector_rotation` - 板块轮动数据
    - `technical_indicators` - 技术指标数据
    - `news_sentiment` - 新闻情感数据
    - `market_sentiment` - 市场情绪数据
    - `prediction_factors` - 预测因子数据
    - `cost_distribution` - 成本分布数据
    - `realtime_trading_decisions` - 实时交易决策数据

- **CSV模式**（`USE_DATABASE = False`）：
  - 所有数据存储在 `data/` 目录下的CSV文件
  - 当前**未启用**

## 注意事项

1. **数据库连接是延迟创建的**：
   - 服务启动时不会立即连接数据库
   - 只有在首次使用数据库功能时才会创建连接
   - 连接失败会在首次使用时抛出异常

2. **表检查是延迟的**：
   - 服务启动时不会检查表是否存在
   - 首次访问相关功能时可能会自动创建表（如 `analysis_tasks` 表）
   - 如果表不存在，会在首次使用时报错

3. **数据存储模式确定**：
   - 启动时根据 `USE_DATABASE` 配置确定存储模式
   - 如果数据库初始化失败，`DataStorage` 会自动回退到CSV模式
   - 不会因为数据库问题导致服务无法启动

4. **不会自动运行任务**：
   - 服务启动时不会自动执行任何数据操作
   - 所有数据操作必须通过API手动触发
   - 这是设计如此，避免意外消耗资源

## 结论

**服务启动时，数据存储模式只是读取配置和准备模块，不会执行任何数据库操作。数据库连接和操作都是延迟的，只在首次使用时才会执行。**

这种设计的好处：
1. 启动速度快
2. 不会因为数据库问题导致服务无法启动
3. 资源占用小
4. 灵活性高（可以在运行时切换存储模式）
