# Web应用启动说明

## 启动行为说明

**重要：Web应用启动时不会自动运行任何分析或抓取任务。**

### 当前行为

1. **服务启动**：
   - 启动Flask Web服务器
   - 初始化必要的模块（但不会自动启动任务）
   - 提供Web界面访问

2. **不自动启动的内容**：
   - ❌ 不会自动运行股票分析任务
   - ❌ 不会自动启动新闻抓取任务
   - ❌ 不会恢复数据库中标记为"激活"的任务
   - ❌ 不会自动执行任何后台分析或抓取

3. **需要手动触发**：
   - ✅ 股票分析：通过设置页面 > 任务管理 > 点击"开始全量分析"或"分析部分股票"
   - ✅ 新闻抓取：通过设置页面 > 新闻抓取 > 创建任务 > 点击"启动"按钮

## 手动启动任务

### 1. 股票分析任务

访问：http://localhost:5000/settings

在"任务管理"标签页：
- **全量分析**：点击"▶️ 开始全量分析"按钮
- **部分分析**：输入数量，点击"▶️ 分析部分股票"按钮

### 2. 新闻抓取任务

在"新闻抓取"标签页：
1. 点击"➕ 创建新任务"
2. 填写任务信息（名称、类型、间隔、股票代码等）
3. 点击"创建"
4. 在任务列表中找到创建的任务，点击"▶️ 启动"按钮

## 注意事项

1. **服务重启**：
   - 服务重启后，所有任务都会停止
   - 需要重新手动启动任务
   - 数据库中已创建的任务不会自动恢复运行

2. **任务持久化**：
   - 任务配置保存在数据库中
   - 但任务的运行状态不会自动恢复
   - 每次重启服务后需要手动启动

3. **资源消耗**：
   - 启动服务本身消耗资源很少
   - 只有手动启动任务后才会消耗CPU、内存、网络资源

## 技术实现

### 初始化顺序

1. Flask应用初始化
2. 导入模块（延迟初始化）
   - `NewsTaskManager` - 仅初始化，不启动任务
   - `NewsStorage` - 仅初始化，不抓取新闻
   - `StockPredictor` - 仅初始化，不执行分析
3. Web服务器启动

### 任务启动流程

**股票分析任务**：
```
用户点击按钮 → API调用 /api/tasks/start → 创建后台线程 → 执行分析
```

**新闻抓取任务**：
```
用户创建任务 → 用户点击启动 → API调用 /api/news/tasks/<id>/start → 
NewsTaskManager.start_task() → NewsCrawler.start_crawl_task() → 创建定时线程
```

## 常见问题

**Q: 为什么服务启动后没有自动开始分析？**
A: 这是设计如此。Web应用仅提供服务，所有任务必须手动启动，这样可以避免意外消耗资源。

**Q: 服务重启后，之前的任务会继续运行吗？**
A: 不会。所有任务在服务停止时都会停止，重启后需要手动重新启动。

**Q: 如何让任务自动启动？**
A: 当前版本不支持自动启动。如果需要，可以在 `web_app.py` 的 `if __name__ == '__main__':` 部分添加自动启动逻辑（但需要谨慎，避免资源浪费）。
