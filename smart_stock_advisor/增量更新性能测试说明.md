# 增量更新性能测试说明

**创建日期**：2026-01-15

---

## 一、测试脚本

**文件**：`scripts/test_incremental_update_performance.py`

**功能**：
- 测试增量更新的性能
- 分析各个API调用的耗时
- 找出性能瓶颈
- 对比快速模式和普通模式的性能

---

## 二、使用方法

### 2.1 基本用法

**测试指定股票**：
```bash
py scripts/test_incremental_update_performance.py --symbols 000001 600519 000002
```

**测试前10只股票（从数据库获取）**：
```bash
py scripts/test_incremental_update_performance.py --all --test-count 10
```

**测试API性能**：
```bash
py scripts/test_incremental_update_performance.py --symbols 000001 600519 --api-test
```

**测试批量更新性能**：
```bash
py scripts/test_incremental_update_performance.py --symbols 000001 600519 000002 --batch-test --max-workers 10
```

### 2.2 参数说明

| 参数 | 说明 | 默认值 |
|-----|------|--------|
| `--symbols` | 股票代码列表 | 默认5只股票 |
| `--all` | 从数据库获取所有股票 | False |
| `--test-count` | 测试股票数量 | 10 |
| `--fast-mode` | 使用快速模式 | True |
| `--no-fast-mode` | 不使用快速模式 | - |
| `--api-test` | 测试各个API的性能 | False |
| `--batch-test` | 测试批量更新性能 | False |
| `--max-workers` | 最大线程数 | 10 |

## 三、测试内容

### 3.1 API性能测试

**测试的API**：
1. `get_stock_info()` - 获取股票信息
2. `get_stock_data()` - 获取K线数据（当日）

## 四、性能瓶颈分析

### 4.1 数据采集耗时占比

**如果数据采集耗时占比 > 80%**：
- ⚠️ **性能瓶颈：数据采集**
- **建议**：
  - 优化API调用（减少不必要的API调用）
  - 使用快速模式（`--fast-mode`）
  - 增加线程数（`--max-workers`）

### 4.2 数据保存耗时占比

**如果数据保存耗时占比 > 50%**：
- ⚠️ **性能瓶颈：数据保存**
- **建议**：
  - 优化数据库操作（使用批量保存）
  - 检查数据库索引
  - 优化SQL查询

### 4.3 性能分布均匀

**如果数据采集和数据保存耗时分布较均匀**：
- ✓ **性能分布较均匀**
- **建议**：
  - 可以同时优化API调用和数据库操作
  - 使用多线程提升整体性能

## 六、性能优化建议

### 6.1 如果API调用慢

**问题**：数据采集耗时占比 > 80%

**优化方案**：
1. **使用快速模式**：`--fast-mode`（默认已启用）
2. **减少API调用**：跳过不必要的API（成本分布、资金流向等）
3. **优化API调用顺序**：先调用快速API，后调用慢速API
4. **使用缓存**：缓存股票列表、股票信息等

### 6.2 如果数据库操作慢

**问题**：数据保存耗时占比 > 50%

**优化方案**：
1. **使用批量保存**：`save_stock_daily_data_batch()`
2. **优化数据库索引**：确保索引正确
3. **减少数据库查询**：批量查询已存在的数据
4. **使用连接池**：优化数据库连接管理

### 6.3 如果整体性能慢

**问题**：单只股票耗时 > 5秒

**优化方案**：
1. **使用多线程**：`--max-workers 10`（或更多）
2. **批量处理**：一次处理多只股票
3. **并行处理**：API调用和数据库操作并行
4. **异步处理**：使用异步IO

## 八、注意事项

1. **测试数量**：建议先测试少量股票（5-10只），确认性能后再测试更多
2. **网络环境**：API调用速度受网络环境影响，建议在网络稳定时测试
3. **数据库状态**：确保数据库连接正常，索引已创建
4. **API限制**：注意API调用频率限制，避免被限流

## 九、问题排查

### 9.1 如果测试失败

**检查**：
1. 数据库连接是否正常
2. API是否可用
3. 股票代码是否正确
4. 网络连接是否正常

### 9.2 如果性能异常慢

**检查**：
1. 是否使用了快速模式
2. 线程数是否设置合理
3. 数据库是否有性能问题
4. API响应是否正常
