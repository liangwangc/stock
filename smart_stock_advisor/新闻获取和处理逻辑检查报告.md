## 一、新闻获取入口

### 1.1 定时任务入口

**文件**：`utils/scheduled_task_manager.py`

**方法**：`_execute_news_crawl(task: Dict)`

**入口点**：
- 通过 `ScheduledTaskManager` 统一调度
- 任务类型：`news_crawl`
- 支持的任务配置：
  - `task_type`: `'all'` / `'market'` / `'stock'`
  - `symbol`: 股票代码（股票新闻需要）
  - `interval_minutes`: 抓取间隔（分钟）
  - `limit`: 每个新闻源的限制数量

**执行流程**：
```python
1. 解析任务配置（task_config）
2. 初始化 UnifiedNewsSource、NewsStorage、NewsCrawler
3. 根据 task_type 执行不同逻辑：
   - 'all': 调用 news_crawler.crawl_all_news()（增量抓取）
   - 'market': 调用 news_source.get_market_news()
   - 'stock': 调用 news_source.get_stock_news()
4. 保存新闻到数据库
5. 返回执行结果统计
```

### 1.2 手动抓取入口

**文件**：`utils/news_crawler.py`

**方法**：
- `crawl_market_news()` - 抓取市场新闻
- `crawl_stock_news()` - 抓取股票新闻
- `crawl_all_news()` - 抓取所有新闻（增量）

## 二、新闻获取逻辑

### 2.1 统一新闻源（UnifiedNewsSource）

**文件**：`quant_trading_platform/news/unified_news_source.py`

**核心方法**：
- `get_market_news(limit, only_today)` - 获取市场新闻
- `get_stock_news(symbol, limit, only_today)` - 获取股票新闻

**获取流程**：
```
1. 遍历所有新闻源（self.sources）
2. 对每个新闻源：
   - 使用线程独立执行（超时30秒）
   - 调用 source.get_market_news(source_limit)
   - 如果超时或失败，跳过该新闻源，继续下一个
3. 聚合所有新闻源的新闻
4. 去重（基于标题）
5. 过滤当天新闻（如果 only_today=True）
6. 按相关性和时间排序
7. 返回限制数量的新闻
```

**优化点**：
- ✅ 已添加超时控制（30秒）
- ✅ 已添加错误隔离（单个失败不影响其他）
- ✅ 已优化每个新闻源的获取数量（至少 limit 条）

### 2.2 单个新闻源获取

**文件**：`quant_trading_platform/news/*_news_source.py`

**示例**：`jin10_news_source.py`

**获取流程**：
```
1. 尝试多个备用URL（3个）
2. 逐个尝试URL，直到成功或全部失败
3. 解析响应数据（支持多种格式）
4. 转换为统一格式：
   {
       'title': str,
       'content': str,
       'time': datetime,
       'url': str,
       'source': str,
       'type': str
   }
5. 返回新闻列表
```

**优化点**：
- ✅ 已添加多个备用URL
- ✅ 已添加请求头（User-Agent、Referer等）
- ✅ 已改进数据解析（支持多种响应格式）

## 三、新闻处理流程

### 3.1 新闻内容分析

**文件**：`utils/news_content_analyzer.py`

**分析时机**：在 `news_crawler.py` 的 `crawl_all_news()` 中

**分析内容**：
1. **发布时间分析**：
   - 解析发布时间
   - 检测时间异常（未来时间、过旧时间）
   - 评估时间质量

2. **可信度分析**：
   - 检测可疑关键词
   - 评估新闻源可信度
   - 评估内容长度

3. **可靠性评分**：
   - 综合时间分析和可信度分析
   - 生成 reliability_score (0-1)
   - 判断是否可用于预测

**分析结果**：
```python
{
    'reliability_score': float,  # 0-1
    'is_reliable': bool,
    'should_use_for_prediction': bool,
    'time_analysis': dict,
    'credibility_analysis': dict,
    'warnings': list
}
```

### 3.2 新闻存储处理

**文件**：`utils/news_storage.py`

**方法**：`save_news_article(news, symbol, sector, industry, concept)`

**处理流程**：
```
1. 提取新闻信息（title, content, source, url, time）
2. 时间处理：
   - 尝试多个时间字段（time, publish_time, pub_time）
   - 如果无时间，尝试从内容提取
   - 如果仍无时间，使用当前时间
3. 判断新闻类型（market/stock/policy/industry）
4. 判断相关性类型（direct/industry/market）
5. 情感分析：
   - 调用 _analyze_sentiment()
   - 生成 sentiment, sentiment_score, sentiment_confidence
   - 判断 is_positive, is_negative, is_policy
6. 内容分析结果（如果已分析）：
   - reliability_score, is_reliable, should_use_for_prediction
   - time_analysis, credibility_analysis, warnings
7. 去重检查：
   - 先检查精确匹配（标题+来源）
   - 再检查SimHash相似度（如果启用）
8. 自动关联股票（如果未指定symbol）：
   - 使用 StockMapper 自动匹配
   - 更新 symbol, sector, industry
9. 计算SimHash（用于相似度检测）
10. 保存到数据库：
    - 尝试包含simhash字段的SQL
    - 如果失败，使用不包含simhash的SQL
    - 处理字段缺失的情况（向后兼容）
11. 返回新闻ID
```

**关键优化**：
- ✅ 支持多种时间格式解析
- ✅ 支持从内容提取时间
- ✅ 支持SimHash去重
- ✅ 支持自动关联股票
- ✅ 支持字段缺失的向后兼容

### 3.3 批量保存

**文件**：`utils/news_storage.py`

**方法**：`save_news_batch(news_list, symbol, sector, industry, concept)`

**处理流程**：
```
1. 遍历新闻列表
2. 对每条新闻调用 save_news_article()
3. 统计成功、失败、重复数量
4. 返回统计结果
```

## 四、发现的问题和建议

### 4.1 问题

#### 问题1：新闻内容分析未在所有路径执行
**位置**：`utils/scheduled_task_manager.py` 的 `_execute_news_crawl()`

**问题描述**：
- `task_type='all'` 时，调用 `news_crawler.crawl_all_news()`，内部会进行内容分析
- `task_type='market'` 或 `'stock'` 时，直接调用 `news_source.get_market_news()`，**未进行内容分析**

**影响**：
- 市场新闻和股票新闻缺少内容分析结果
- 无法过滤不可靠的新闻

**建议**：
在保存新闻前，统一进行内容分析：
```python
# 在保存新闻前添加内容分析
from utils.news_content_analyzer import NewsContentAnalyzer
analyzer = NewsContentAnalyzer()

for news_item in news_list:
    # 进行内容分析
    analysis_result = analyzer.analyze_news(news_item)
    news_item.update(analysis_result)
    
    # 然后保存
    news_id = news_storage.save_news_article(news_item)
```

#### 问题2：新闻获取后未过滤不可靠新闻
**位置**：`utils/scheduled_task_manager.py` 和 `utils/news_crawler.py`

**问题描述**：
- 即使进行了内容分析，仍然会保存 `should_use_for_prediction=False` 的新闻
- 这些新闻可能误导预测

**建议**：
在保存前过滤不可靠新闻：
```python
# 过滤不可靠新闻
reliable_news = []
for news_item in news_list:
    analysis_result = news_item.get('analysis_result') or analyzer.analyze_news(news_item)
    if analysis_result.get('should_use_for_prediction', True):
        reliable_news.append(news_item)
    else:
        self.logger.warning(f"跳过不可靠新闻: {news_item.get('title', '')[:50]}...")

# 只保存可靠的新闻
for news_item in reliable_news:
    news_id = news_storage.save_news_article(news_item)
```

#### 问题3：内存清理不完整
**位置**：`utils/scheduled_task_manager.py` 的 `_execute_news_crawl()`

**问题描述**：
- `task_type='all'` 时，`crawl_all_news()` 内部会清理内存
- `task_type='market'` 或 `'stock'` 时，`news_list` 未清理

**建议**：
在 finally 块中统一清理：
```python
finally:
    # 清理内存
    if news_list:
        del news_list
    if news_source:
        del news_source
    if news_storage:
        del news_storage
    if news_crawler:
        del news_crawler
    import gc
    gc.collect()
```

#### 问题4：错误处理不够详细
**位置**：`utils/scheduled_task_manager.py` 的 `_execute_news_crawl()`

**问题描述**：
- 保存新闻时，只统计成功/失败数量
- 未记录具体失败原因

**建议**：
记录详细的错误信息：
```python
for news_item in news_list:
    try:
        news_id = news_storage.save_news_article(news_item)
        if news_id:
            success_count += 1
        else:
            duplicate_count += 1
    except Exception as e:
        fail_count += 1
        self.logger.error(f"保存新闻失败: {news_item.get('title', '')[:50]}... 错误: {str(e)}")
```

### 4.2 优化建议

#### 建议1：统一内容分析入口
在 `NewsStorage.save_news_article()` 中统一进行内容分析，确保所有保存的新闻都经过分析。

#### 建议2：添加新闻质量过滤
在保存前过滤低质量新闻：
- 时间异常（未来时间、过旧时间）
- 可信度低（可疑关键词、不可信来源）
- 内容过短（少于50字）

#### 建议3：优化日志记录
- 记录每个新闻源的获取情况
- 记录内容分析结果
- 记录过滤掉的新闻及原因

#### 建议4：添加监控指标
- 新闻获取成功率
- 新闻质量分布（可靠性评分分布）
- 各新闻源的贡献度

## 五、完整流程图

```
定时任务触发
    ↓
_execute_news_crawl()
    ↓
根据 task_type 选择路径：
    ├─ 'all' → crawl_all_news()

    │   ├─ 获取新闻（带超时控制）

    │   ├─ 保存到数据库（save_news_batch）
    │   └─ 返回统计结果
    │
    ├─ 'market' → get_market_news()
    │   ├─ 遍历所有新闻源
    │   ├─ 获取新闻（带超时控制）
    │   ├─ 去重和排序
    │   ├─ ❌ 未进行内容分析
    │   ├─ 保存到数据库（save_news_article）
    │   └─ 返回统计结果
    │
    └─ 'stock' → get_stock_news()
        ├─ 遍历所有新闻源
        ├─ 获取新闻（带超时控制）
        ├─ 去重和排序
        ├─ ❌ 未进行内容分析
        ├─ 保存到数据库（save_news_article）
        └─ 返回统计结果

保存新闻流程（save_news_article）：
    ├─ 提取新闻信息
    ├─ 时间处理（多种格式）
    ├─ 判断新闻类型和相关性
    ├─ 情感分析
    ├─ 去重检查（精确匹配 + SimHash）
    ├─ 自动关联股票（可选）
    ├─ 保存到数据库
    └─ 返回新闻ID
```
