# 新闻获取定时任务问题修复说明

## 问题分析

### 发现的问题

1. **方法名错误**：
   - `_execute_news_crawl` 方法中调用了 `fetch_market_news()` 和 `fetch_all_news()` 方法
   - 但 `UnifiedNewsSource` 类中只有 `get_market_news()` 和 `get_stock_news()` 方法
   - 这会导致 `AttributeError: 'UnifiedNewsSource' object has no attribute 'fetch_market_news'`

2. **日期过滤过严**：
   - `get_market_news()` 默认 `only_today=True`
   - 这会导致只获取当天的新闻
   - 如果当天新闻少，就会获取不到多少新闻

3. **缺少日志记录**：
   - 没有详细的日志记录，难以调试问题
   - 无法知道获取了多少新闻、保存了多少新闻

4. **错误处理不完善**：
   - 没有区分重复新闻和失败新闻
   - 错误信息不够详细

## 修复内容

### 1. 修正方法调用 ✅

**修改前**：
```python
news_list = news_source.fetch_market_news(limit=50)
news_list = news_source.fetch_stock_news(symbol, limit=50)
news_list = news_source.fetch_all_news(limit=100)
```

**修改后**：
```python
news_list = news_source.get_market_news(limit=100, only_today=False)
news_list = news_source.get_stock_news(symbol, limit=100, only_today=False)
# 对于 'all' 类型，使用 get_market_news 获取更多新闻
market_news = news_source.get_market_news(limit=200, only_today=False)
```

### 2. 放宽日期限制 ✅

**修改前**：
- 默认 `only_today=True`，只获取当天新闻

**修改后**：
- 所有调用都使用 `only_today=False`，获取更多新闻
- 这样可以获取最近几天的新闻，增加新闻数量

### 3. 增加日志记录 ✅

**新增日志**：
- 任务开始时的日志：`开始执行新闻抓取任务，类型: {task_type}`
- 获取新闻后的日志：`获取到 {len(news_list)} 条市场新闻`
- 保存完成后的日志：`新闻抓取完成: 成功 {success_count}, 重复 {duplicate_count}, 失败 {fail_count}`

### 4. 改进错误处理 ✅

**新增**：
- 区分重复新闻和失败新闻
- 使用 `save_news_article()` 方法（而不是 `save_news()`）
- 检查返回的 `news_id` 来判断是否成功
- 如果 `news_id` 为 `None`，检查是否是重复新闻

**错误处理增强**：
- 添加 `AttributeError` 异常捕获
- 添加详细的错误堆栈跟踪
- 返回更详细的错误信息

### 5. 增加统计信息 ✅

**新增统计**：
- `duplicate_count`：重复新闻数量
- 在返回结果中包含重复新闻统计

## 注意事项

1. **新闻数量**：
   - 虽然设置了 `only_today=False`，但实际获取的新闻数量仍然取决于：
     - 各个新闻源的可用性
     - 网络连接状况
     - API限制

2. **重复新闻**：
   - 系统会自动检测重复新闻（基于标题+来源，以及SimHash）
   - 重复新闻不会保存，但会统计在 `duplicate_count` 中

3. **新闻源可用性**：
   - 如果某些新闻源不可用，会记录警告日志
   - 但不会影响其他新闻源的获取
