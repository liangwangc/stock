# 板块爆发因子设计与数据库可行性分析

**日期**：2026-02-10  
**目的**：在不修改现有数据库结构的前提下，设计一套“板块爆发行程因子”，用于在预测时动态提升/降低相关股票的权重。

---

## 一、业务需求与现象描述

- **现象**：实际盘面中，经常出现某个行业/概念板块内，大量股票连续涨停或大幅上涨，该板块整体资金、情绪、新闻都非常强，处于“爆发期”。
- **直觉**：
  - 在板块爆发期，属于该板块的股票 **整体上涨概率更高**，应在预测中给更高权重；
  - 但爆发不会无限持续，往往经历：启动 → 爆发 → 见顶回落；接近尾声时，风险反而放大。

**目标**：  
设计一个板块级别的动态因子，用于：

1. 识别板块是否处在“爆发期”以及处于爆发的哪个阶段；
2. 在预测单只股票时，根据其所属板块的阶段，动态调整该股票的因子权重或加成；
3. 在爆发后期给出风险提示，避免追高被套。

---

## 二、现有数据能力梳理（无需改表）

### 2.1 涨停与行业/板块映射

- `stock_history_data`（见 `stock_history_README.md`）：
  - 含：`symbol`、`trade_date`、价格、涨跌幅、**是否涨停/跌停** 等字段。
  - 可用于统计：**每日、每个板块内的涨停股数量与占比**。
- `stock_predictions` / 相关扩展表（见 `init_database.sql` / `add_stock_info_fields.sql`）：
  - 字段：
    - `industry`：所属行业
    - `concepts`：概念板块（JSON 数组）
    - `main_concept`：主要概念板块
    - `sector`（部分表中，如 `add_sector_field.sql`）：所属板块
  - 可将单只股票映射到 **行业 / 概念 / 板块**。

### 2.2 板块级行情与热度

- `sector_rotation`（见 `init_database.sql` 第 103 行起）：
  - 字段：
    - `sector_name`：板块名称
    - `sector_type`：`industry` / `concept`
    - `change_pct`：板块涨跌幅
    - `capital_flow`：板块资金净流入
    - `heat`：热度（0–1）
    - `is_hot`：是否热门板块
  - 是 **按日期、按板块** 的时间序列表，可直接用于计算“板块热度/爆发度”。

### 2.3 新闻与板块/行业关联

- `news_articles`（见 `database/news_table.sql`）：
  - 与板块/行业的关联字段：
    - `sector`：关联板块
    - `industry`：关联行业
    - `concept`：关联概念
  - 情感字段：
    - `sentiment`、`sentiment_score`、`sentiment_confidence`
    - `is_positive`、`is_negative`、`is_policy`
    - `relevance_type`：`direct` / `industry` / `market`
  - 可用于统计 **某行业/板块在最近 N 日的利好/利空和政策新闻强度**。

- `news_sentiment`（见 `init_database.sql` 第 150 行起）：
  - 按日期 & 股票/整体的情感聚合，可作为更粗粒度的情绪参考。

### 2.4 因子与权重存储

- `prediction_factors`（见 `init_database.sql` 第 186 行起）：
  - 存储各因子每日得分、权重、趋势等（技术、新闻、资金、市场、历史等）。
  - 是落地新因子的合适位置（新增一列或复用已有板块相关字段）。

- `model_performance` / `parameter_optimization_history` / `model_learning_tasks`（见 `model_learning_tables.sql`）：
  - 可用于评估引入新因子后的收益、回撤、夏普等表现变化。

**结论**：  
要实现“板块爆发行程因子”，**现有数据表已经基本满足需求**，尤其是：

- 每日个股级别的涨停、行业/概念归属；
- 每日板块级别的涨跌幅、资金、热度；
- 每日板块级别的新闻与情绪。

## 三、板块爆发行程因子设计

### 3.1 日度板块爆发度 `sector_boom_score`

对每个交易日、每个板块（行业/概念），计算一个 0–1 的爆发度评分：

1. **涨停强度**：
   - `limit_up_count`：当天该板块内涨停股数量；
   - `limit_up_ratio = limit_up_count / 总股数`；
2. **板块行情**（来自 `sector_rotation`）：
   - `change_pct`：当日涨跌幅；
   - `capital_flow`：资金净流入；
   - `heat`、`is_hot`：已有热度标签。
3. **简单示例（仅示意）**：
   \[
   \text{boom\_score} = w_1 \cdot f(\text{limit\_up\_ratio}) + w_2 \cdot g(\text{change\_pct}) + w_3 \cdot h(\text{capital\_flow}) + w_4 \cdot \text{heat}
   \]
   - 各分量映射到 0–1 后加权求和。

### 3.2 爆发行程阶段划分

基于某板块的时间序列 `boom_score(date)`，识别其处于：

- **启动期**：最近连续几天 `boom_score` 上升并突破阈值（例如 0.6），但持续时间较短（低于历史 P25）。
- **爆发期**：`boom_score` 持续高位（例如 ≥0.7）一段时间（介于历史 P25–P75）。
- **衰退/过热期**：持续高位时间明显超过历史常态（>P75 或远超均值），或 `boom_score` 明显下行。

可以对每个板块统计历史上所有爆发段的：

- 持续时间分布（均值、中位数、P25、P75）；
- 爆发后期平均回撤情况；

再根据当前所在天数，给出“处在爆发早期/中后期/尾声”的标签。

### 3.3 与新闻情绪结合

为避免仅凭涨停形成“假爆发”，需要叠加新闻维度：

- 统计最近 N 天 `news_articles` 中该板块/行业相关的：
  - `news_count`、`is_policy` 的占比；
  - `sentiment_score` 平均值、`is_positive`/`is_negative` 数量；
  - 相关性为 `industry` / `market` 的新闻强度。

形成一个 `sector_news_score`（0–1），与 `boom_score` 综合：

\[
\text{final\_sector\_boom} = \alpha \cdot \text{boom\_score} + (1-\alpha) \cdot \text{sector\_news\_score}
\]

最终得到：

- `final_sector_boom`：当前爆发强度；
- `phase`：`startup` / `boom` / `late_boom` / `cooldown`。

## 四、在预测中的使用方式（设计层面）

> 以下为逻辑设计，暂不涉及具体代码实现。

### 4.1 对单只股票的影响

对于一只股票，已知：

- `industry`、`concepts`、`main_concept` / `sector`；
- 通过板块映射拿到对应板块的：
  - `final_sector_boom`；
  - `phase`。

设计两种使用方式：

1. **作为独立因子**：
   - 在 `prediction_factors` 中增加一个 `sector_boom_score` 字段；
   - 在预测得分中，给该因子一个权重（例如属于“板块因子”一部分）。
2. **作为权重乘子**（推荐，改动小）：
   - 对现有的 **新闻因子 / 资金流向 / 市场情绪** 等，与板块高度相关的因子，按板块爆发阶段动态放大/缩小：
     - 启动期：`multiplier ≈ 1.1`；
     - 爆发期：`multiplier ≈ 1.2`；
     - 过热期：`multiplier ≈ 0.9` 或以下；
     - 冷却期：`multiplier ≈ 0.8`。

### 4.2 爆发尾声的风险提示

在 UI 或交易建议中，可以基于 `phase` 给出简单文案：

- **startup / boom**：板块处于上升阶段，相关个股具备板块助推作用；
- **late_boom**：板块已连续高位运行，多数历史样本此后出现明显回调，注意控制仓位；
- **cooldown**：板块热度和资金均在回落，尽量避免追高。

这些提示可用于：

- 预测详情页；
- 交易建议弹窗；
- 设置页的模型学习报告中。

## 五、数据库可行性结论

1. **无需修改现有表结构** 即可完成第一版实现：
   - 涨停统计：`stock_history_data`；
   - 行业/板块归属：`stock_predictions` / 股票基础信息表中的 `industry` / `concepts` / `sector` 字段；
   - 板块级行情：`sector_rotation`；
   - 板块级新闻与情绪：`news_articles`（`sector`/`industry`/`concept` + 情感字段）。
2. **性能优化（可选未来步骤）**：
   - 若后续计算压力较大，可考虑新增一张如 `sector_boom_state` 的汇总表，按日写入每个板块的：
     - `final_sector_boom`、`phase`、`limit_up_count`、`limit_up_ratio` 等；
   - 但这属于缓存/性能优化层，而非功能必需。

综上，现有数据库已经具备实现“根据涨停集中度 + 行业/板块 + 新闻，识别并利用板块爆发行程”的所有关键字段与表结构，可以在不改库的前提下，先通过脚本和新因子逻辑逐步验证效果，再决定是否落地成持久化汇总表和前端展示。
