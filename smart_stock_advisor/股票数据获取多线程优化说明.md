# 股票数据获取多线程优化说明

## 一、优化概述

将股票数据获取定时任务改为多线程模式，大幅提升数据收集效率。参考历史数据获取脚本 `batch_collect_10years_data.py` 的实现方式。

## 二、优化参数

### 默认参数值
- `batch_size`: 1000（每批处理的股票数量）
- `delay`: 1.0（批次之间的延迟，秒）
- `threads`: 10（最大线程数）

### 参数说明
- **batch_size**: 将股票列表分批处理，每批内部使用多线程并行处理
- **delay**: 批次之间的延迟时间，避免API速率限制
- **threads**: 每个批次内部使用的线程数，控制并发度

## 三、实现方式

### 1. 中国股票数据获取（`_execute_cn_stock_data_collection`）

**多线程工作函数**：`_collect_single_cn_stock_worker`
- 每个线程创建独立的收集器实例
- 支持增量更新和全量收集两种模式
- 自动处理异常和错误

**执行流程**：
1. 从任务配置读取多线程参数（`batch_size`, `delay`, `threads`）
2. 获取股票列表（增量更新从数据库获取，全量收集获取所有股票）
3. 如果线程数 <= 1，使用单线程模式（兼容旧代码）
4. 如果线程数 > 1，使用多线程模式：
   - 将股票列表分批处理
   - 每批内部使用 `ThreadPoolExecutor` 并行处理
   - 批次之间添加延迟
   - 实时统计成功/失败/跳过数量

### 2. 美国股票数据获取（`_execute_us_stock_data_collection`）

**多线程工作函数**：`_collect_single_us_stock_worker`
- 每个线程创建独立的收集器实例
- 支持增量更新和全量收集两种模式
- 自动处理异常和错误

**特殊处理**：
- 美股API速率限制较严格，自动限制最大线程数为2
- 如果配置的线程数 > 2，会自动降低到2并记录警告

**执行流程**：
1. 从任务配置读取多线程参数（`batch_size`, `delay`, `threads`）
2. 限制线程数（美股最多2个线程）
3. 获取股票列表（根据 `index_type` 或 `symbols` 配置）
4. 如果线程数 <= 1，使用单线程模式（兼容旧代码）
5. 如果线程数 > 1，使用多线程模式（同中国股票）

## 四、任务配置示例

### 创建多线程数据获取任务

在设置页面创建任务时，在"任务配置"JSON中添加以下参数：

```json
{
  "collection_type": "incremental",
  "batch_size": 1000,
  "delay": 1.0,
  "threads": 10
}
```

### 配置说明

**增量更新任务**（中国股票）：
```json
{
  "collection_type": "incremental",
  "batch_size": 1000,
  "delay": 1.0,
  "threads": 10
}
```

**全量收集任务**（中国股票）：
```json
{
  "collection_type": "full",
  "years": 10,
  "batch_size": 1000,
  "delay": 1.0,
  "threads": 10
}
```

**增量更新任务**（美国股票）：
```json
{
  "collection_type": "incremental",
  "symbols": ["AAPL", "MSFT", "GOOGL"],
  "batch_size": 1000,
  "delay": 1.0,
  "threads": 2
}
```

**全量收集任务**（美国股票，S&P 500）：
```json
{
  "collection_type": "full",
  "index_type": "sp500",
  "period": "10y",
  "batch_size": 1000,
  "delay": 1.0,
  "threads": 2
}
```

## 五、性能提升

### 单线程模式 vs 多线程模式

**单线程模式**（`threads = 1`）：
- 逐个处理股票，速度较慢
- 适合API速率限制严格的情况
- 兼容旧代码，无需修改配置

**多线程模式**（`threads = 10`）：
- 并行处理多只股票，速度提升约5-10倍
- 适合网络条件良好、API限制较宽松的情况
- 需要合理设置 `batch_size` 和 `delay` 参数

### 推荐配置

**保守配置**（API限制较严格）：
```json
{
  "batch_size": 500,
  "delay": 2.0,
  "threads": 5
}
```

**平衡配置**（一般情况）：
```json
{
  "batch_size": 1000,
  "delay": 1.0,
  "threads": 10
}
```

**激进配置**（网络条件良好）：
```json
{
  "batch_size": 2000,
  "delay": 0.5,
  "threads": 20
}
```

## 六、兼容性

### 向后兼容
- 如果任务配置中没有 `batch_size`, `delay`, `threads` 参数，使用默认值
- 如果 `threads <= 1`，自动使用单线程模式（兼容旧代码）
- 不影响现有的单线程任务

### 自动降级
- 美股自动限制最大线程数为2（避免API速率限制）
- 如果配置的线程数超过限制，会自动降低并记录警告

## 七、日志输出

多线程模式下会输出详细的进度信息：
- 批次进度：`批次 1/10: 处理 1000 只股票（使用10个线程）`
- 批次完成：`批次 1 完成: 成功 950, 失败 50, 跳过 0, 耗时 120.5秒`
- 总体统计：`收集完成: 成功 9500, 失败 500, 跳过 0, 总耗时 1200.0秒`
