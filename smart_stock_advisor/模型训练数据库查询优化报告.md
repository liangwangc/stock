## 二、SQL查询分析

### 2.1 模型训练数据加载查询

**查询1：指定股票列表**
```sql
SELECT symbol, trade_date, close_price, ...
FROM stock_history_data
WHERE period_type = 'daily'
  AND trade_date >= %s
  AND trade_date <= %s
  AND symbol IN (%s, %s, ...)
ORDER BY symbol, trade_date
```

**索引使用分析**：
- ✅ `WHERE period_type = 'daily'` → 可以使用 `idx_period_type` 索引
- ✅ `AND symbol IN (...)` → 可以使用 `idx_symbol_date` 或 `uk_symbol_date_period` 索引的前缀
- ✅ `AND trade_date >= ? AND trade_date <= ?` → 可以使用 `idx_symbol_date` 索引
- ✅ `ORDER BY symbol, trade_date` → 可以使用 `idx_symbol_date` 索引（完全匹配）

**MySQL优化器选择**：
- 最优索引：`idx_symbol_date` (`symbol`, `trade_date`)
- 原因：完全匹配 WHERE 和 ORDER BY 条件

## 三、索引优化建议

### 3.1 当前索引状态

根据 `数据库索引重复分析与优化建议.md`，存在以下重复索引：

| 索引名称 | 字段 | 状态 | 建议 |
|---------|------|------|------|
| `uk_symbol_date_period` | `symbol`, `trade_date`, `period_type` | ✅ 必须保留 | 唯一索引 |
| `idx_symbol` | `symbol` | ⚠️ 可能冗余 | 可以删除（被复合索引前缀覆盖） |
| `idx_trade_date` | `trade_date` | ✅ 需要保留 | 单列查询需要 |
| `idx_symbol_date` | `symbol`, `trade_date` | ✅ 需要保留 | 最常见的查询模式 |
| `idx_date_range` | `trade_date`, `symbol` | ⚠️ 可能冗余 | 可以删除（与 idx_symbol_date 重复） |
| `idx_period_type` | `period_type` | ✅ 需要保留 | 单列查询需要 |

### 3.2 优化建议

**建议1：删除重复索引**

根据 `database/remove_duplicate_indexes.sql`，可以删除以下索引：
- `idx_symbol` - 被复合索引前缀覆盖
- `idx_date_range` - 与 `idx_symbol_date` 重复

**优化SQL**：
```sql
-- 删除重复索引（提升写入性能，减少锁竞争）
ALTER TABLE `stock_history_data` DROP INDEX IF EXISTS `idx_symbol`;
ALTER TABLE `stock_history_data` DROP INDEX IF EXISTS `idx_date_range`;
```

**影响**：
- ✅ **提升写入性能**：减少索引维护开销
- ✅ **减少锁竞争**：减少索引更新时的锁竞争
- ⚠️ **查询性能**：影响很小（可以使用其他索引）

### 4.1 当前查询性能

**查询特点**：

- ✅ WHERE 条件顺序合理（period_type → trade_date → symbol）
- ✅ ORDER BY 与索引匹配

**性能评估**：

- ✅ **查询效率**：对于大量数据（几年数据），查询时间应该在可接受范围内

### 4.2 进一步优化建议

**建议1：添加覆盖索引（如果查询字段固定）**

如果查询字段固定，可以创建覆盖索引：
```sql
-- 覆盖索引：包含所有查询字段，避免回表
ALTER TABLE `stock_history_data` 
ADD INDEX `idx_ml_training_cover` (
    `period_type`, `trade_date`, `symbol`,
    `close_price`, `open_price`, `high_price`, `low_price`,
    `pre_close`, `change_pct`, `change_amount`, `volume`, `amount`,
    `turnover_rate`, `volume_ratio`, `ma5`, `ma10`, `ma20`, `ma60`,
    `rsi`, `macd`, `macd_signal`, `macd_hist`, `x2`,
    `main_net_inflow`, `super_large_inflow`, `large_inflow`, `medium_inflow`, `small_inflow`,
    `pe_ratio`, `pb_ratio`, `total_market_cap`, `float_market_cap`,
    `margin_balance`, `short_balance`, `margin_ratio`
);
```

**注意**：覆盖索引会占用大量空间，需要权衡。

**建议2：使用分区表（如果数据量非常大）**

如果数据量非常大（千万级别），可以考虑按日期分区：
```sql
-- 按年份分区（示例）
ALTER TABLE `stock_history_data` 
PARTITION BY RANGE (YEAR(trade_date)) (
    PARTITION p2014 VALUES LESS THAN (2015),
    PARTITION p2015 VALUES LESS THAN (2016),
    ...
);
```

**建议3：优化查询顺序**

当前查询顺序已经合理：
- `WHERE period_type = 'daily'` - 过滤大部分数据
- `AND trade_date >= ? AND trade_date <= ?` - 进一步过滤
- `AND symbol IN (...)` - 最后过滤（如果指定）
