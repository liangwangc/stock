## 测试目的

在开始大规模数据收集之前，先进行小规模测试，验证：
1. 脚本是否正常工作
2. 数据库连接是否正常
3. 数据源API是否可用
4. 数据存储是否正常

### 方法2：查询数据库

**A股数据**:
```sql
SELECT symbol, COUNT(*) as record_count, 
       MIN(trade_date) as first_date, 
       MAX(trade_date) as last_date
FROM stock_history_data
WHERE symbol IN ('000001', '000002', '600000')
  AND period_type = 'daily'
GROUP BY symbol;
```

**美股数据**:
```sql
SELECT symbol, COUNT(*) as record_count,
       MIN(trade_date) as first_date,
       MAX(trade_date) as last_date
FROM us_stock_history_data
WHERE symbol IN ('AAPL', 'MSFT', 'GOOGL')
  AND period_type = 'daily'
GROUP BY symbol;
```

**预期结果**：每只股票应该有约250-252条记录（1年的交易日数据）

## 测试通过标准

✅ **测试通过**的条件：
1. 脚本能够正常启动
2. 能够获取股票列表
3. 能够成功收集至少1只股票的数据
4. 数据能够正常保存到数据库
5. 数据库中能够查询到收集的数据

❌ **测试失败**的情况：
1. 脚本无法启动（Python错误、导入错误等）
2. 无法获取股票列表（API错误、网络错误等）
3. 无法收集数据（数据源错误、数据库错误等）
4. 数据无法保存到数据库（数据库连接错误、表不存在等）

## 常见测试问题

### 1. 导入错误
**错误**：`ModuleNotFoundError: No module named 'akshare'`
**解决**：安装缺失的依赖
```bash
pip install akshare yfinance pandas pymysql
```

### 2. 数据库连接错误
**错误**：`pymysql.err.OperationalError: (2003, "Can't connect to MySQL server")`
**解决**：
- 检查MySQL服务是否运行
- 检查`config_db.py`中的数据库配置
- 确保数据库表已创建

### 3. API限制错误
**错误**：`请求过于频繁`或`Rate limit exceeded`
**解决**：
- 增加延迟时间（`--delay 2.0`）
- 减小批次大小（`--batch-size 1`）
- 等待一段时间后重试

### 4. 数据源错误
**错误**：`获取股票列表失败`或`获取数据失败`
**解决**：
- 检查网络连接
- 检查数据源API是否可用
- 查看详细错误日志

## 测试完成后

如果测试通过：
1. ✅ 可以开始正式的大规模数据收集
2. ✅ 使用更大的批次大小（如50只）
3. ✅ 收集10年数据（`--years 10`）
4. ✅ 可以中断和恢复（使用`--resume`）

如果测试失败：
1. ❌ 检查错误信息
2. ❌ 修复相关问题
3. ❌ 重新测试
4. ❌ 确保所有依赖已安装
5. ❌ 确保数据库配置正确
