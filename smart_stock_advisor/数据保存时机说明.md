## 一、问题

## 二、答案

**不是马上存入数据库，而是先收集所有数据，然后批量保存**

## 三、详细流程

### 3.1 历史数据批量采集流程

**代码位置**：`utils/stock_history_collector.py` → `_collect_stock_history_batch()` 方法

**流程**：

```
1. 从API获取数据（57个字段）
   ↓
2. 处理所有日期的数据
   ↓
3. 收集到 batch_data 列表（内存中）
   ↓
4. 所有数据收集完成后
   ↓
5. 调用 save_stock_daily_data_batch() 批量保存
```

**关键代码**（第766-915行）：

```python
# 1. 批量处理数据（先收集，不立即保存）
batch_data = []
batch_size = 1000  # 每批保存1000条

for date_str in missing_dates:
    # 处理数据，构建数据字典
    data = {...}
    # 添加到列表（内存中，未保存）
    batch_data.append((date_str, data))

# 2. 收集完所有数据后，一次性批量保存
if batch_data:
    self.logger.info(f"开始批量保存 {len(batch_data)} 条数据...")
    save_result = self.storage.save_stock_daily_data_batch(
        batch_save_data, 
        batch_size=1000,
        skip_existence_check=True
    )
```

### 3.2 增量更新今日数据流程

**代码位置**：`utils/stock_history_collector.py` → `incremental_update_today()` 方法

**流程**（多线程模式）：

```
1. 多线程并行采集数据
   ↓
2. 每个线程采集完成后，添加到 collected_data 列表（内存中）
   ↓
3. 所有线程完成后
   ↓
4. 调用 save_stock_daily_data_batch() 批量保存
```

**关键代码**（第1088-1156行）：

```python
# 1. 多线程采集数据（先收集，不立即保存）
collected_data = []  # 收集到的数据，用于批量保存
data_lock = Lock()

def process_symbol(symbol: str):
    # 采集今日数据
    data = self.collect_stock_daily_data(symbol, today)
    if data:
        # 添加到批量保存列表（内存中，未保存）
        with data_lock:
            collected_data.append((symbol, today, data))

# 2. 所有数据采集完成后，批量保存
if collected_data:
    self.logger.info(f"开始批量保存 {len(collected_data)} 条数据...")
    save_result = self.storage.save_stock_daily_data_batch(
        collected_data, 
        batch_size=batch_size,
        skip_existence_check=True
    )
```

## 四、批量保存的优势

### 4.1 性能优势

**批量保存 vs 逐条保存**：

| 方式 | 数据库操作次数 | 性能 |
|-----|-------------|------|
| **逐条保存** | N次（每一条一次） | 慢 |
| **批量保存** | N/1000次（每1000条一次） | **快3-5倍** |

**示例**（5000条数据）：
- 逐条保存：5000次数据库操作
- 批量保存：5次数据库操作（每批1000条）

### 4.2 优化策略

**批量保存的优化点**：

1. **减少SQL构建次数**：从N次减少到N/1000次
2. **减少数据库连接开销**：减少连接次数
3. **使用批量INSERT**：`executemany()` 方法，性能更好
4. **分离INSERT和UPDATE**：避免唯一索引锁竞争

## 五、保存时机总结

### 5.1 历史数据采集

**时机**：
- ✅ **先收集**：处理完所有日期的数据后，收集到 `batch_data` 列表
- ✅ **后保存**：所有数据收集完成后，一次性批量保存

**批次大小**：1000条/批

### 5.2 增量更新今日数据

**时机**：
- ✅ **先收集**：多线程采集所有股票数据，收集到 `collected_data` 列表
- ✅ **后保存**：所有线程完成后，一次性批量保存

**批次大小**：100条/批（可配置）

### 5.3 单线程模式（兼容旧代码）

**时机**：
- ⚠️ **逐条保存**：每采集一条数据，立即保存（性能较慢）

**代码位置**：`_incremental_update_today_single_thread()` 方法

## 六、数据在内存中的状态

### 6.1 数据收集阶段

**状态**：数据在内存中（`batch_data` 或 `collected_data` 列表）

**特点**：
- ✅ 速度快（内存操作）
- ✅ 不占用数据库资源
- ⚠️ 如果程序中断，未保存的数据会丢失

### 6.2 批量保存阶段

**状态**：数据从内存批量写入数据库

**特点**：
- ✅ 性能高（批量操作）
- ✅ 事务安全（批量提交）
- ✅ 减少数据库压力

## 八、总结

4. **保存方式**：使用 `save_stock_daily_data_batch()` 批量保存（每批1000条或100条）

**关键点**：
- ❌ **不是**：处理完一条就保存一条
- ✅ **而是**：收集完所有数据后，批量保存
- ✅ **优势**：性能提升3-5倍
