# 进度条"总量57"说明

**创建日期**：2026-01-15

---

## 一、问题说明

在运行股票数据获取时，进度条显示"总量57"，这一步是在做什么？

---

## 二、答案

**进度条显示的"总量57"是指：akshare API返回的字段数量**

### 2.1 具体含义

当系统从 akshare API 获取股票数据时，API 会返回包含 **57个字段** 的数据。这个进度条显示的是：

- **正在处理的数据字段数量**
- **总字段数：57个**（akshare API返回的完整字段数）

### 2.2 这一步在做什么

**步骤**：**从 akshare API 获取股票K线数据**

**位置**：`utils/stock_history_collector.py` → `collect_stock_history_data()` 方法

**具体操作**：
1. 调用 `data_source.get_stock_data()` 获取股票K线数据
2. akshare API 返回包含57个字段的数据
3. 系统处理这57个字段，提取需要的数据
4. 实际保存到数据库的字段：**41个**（已注释掉16个历史数据不可用的字段）

---

## 三、字段说明

### 3.1 API返回的57个字段

akshare API 返回的股票数据包含以下字段（共57个）：

**基础价格数据**（7个）：
- `date` - 日期
- `open` - 开盘价
- `close` - 收盘价
- `high` - 最高价
- `low` - 最低价
- `volume` - 成交量
- `amount` - 成交额

**其他字段**（50个）：
- 包括各种技术指标、资金流向、买卖盘数据等

### 3.2 实际保存的41个字段

系统会从57个字段中筛选出**41个有效字段**保存到数据库，已注释掉16个历史数据不可用的字段：

**已注释的16个字段**：
1. `turnover_rate` - 换手率（1个）
2. `outer_volume` / `inner_volume` / `bid_ask_ratio` - 外盘/内盘/委比（3个）
3. `bid_levels` / `ask_levels` / `bid_total_volume` / `ask_total_volume` - 买卖盘数据（4个）
4. `cost_distribution_intraday` - 当日成本分布（1个）
5. `total_market_cap` / `float_market_cap` - 总市值/流通市值（2个）
6. `main_net_inflow` / `super_large_inflow` / `large_inflow` / `medium_inflow` / `small_inflow` - 资金流向（5个）

**实际保存的41个字段**：
- 基础价格数据（开盘、收盘、最高、最低、昨收等）
- 涨跌幅、成交量、成交额
- 技术指标（MA5/10/20/60、RSI、MACD等）
- 估值指标（PE、PB）
- 涨跌停价、振幅
- 融资融券数据
- 成本分布（历史）
- 元数据（数据源、质量评分等）

## 五、为什么显示57而不是41？

### 5.1 原因

进度条显示的是 **akshare API 返回的原始字段数量（57个）**，而不是实际保存到数据库的字段数量（41个）。

### 5.2 说明

- **API返回**：57个字段（包含所有可用数据）
- **系统处理**：从57个字段中提取有效数据
- **数据库保存**：41个字段（过滤掉16个历史数据不可用的字段）

### 5.3 日志输出

系统会在日志中明确说明：
```
{symbol} 批量保存完成: {success_count}/{len(missing_dates)} 条记录（实际保存41个字段，进度条显示的57个字段是API返回的字段数量）
```

2. **57个字段**：API返回的完整字段数量
3. **实际保存**：41个字段（已过滤掉16个历史数据不可用的字段）
4. **这一步的作用**：获取并处理股票的基础价格数据、技术指标等

**这是正常现象**，系统会正确处理数据并保存到数据库。
