# 历史记录逻辑说明

## 核心逻辑

### 1. 预测数据保存逻辑

#### 唯一标识
- **使用 `symbol + target_date` 作为唯一标识**，而不是 `symbol + prediction_date`
- 这样可以确保：
  - 当天预测明天：`prediction_date = 今天`，`target_date = 明天`
  - 明天预测后天：`prediction_date = 明天`，`target_date = 后天`
  - 不会因为同一天多次预测而覆盖之前的数据

#### 保存时机
- 每次调用 `save_stock_record()` 保存新预测时：
  1. 检查是否存在相同 `symbol + target_date` 的记录
  2. 如果存在，更新预测数据（但保留已有的实际数据字段）
  3. 如果不存在，添加新记录
  4. **自动调用 `_update_historical_actual_data()` 更新所有历史记录的实际数据**

### 2. 实际数据更新逻辑

#### 更新时机
- **每次保存新预测时自动触发**（在 `save_stock_record()` 中调用）
- **查看历史页面时也会更新**（在 `create_stock_history_page()` 中）
- 双重保障确保实际数据及时更新

#### 更新条件
- 目标日期（`target_date`）已过去（`target_date < today`）
- 该记录还没有实际数据（`actual_price` 为空）

#### 更新内容
1. **实际价格** (`actual_price`)：目标日期的收盘价
2. **实际涨跌幅** (`actual_change_pct`)：相对于预测时价格的涨跌幅
3. **实际方向** (`actual_direction`)：上涨/下跌/平盘
4. **预测命中** (`prediction_hit`)：命中/未命中/未知

### 3. 预测命中判断逻辑

#### 判断规则（精确版本）
```python
# 1. 预测上涨 + 实际上涨（涨跌幅>0） = 命中
if prediction == '上涨' and actual_direction == '上涨' and actual_change_pct > 0:
    prediction_hit = '命中'

# 2. 预测下跌 + 实际下跌（涨跌幅<0） = 命中
elif prediction == '下跌' and actual_direction == '下跌' and actual_change_pct < 0:
    prediction_hit = '命中'

# 3. 预测震荡 + 实际平盘（-0.5% < 涨跌幅 < 0.5%） = 命中
elif prediction == '震荡' and -0.5 <= actual_change_pct <= 0.5:
    prediction_hit = '命中'

# 4. 其他情况 = 未命中
else:
    prediction_hit = '未命中'
```

#### 判断说明
- **上涨预测**：需要实际涨跌幅 > 0 才算命中
- **下跌预测**：需要实际涨跌幅 < 0 才算命中
- **震荡预测**：实际涨跌幅在 -0.5% 到 0.5% 之间算命中
- **未知状态**：如果无法获取实际方向，标记为"未知"

## 数据流程示例

### 场景1：连续两天预测同一只股票

#### 第一天（2026-01-07）
```
预测操作：
- prediction_date = 2026-01-07（预测日期）
- target_date = 2026-01-08（目标日期，明天）
- 保存记录：symbol=600362, prediction_date=2026-01-07, target_date=2026-01-08

结果：
- CSV中新增一条记录
- actual_price = ''（空，因为目标日期还没到）
- prediction_hit = ''（空）
```

#### 第二天（2026-01-08）
```
预测操作：
1. 预测新的目标日期
   - prediction_date = 2026-01-08（预测日期）
   - target_date = 2026-01-09（目标日期，明天）
   - 保存新记录：symbol=600362, prediction_date=2026-01-08, target_date=2026-01-09

2. 自动更新历史记录
   - 检查所有历史记录
   - 发现 target_date=2026-01-08 的记录（昨天的预测）
   - 获取 2026-01-08 的实际收盘价
   - 计算实际涨跌幅和方向
   - 判断预测是否命中
   - 更新该记录的实际数据字段

结果：
- CSV中有两条记录：
  1. symbol=600362, prediction_date=2026-01-07, target_date=2026-01-08
     - actual_price = 10.50（已更新）
     - actual_change_pct = 2.5%（已更新）
     - actual_direction = '上涨'（已更新）
     - prediction_hit = '命中' 或 '未命中'（已更新）
  
  2. symbol=600362, prediction_date=2026-01-08, target_date=2026-01-09
     - actual_price = ''（空，因为目标日期还没到）
     - prediction_hit = ''（空）
```

### 场景2：同一天多次预测同一只股票

如果同一天多次预测同一只股票的同一个目标日期，会**更新**而不是新增记录：

```
第一次预测（9:00）：
- prediction_date = 2026-01-07
- target_date = 2026-01-08
- 保存记录A

第二次预测（14:00）：
- prediction_date = 2026-01-07
- target_date = 2026-01-08
- 检查：已存在 symbol=600362 + target_date=2026-01-08 的记录
- 更新记录A的预测数据（保留实际数据字段）
- 不会新增记录
```

## 注意事项

1. **时区问题**：使用本地时间判断日期，确保与实际交易日一致
2. **交易日判断**：如果目标日期是周末或节假日，可能无法获取实际数据
3. **数据延迟**：实际收盘价可能在交易日结束后一段时间才能获取
4. **错误处理**：如果获取实际数据失败，不会影响新预测的保存
5. **数据保留**：更新记录时会保留已有的实际数据，避免覆盖

## 优化建议

1. **批量更新**：可以考虑在非预测时间批量更新所有历史记录
2. **缓存机制**：可以缓存已获取的实际数据，避免重复请求
3. **异步更新**：实际数据更新可以异步进行，不阻塞预测流程
4. **数据校验**：添加数据校验逻辑，确保实际数据的合理性
