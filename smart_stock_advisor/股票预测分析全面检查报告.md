### ⚠️ 2. 数据库存储 (`utils/db_storage.py`) **需要优化**

#### 2.1 `save_prediction_factors` 方法（第321-348行）

**问题**：
- ❌ SQL插入语句仍然包含三个已移除因子的字段
- ❌ 参数仍然包含三个已移除因子的值

**当前代码**：
```python
sql = """
    INSERT INTO prediction_factors 
    (timestamp, date, symbol, technical_score, technical_weight, technical_trend,
     news_score, news_weight, news_sentiment,
     capital_flow_score, capital_flow_weight, capital_flow_trend,
     market_score, market_weight, market_trend,
     sector_rotation_score, sector_rotation_weight, sector_rotation_trend,  # ← 已移除
     history_score, history_weight, history_pattern,
     valuation_score, valuation_weight, pe_ratio, pb_ratio,  # ← 已移除
     us_sector_score, us_sector_weight, us_sector_name,  # ← 已移除
     final_score, up_probability, down_probability, confidence)
    VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
"""
params = (
    ...
    sector_rotation.get('score'), sector_rotation.get('weight'), sector_rotation.get('trend'),  # ← 已移除
    ...
    valuation.get('score'), valuation.get('weight'), valuation.get('pe_ratio'), valuation.get('pb_ratio'),  # ← 已移除
    us_sector.get('score'), us_sector.get('weight'), us_sector.get('sector'),  # ← 已移除
    ...
)
```

**建议修改**：
- 方案1（推荐）：保留SQL字段，但参数设置为NULL或0
  - 优点：向后兼容，不破坏数据库结构
  - 缺点：仍然保存无用的数据
- 方案2：修改SQL，移除三个字段
  - 优点：不保存无用数据
  - 缺点：需要数据库迁移，可能影响历史数据

**推荐方案1**，因为：
- 数据库表结构保留这些字段是为了向后兼容
- 设置为NULL或0不会影响功能
- 不需要数据库迁移
