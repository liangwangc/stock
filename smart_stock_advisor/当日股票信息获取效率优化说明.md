# 当日股票信息获取效率优化说明

## 一、优化概述

参考 `batch_collect_10years_data.py` 的实现方式，优化当日股票信息获取的效率，主要优化点包括：
1. **批量查询已存在的数据**：减少数据库查询次数
2. **多线程并行处理**：提升数据采集速度
3. **优化延迟策略**：多线程模式下减少延迟
4. **批量过滤**：提前过滤已存在的股票，减少不必要的API调用

## 二、优化前的问题

### 1. 单线程模式（`incremental_update_today`）
- **问题**：逐个处理股票，速度慢
- **延迟**：每只股票采集后 sleep(0.5) 秒
- **数据库查询**：每只股票都要单独查询数据库检查数据是否存在

### 2. 多线程模式（优化前）
- **问题**：每个线程都要单独查询数据库检查数据是否存在
- **延迟**：没有根据线程数优化延迟策略
- **重复检查**：主函数和工作函数都检查数据是否存在

## 三、优化内容

### 1. 批量查询已存在的数据（`_execute_cn_stock_data_collection`）

**优化前**：
```python
# 每个线程都要单独查询
if collector.storage.check_data_exists(symbol, today):
    return {'skipped': True}
```

**优化后**：
```python
# 在主函数中批量查询所有已存在的股票
if collection_type == 'incremental':
    today = datetime.now().strftime('%Y-%m-%d')
    
    # 批量查询已存在的股票（分批查询，避免SQL过长）
    existing_symbols_set = set()
    query_batch_size = 1000
    
    for query_start in range(0, len(symbols), query_batch_size):
        query_end = min(query_start + query_batch_size, len(symbols))
        query_batch = symbols[query_start:query_end]
        
        # 构建IN条件查询
        placeholders = ','.join(['%s'] * len(query_batch))
        sql = f"""
            SELECT DISTINCT symbol 
            FROM stock_history_data 
            WHERE symbol IN ({placeholders}) 
              AND trade_date = %s 
              AND period_type = 'daily'
        """
        params = [str(s).zfill(6) for s in query_batch] + [today]
        results = collector.storage.db.execute_query(sql, tuple(params))
        
        for result in results:
            existing_symbols_set.add(str(result.get('symbol', '')).strip())
    
    # 过滤出需要处理的股票
    pending_symbols = [s for s in symbols if str(s).strip() not in existing_symbols_set]
    total_skipped = len(symbols) - len(pending_symbols)
```

**优化效果**：
- ✅ 从 N 次数据库查询减少到 `ceil(N/1000)` 次
- ✅ 提前过滤已存在的股票，减少不必要的API调用
- ✅ 工作函数中不再需要重复检查

### 2. 优化延迟策略（`_collect_single_cn_stock_worker`）

**优化前**：
```python
# 固定延迟
time.sleep(0.5)
```

**优化后**：
```python
# 多线程模式下减少延迟（参考batch_collect_10years_data.py）
import random
if max_workers > 1:
    # 多线程模式下减少延迟（批量模式已经优化了API调用）
    time.sleep(delay * random.uniform(0.1, 0.3))  # 0.1-0.3倍延迟
else:
    # 单线程模式保持原延迟
    time.sleep(delay * random.uniform(0.5, 1.0))  # 0.5-1.0倍延迟
```

**优化效果**：
- ✅ 多线程模式下延迟减少到原来的 0.1-0.3 倍
- ✅ 单线程模式保持原延迟，确保API速率限制
- ✅ 随机延迟避免请求过于规律

### 3. 优化批次间延迟（`_execute_cn_stock_data_collection`）

**优化前**：
```python
# 固定延迟
time.sleep(delay)
```

**优化后**：
```python
# 批次之间的延迟（多线程模式下可以减少延迟）
if batch_num + 1 < total_batches:
    # 多线程模式下减少延迟（参考batch_collect_10years_data.py）

```

**优化效果**：
- ✅ 多线程模式下批次间延迟减少到原来的 0.5 倍
- ✅ 单线程模式保持原延迟

### 4. 提前过滤已存在的股票

**优化效果**：
- ✅ 如果所有股票今日数据都已存在，直接返回，无需处理
- ✅ 减少不必要的线程创建和API调用

## 四、性能提升

### 优化前（单线程模式）
- **数据库查询次数**：N 次（每只股票1次）
- **延迟时间**：N × 0.5 秒
- **总耗时**：约 N × (API耗时 + 0.5秒)

### 优化后（多线程模式，10线程）
- **数据库查询次数**：`ceil(N/1000)` 次（批量查询）
- **延迟时间**：N × 0.1-0.3秒（多线程模式）
- **总耗时**：约 `N/10 × (API耗时 + 0.1-0.3秒)` + 批次间延迟

### 性能提升估算

假设处理 5000 只股票，其中 1000 只已存在：

**优化前（单线程）**：
- 数据库查询：5000 次
- 实际处理：5000 只（包括已存在的）
- 延迟：5000 × 0.5 = 2500 秒
- 总耗时：约 2500 + API耗时

**优化后（10线程，batch_size=1000）**：
- 数据库查询：5 次（批量查询）
- 实际处理：4000 只（已过滤已存在的）
- 延迟：4000 × 0.2（平均） = 800 秒
- 批次间延迟：4 × 0.5 = 2 秒
- 总耗时：约 (800 + API耗时) / 10 + 2 ≈ 80 + API耗时/10

**性能提升**：约 **10-30倍**（取决于API响应时间）
