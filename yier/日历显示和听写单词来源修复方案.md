# 日历显示和听写单词来源修复方案

## 📋 一、需求分析

### 1.1 日历显示需求

**用户要求：**
点击日历应该显示三种分类：
1. **头天**（昨天学习的单词）- 全量
2. **复习**（以前学的单词根据权重进行复习）- 40%的daily_goal
3. **新单词**（用户设置的数量）- 100%的daily_goal

**当前问题：**
- 显示的是"新词+复习"，分类不对
- 没有区分"头天"、"复习"、"新单词"

### 1.2 听写单词来源需求

**用户要求：**
- 家长听写和自动听写的单词都应该根据学习队列的数量来
- 学习队列 = 头天（昨天学习的单词）+ 复习（40%的daily_goal）+ 新单词（100%的daily_goal）

**当前问题：**
- 听写使用的是 `get_today_learned_words_for_dictation` API
- 这个API查询的是"今天学习过的单词"（今天添加的 + 今天复习过的）
- 应该使用 `prepare_study_queue` API 的队列

---

## 🔧 二、修复方案

### 2.1 修改日历显示逻辑

**方案：**
1. **如果点击的是今天**：调用 `prepare_study_queue` API，获取今天的学习队列
2. **如果点击的是其他日期**：显示那个日期的学习情况（添加的单词 + 复习过的单词）

**修改 `day_details` API：**
- 如果 `$date == $today`：调用 `prepare_study_queue` 的逻辑，返回三种分类
- 如果 `$date != $today`：查询指定日期的学习情况

### 2.2 修改听写单词来源

**方案：**
- 家长听写和自动听写都使用 `prepare_study_queue` API 的队列
- 队列 = 头天（昨天学习的单词）+ 复习（40%的daily_goal）+ 新单词（100%的daily_goal）

**修改：**
- `startSession`：使用 `prepare_study_queue` API
- `startDictation`：使用 `prepare_study_queue` API（而不是 `get_today_learned_words_for_dictation`）
