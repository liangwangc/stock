# 听写逻辑与复习权重分析报告

## 一、当前听写逻辑分析

### 1. 听写检查流程 (`checkDictation` 函数)

#### 写对的情况：
- **2次内写对** → `quality=5`（记住），自动跳转，记录到 `word_review_logs`
- **4次内写对** → `quality=3`（模糊），自动跳转，记录到 `word_review_logs`
- **超过4次写对** → `quality=3`（模糊），自动跳转，记录到 `word_review_logs`

#### 写错的情况：
- **5次以内写错**：
  - ❌ **只显示错误，不记录到数据库**
  - 清空输入框，让用户继续尝试
  - **问题**：这些错误尝试没有被记录，无法统计真实的错误次数

- **第5次以后写错**：
  - ✅ 显示正确答案
  - ✅ 自动调用 `rate(1, true)` 记录为"忘记"（`quality=1`）
  - ✅ 跳转到下一个单词
  - ✅ 记录到 `word_review_logs` 表

### 2. 数据记录情况

**当前记录时机**：
- ✅ 写对后：记录（根据尝试次数设置quality）
- ✅ 第5次后写错：记录（quality=1）
- ❌ **5次内的错误：不记录**

**问题**：
- 如果用户尝试了4次都错了，第5次写对，只记录1次"记住"，但实际上前面有4次错误
- 无法准确统计听写错误次数，影响复习优先级计算

## 二、复习权重系统分析

### 1. 权重计算函数 (`calculateReviewPriority`)

#### 听写模式权重（主要判断依据，权重高）：

| 项目 | 权重 | 说明 |
|------|------|------|
| 连续忘记次数 | **×20** | 最高权重 |
| 连续模糊次数 | **×12** | 较高权重 |
| 连续记住次数 | **×(-5)** | 降低优先级 |
| 总失败率 | **×15** | 失败率越高，优先级越高 |

#### 学习模式权重（辅助判断，权重低）：

| 项目 | 权重 | 说明 |
|------|------|------|
| 连续忘记次数 | **×5** | 权重较低（是听写的1/4） |
| 连续模糊次数 | **×3** | 权重最低（是听写的1/4） |
| 连续记住次数 | **×(-1)** | 降低优先级（影响较小） |

#### 其他因素：

| 因素 | 权重 | 说明 |
|------|------|------|
| 距离上次复习时间 | **×2** | 时间越长，优先级越高 |
| ef_factor越低 | **×3** | 越难的单词，优先级越高 |
| 只有学习记录，无听写记录 | **+8** | 需要听写验证 |

### 2. SQL查询中的优先级计算 (`prepare_study_queue`)

```sql
CASE 
    -- 优先级1：听写模式连续忘记2次以上（分数：1000+）
    WHEN 听写模式忘记次数 >= 2 THEN 1000 + review_priority
    
    -- 优先级2：听写模式有失败记录但少于2次（分数：500+）
    WHEN 听写模式失败次数 > 0 THEN 500 + review_priority
    
    -- 优先级3：没有听写记录，但学习模式表现差（分数：200+）
    WHEN 无听写记录 AND 学习模式忘记次数 >= 2 THEN 200 + review_priority
    
    -- 优先级4：正常复习（分数：review_priority）
    ELSE review_priority
END
```

**结论**：
- ✅ **听写错误的权重确实远高于学习模式**
- ✅ **听写模式连续忘记2次以上优先级最高（1000+）**
- ✅ **听写模式有失败记录优先级较高（500+）**
- ✅ **学习模式权重较低（200+）**

## 三、存在的问题

### 问题1：5次内的错误没有记录
**影响**：
- 无法准确统计听写错误次数
- 如果用户尝试4次都错了，第5次写对，只记录1次"记住"，但实际上有4次错误
- 影响复习优先级计算的准确性

**建议**：
- 每次错误尝试都应该记录到 `word_review_logs`
- 可以设置一个临时状态，在写对后统一提交，或者每次错误都记录

### 问题2：听写错误次数统计不完整
**当前逻辑**：
- 只有写对后或第5次后写错才会记录
- 5次内的错误不记录

**建议**：
- 每次错误尝试都应该记录（即使不跳转）
- 可以记录为 `quality=1`（忘记），`should_advance=0`（不跳转）

## 五、当前复习单词逻辑总结

### 1. 复习单词计算流程

1. **点击"开始学习"** → 调用 `prepare_study_queue` API
2. **计算复习单词**：
   - 查询 `next_review <= today` 的单词
   - 根据 `word_review_logs` 表计算优先级
   - 按优先级排序
3. **计算新单词**：
   - 优先手动录入的单词
   - 然后单词库导入的单词
4. **合并队列**：复习单词在前，新单词在后

### 2. 优先级计算规则

**听写模式（权重高）**：
- 连续忘记2次以上 → 优先级1000+
- 有失败记录 → 优先级500+
- 连续忘记次数 × 20
- 连续模糊次数 × 12

**学习模式（权重低）**：
- 连续忘记次数 × 5
- 连续模糊次数 × 3
- 只有学习记录，无听写记录 → 优先级+200

### 3. 数据记录流程

**学习模式**：
- 点击状态按钮 → `rate()` → `submit_review` API → 记录到 `word_review_logs`

**听写模式**：
- 写对后 → `checkDictation()` → `rate()` → `submit_review` API → 记录到 `word_review_logs`
- 第5次后写错 → `checkDictation()` → `rate(1, true)` → `submit_review` API → 记录到 `word_review_logs`
- **5次内写错 → 不记录** ❌

## 六、建议的优化方案

### 方案1：记录每次错误尝试（推荐）

修改 `checkDictation` 函数，在每次错误时都记录：

```javascript
} else {
    // 写错了
    // 记录这次错误尝试（即使5次内也记录）
    // quality=1（忘记），should_advance=false（不跳转，继续尝试）
    this.rate(1, false);
    
    if (this.dictationAttemptCount < 5) {
        // 5次以内：只告诉错了，不显示正确答案
        // ...
    } else {
        // 第5次以后：显示正确答案，跳转到下一个
        // ...
    }
}
```

**优点**：
- ✅ 准确记录所有错误尝试
- ✅ 复习优先级计算更准确
- ✅ 可以统计真实的错误率

**缺点**：
- ⚠️ 会产生更多数据库记录（但这是合理的）

### 方案2：保持当前逻辑，但优化权重计算

如果不想记录5次内的错误，可以：
- 在写对后，根据尝试次数调整quality值
- 例如：尝试5次才写对，即使quality=3，也应该提高优先级
