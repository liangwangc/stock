## 📋 一、逻辑问题检查

### 1.1 进度百分比计算不一致 ⚠️

**问题位置：** `api.php` - `get_home_data` API (第955行)

**当前逻辑：**
```php
$progress_percent = $daily_goal > 0 ? min(100, round(($today_learned_count / $daily_goal) * 100)) : 0;
```

**问题分析：**
- 进度百分比使用`daily_goal`作为分母
- 但实际总任务量是变化的：
  - 第1天：`daily_goal`
  - 第2天：`daily_goal * 2`
  - 第3天及以后：`daily_goal * 2.4`
- 这导致进度百分比计算不准确

**示例：**
- 第3天，用户学习了12个单词，`daily_goal=10`
- 当前计算：`(12/10)*100 = 120%`（被限制为100%）
- 实际总任务量：`10 * 2.4 = 24个`
- 应该计算：`(12/24)*100 = 50%`

**修复建议：**
```php
// 使用实际总任务量计算进度百分比
$progress_percent = $total_task > 0 ? min(100, round(($today_learned_count / $total_task) * 100)) : 0;
```

### 1.5 总任务量计算逻辑重复 ⚠️

**问题位置：** 
- `api.php` - `get_home_data` API (第978-1002行)
- `api.php` - `prepare_study_queue` API (可能也需要)

**问题分析：**
- 总任务量计算逻辑在两个API中都有
- 代码重复，维护成本高

**修复建议：**
- 提取为公共函数：
```php
function calculateTotalTask($conn, $uid, $daily_goal, $today) {
    // 检查用户是否是第一次登录
    $stmt = prepare_check($conn, "
        SELECT COUNT(*) as total_words, 
               COUNT(CASE WHEN date_added < ? THEN 1 END) as words_before_today
        FROM words 
        WHERE user_id = ?
    ");
    $stmt->bind_param("si", $today, $uid);
    $stmt->execute();
    $user_history = $stmt->get_result()->fetch_assoc();
    $total_words = (int)($user_history['total_words'] ?? 0);
    $words_before_today = (int)($user_history['words_before_today'] ?? 0);
    $is_first_login = ($total_words == 0) || ($words_before_today == 0 && $total_words > 0);
    
    if ($is_first_login) {
        return $daily_goal; // 第1天
    }
    
    // 检查学习天数
    $stmt = prepare_check($conn, "
        SELECT COUNT(DISTINCT date_added) as distinct_days
        FROM words 
        WHERE user_id = ? AND date_added <= ?
    ");
    $stmt->bind_param("is", $uid, $today);
    $stmt->execute();
    $days_result = $stmt->get_result()->fetch_assoc();
    $distinct_days = (int)($days_result['distinct_days'] ?? 0);
    
    if ($distinct_days == 2) {
        return $daily_goal * 2; // 第2天
    } elseif ($distinct_days >= 3) {
        return $daily_goal * 2.4; // 第3天及以后
    }
    
    return $daily_goal; // 默认
}
```

### 1.6 判断第一次登录的逻辑可能不准确 ⚠️

**问题位置：** `api.php` - `prepare_study_queue` API (第2468-2484行)

**当前逻辑：**
```php
$is_first_login = ($total_words == 0) || ($words_before_today == 0 && $total_words > 0);
```

**问题分析：**
- 如果用户今天添加了单词，但还没学习，`$total_words > 0`但`$words_before_today == 0`
- 这会被判断为第一次登录，但实际上用户今天已经添加了单词
- 应该检查是否有学习记录（`word_review_logs`表），而不是只检查`words`表

**修复建议：**
```php
// 检查是否有学习记录（word_review_logs表）
$has_learning_record = false;
$check_table = $conn->query("SHOW TABLES LIKE 'word_review_logs'");
if ($check_table && $check_table->num_rows > 0) {
    $stmt = prepare_check($conn, "
        SELECT COUNT(*) as count
        FROM word_review_logs 
        WHERE user_id = ? AND review_date < ?
    ");
    $stmt->bind_param("is", $uid, $today);
    $stmt->execute();
    $record_result = $stmt->get_result()->fetch_assoc();
    $has_learning_record = (int)($record_result['count'] ?? 0) > 0;
}

// 判断是否是第一次登录：没有学习记录，或者今天之前没有学习过
$is_first_login = !$has_learning_record && ($words_before_today == 0);
```

## 🐛 四、边界情况处理

### 4.1 昨天新单词数量超过预期 ⚠️

**问题位置：** `api.php` - `prepare_study_queue` API

**问题分析：**
- 如果昨天学习了20个新单词（超过daily_goal），今天会全部复习
- 加上复习单词（40%）和今天新单词（100%），总任务量可能超过`daily_goal * 2.4`

**示例：**
- `daily_goal=10`，昨天学习了20个新单词
- 今天任务：4个复习 + 20个昨天 + 10个今天 = 34个
- 但`daily_goal * 2.4 = 24个`

**修复建议：**
- 总任务量应该根据实际情况计算：`review_count_target + yesterday_review_count + new_word_target`
- 或者限制昨天新单词的复习数量

---

### 4.2 前面所有天的单词不足 ⚠️

**问题位置：** `api.php` - `prepare_study_queue` API

**问题分析：**
- 如果前面所有天的单词不足`daily_goal * 0.4`个，实际复习单词数量会少于预期
- 总任务量会相应减少

**当前处理：**
- 代码已经处理了这种情况（有多少抽多少）

**建议：**
- 这是合理的，不需要修改

---

### 4.3 用户修改daily_goal后的影响 ⚠️

**问题分析：**
- 如果用户修改了`daily_goal`，总任务量会立即变化
- 但已经添加的单词不会自动调整

**建议：**
- 这是合理的，用户修改目标后，新的学习计划会使用新目标
- 不需要特殊处理

    SELECT DISTINCT date_added FROM words WHERE user_id = ? ORDER BY date_added DESC
