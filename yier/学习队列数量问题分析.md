# 学习队列数量问题分析

## 📋 问题描述

**用户反馈：**
1. 设置的每日目标是10个单词
2. 点击日历显示：新单词只有7个，复习单词是13个
3. **期望：** 新单词应该是10个，复习单词应该是昨天学习的10个 + 40%的复习以前单词（4个）= 14个

---

## 🔍 问题分析

### 问题1：新单词只有7个，应该是10个

#### 1.1 新单词导入逻辑

**代码位置：** `api.php` 第538-610行（`importWordBankWords` 函数）

**导入逻辑：**
```php
// 计算还需要导入的数量
$need_import = max(0, $daily_goal - $today_manual - $today_imported);

// 如果今天已经导入足够数量，不再导入
if ($need_import <= 0) {
    return ['imported' => 0, ...];
}
```

**问题：**
- ✅ 逻辑正确：`need_import = 10 - 手动录入 - 已导入`
- ⚠️ **但是**：如果单词库中没有足够的单词，或者导入失败，就只能有7个

#### 1.2 新单词查询逻辑

**代码位置：** `api.php` 第2875-2895行（`prepare_study_queue` API）

**查询逻辑：**
```php
// 先获取手动录入的单词（最多取new_word_target个）
SELECT * FROM words 
WHERE user_id = ? AND status = 'new' AND date_added <= ? AND source = 'manual' 
LIMIT ?

// 计算还需要多少新单词
$remaining = max(0, $new_word_target - $manual_count);

// 如果还有剩余，从单词库导入的单词中取
SELECT * FROM words 
WHERE user_id = ? AND status = 'new' AND date_added <= ? AND source = 'word_bank' 
LIMIT ?
```

**问题：**
- ⚠️ **查询条件是 `date_added <= ?`**：会查询今天及之前的所有新单词
- ⚠️ **如果今天只导入了7个单词**（手动录入+单词库导入），那么就只能返回7个
- ⚠️ **如果单词库中没有足够的单词**，或者导入失败，就无法达到10个

#### 1.3 可能的原因

1. **单词库中没有足够的单词**
   - 单词库中该年级的单词已经全部导入
   - 单词库中该年级的单词数量不足

2. **导入失败**
   - 单词库导入过程中出现错误
   - 单词重复（已存在）导致无法导入

3. **手动录入不足**
   - 用户手动录入了3个单词
   - 单词库导入了4个单词
   - 总共7个，不足10个

---

### 问题2：复习单词是13个，应该是14个

#### 2.1 复习单词计算逻辑

**代码位置：** `api.php` 第2759-2853行（`prepare_study_queue` API）

**计算逻辑：**
```php
// 昨天学习的单词（全量强制复习）
$yesterday_review_count = count($yesterday_words);  // 应该是10个

// 40%的复习以前单词
$review_count_target = max(1, ceil($daily_goal * 0.4));  // 10 * 0.4 = 4个

// 合并复习单词
$list_reviews = array_merge($yesterday_words, $list_reviews_by_next_review);
```

**期望：**
- 昨天学习的单词：10个
- 40%的复习以前单词：4个
- **总计：14个**

**实际：**
- 复习单词：13个

#### 2.2 可能的原因

1. **昨天学习的单词不是10个**
   - 昨天实际学习了7个单词（不是10个）
   - 所以：7个（昨天）+ 4个（40%）= 11个
   - 但实际显示13个，说明可能还有其他复习单词

2. **日历显示的逻辑问题**
   - 日历显示使用的是 `day_details` API
   - 我刚才修改过，现在包括指定日期添加的单词 + 指定日期复习过的单词
   - 但是，用户点击的是"今天"，所以应该显示：
     - 今天添加的单词（7个）
     - 今天复习过的单词（昨天10个 + 40%的4个 = 14个）
   - **但是，日历显示的是"新单词7个，复习单词13个"**

3. **日历显示的统计逻辑**
   - 日历显示可能不是按照"新单词"和"复习单词"来分类的
   - 可能是按照 `status` 字段来分类的（`status='new'` 是新单词，`status!='new'` 是复习单词）

---

## 🔧 解决方案

### 方案1：确保新单词数量达到10个

**问题：** 如果单词库中没有足够的单词，或者导入失败，就无法达到10个

**解决方案：**
1. **检查单词库导入是否成功**
   - 如果导入失败，提示用户
   - 如果单词库中没有足够的单词，提示用户

2. **强制导入10个单词**
   - 如果手动录入+单词库导入不足10个，继续从单词库导入
   - 如果单词库中没有足够的单词，提示用户手动录入

### 方案2：修复日历显示的统计逻辑

**问题：** 日历显示可能不是按照"新单词"和"复习单词"来分类的

**解决方案：**
1. **检查日历显示的统计逻辑**
   - 查看 `openSheet` 函数如何统计"新单词"和"复习单词"
   - 可能需要修改统计逻辑

2. **统一统计逻辑**
   - 日历显示应该与学习队列的统计逻辑一致
   - 新单词 = `date_added = 今天` 的单词
   - 复习单词 = 今天复习过的单词（通过 `word_review_logs` 表查询）
