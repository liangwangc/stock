# 每日学习和听写逻辑说明

## 📚 一、每日学习逻辑（开始学习按钮）

### 1.1 触发时机
- 用户点击主页的 **"开始学习"** 按钮时触发
- 调用 `api.php?action=prepare_study_queue` API

### 1.2 学习队列组成

每日学习队列 = **复习单词** + **新单词**

#### 1.2.1 复习单词（40%）

**固定比例：40%的每日目标数量**

**复习单词来源（优先级从高到低）：**

1. **前一天学习的所有新单词**（最高优先级）
   - 如果用户昨天学习了5个新单词，今天这5个单词会全部进入复习队列
   - 这是强制复习，确保新学单词得到及时巩固

2. **基于SM-2算法的复习单词**（剩余40%配额）
   - 从 `words` 表中查询 `next_review <= 今天` 的单词
   - **排除前一天学习的单词**（避免重复）
   - 根据优先级排序：
     - **优先级1**：听写模式连续忘记2次以上（分数：1000+）
     - **优先级2**：听写模式有失败记录但少于2次（分数：500+）
     - **优先级3**：没有听写记录，但学习模式表现差（分数：200+）
     - **优先级4**：正常复习（分数：review_priority）

**计算公式：**
```php
// 如果不是第一次登录
review_count_target = max(1, ceil(daily_goal * 0.4))  // 40%的复习量，至少1个

// 前一天学习的单词数量
yesterday_review_count = count(昨天date_added的单词)

// 剩余需要从SM-2算法获取的复习单词
remaining_review_target = max(0, review_count_target - yesterday_review_count)

// 最终复习队列 = 前一天学习的单词 + SM-2算法获取的复习单词
list_reviews = array_merge(yesterday_words, list_reviews_by_next_review)
```

#### 1.2.2 新单词（60%）

**固定比例：60%的每日目标数量**

**新单词来源（优先级从高到低）：**

1. **手动录入的单词**（最高优先级）
   - 从 `words` 表中查询 `status = 'new'` 且 `source = 'manual'` 的单词
   - 按 `date_added ASC, id ASC` 排序

2. **单词库导入的单词**（补充）
   - 如果手动录入的单词不足60%，从单词库导入的单词中补充
   - 从 `words` 表中查询 `status = 'new'` 且 `source = 'word_bank'` 的单词
   - 按 `date_added ASC, id ASC` 排序

**计算公式：**
```php
// 如果不是第一次登录
new_word_target = max(1, floor(daily_goal * 0.6))  // 60%的新单词量，至少1个

// 先获取手动录入的单词（最多取new_word_target个）
list_manual = SELECT * FROM words WHERE status='new' AND source='manual' LIMIT new_word_target

// 计算还需要多少新单词
remaining = max(0, new_word_target - count(list_manual))

// 如果还有剩余，从单词库导入的单词中取
if (remaining > 0) {
    list_word_bank = SELECT * FROM words WHERE status='new' AND source='word_bank' LIMIT remaining
}

// 合并：手动录入优先
list_new = array_merge(list_manual, list_word_bank)
```

### 1.3 特殊情况处理

#### 1.3.1 第一次登录
- **复习单词：0个**
- **新单词：100%（全部新单词）**
- `review_count_target = 0`
- `new_word_target = daily_goal`

#### 1.3.2 单词库导入逻辑
- 在点击"开始学习"时，会先调用 `import_words_for_study` API
- 如果启用了单词库且手动录入不足，会提示用户是否导入单词库单词
- 单词库导入后，单词会添加到 `words` 表，`source = 'word_bank'`

### 1.4 最终队列
```php
// 合并队列：优先显示待复习（不会的多练），然后是新词
final_queue = array_merge(list_reviews, list_new)
```

**队列顺序：**
1. 前一天学习的所有新单词（强制复习）
2. 基于SM-2算法的复习单词（按优先级排序）
3. 手动录入的新单词
4. 单词库导入的新单词

## 🎧 二、听写逻辑

### 2.1 触发时机
- 用户点击主页的 **"🎧 听写"** 按钮时触发
- 调用 `api.php?action=get_today_learned_words_for_dictation` API

### 2.2 听写单词来源

**听写队列 = 今天学习过的所有单词**

包括：
1. **今天新添加的单词**（`date_added = 今天`）
2. **今天复习过的单词**（通过 `word_review_logs` 表查询，`review_date = 今天`）

### 2.3 查询逻辑

```php
// 如果word_review_logs表存在
SELECT DISTINCT w.*
FROM words w
WHERE w.user_id = ?
AND (
    -- 今天新添加的单词
    (w.date_added = ?)
    OR
    -- 今天复习过的单词（通过word_review_logs表）
    EXISTS (
        SELECT 1 
        FROM word_review_logs rl 
        WHERE rl.word_id = w.id 
        AND rl.user_id = ? 
        AND rl.review_date = ?
    )
)
ORDER BY 
    -- 优先显示今天复习过的单词（需要更多练习）
    CASE WHEN EXISTS (
        SELECT 1 FROM word_review_logs rl2 
        WHERE rl2.word_id = w.id AND rl2.user_id = ? AND rl2.review_date = ?
    ) THEN 0 ELSE 1 END,
    w.date_added ASC, w.id ASC
```

### 2.4 前置条件检查

**如果今天还没有学习过：**
- 提示用户："您今天还没有学习过单词。听写功能需要先学习单词才能使用。是否现在开始学习？"
- 如果用户确认，会调用 `startSession()` 切换到学习模式

### 2.5 听写记录

- 听写过程中的每次尝试都会记录到 `word_review_logs` 表
- `review_mode = 'dictation'`
- 听写错误次数会影响单词的复习优先级（见1.2.1节）

## 📊 三、数据统计

### 3.1 今日任务统计

**显示在主页的统计信息：**

1. **要复习**：`total_review_count`（所有需要复习的单词数，不限制数量）
2. **新单词**：`new_count`（今天要学习的新单词数，60%）
3. **今天任务**：`review_count + new_count`（实际要学习的数量）

### 3.2 学习进度统计

**通过 `word_review_logs` 表统计：**

- **今日已学习**：`COUNT(DISTINCT word_id) WHERE review_date = 今天`
- **今日新学**：`COUNT(DISTINCT word_id) WHERE date_added = 今天 AND review_date = 今天`
- **今日复习**：`今日已学习 - 今日新学`
- **今日听写**：`COUNT(DISTINCT word_id) WHERE review_date = 今天 AND review_mode = 'dictation'`

### 3.3 按钮进度显示

**"开始学习"按钮：**
- 格式：`开始学习 (已学习数/总任务数)`
- 总任务数 = `max(队列长度, 每日目标)`

**"🎧 听写"按钮：**
- 格式：`🎧 听写 (已听写数/总任务数)`
- 总任务数 = `max(队列长度, 每日目标)`

## 🔄 四、学习流程示例

### 场景1：第一天学习（新用户）

1. **点击"开始学习"**
   - 复习单词：0个
   - 新单词：5个（假设每日目标=5）
   - 队列：[新单词1, 新单词2, 新单词3, 新单词4, 新单词5]

2. **学习完成后**
   - 5个新单词的状态更新为 `learning` 或 `review`
   - 记录到 `word_review_logs` 表

3. **点击"🎧 听写"**
   - 听写队列：[新单词1, 新单词2, 新单词3, 新单词4, 新单词5]
   - 听写过程中的错误会记录到 `word_review_logs` 表

### 场景2：第二天学习

1. **点击"开始学习"**
   - **复习单词：5个**（前一天学习的5个新单词，强制复习）
   - **新单词：3个**（60% = 5 * 0.6 = 3）
   - 队列：[前一天单词1, 前一天单词2, 前一天单词3, 前一天单词4, 前一天单词5, 新单词1, 新单词2, 新单词3]

2. **学习完成后**
   - 5个复习单词的状态更新
   - 3个新单词的状态更新
   - 记录到 `word_review_logs` 表

3. **点击"🎧 听写"**
   - 听写队列：[前一天单词1, 前一天单词2, ..., 新单词1, 新单词2, 新单词3]
   - 优先显示今天复习过的单词

### 场景3：第三天学习

1. **点击"开始学习"**
   - **复习单词：**
     - 前一天学习的3个新单词（强制复习）
     - 基于SM-2算法的复习单词（剩余40%配额，约2个）
   - **新单词：3个**（60%）
   - 队列：[前一天单词1, 前一天单词2, 前一天单词3, SM-2单词1, SM-2单词2, 新单词1, 新单词2, 新单词3]

## 📝 五、关键API说明

### 5.1 `prepare_study_queue`
- **功能**：准备学习队列（复习单词+新单词）
- **返回**：
  - `queue`：学习队列
  - `review_count`：复习单词数量
  - `new_count`：新单词数量
  - `total_review_count`：所有需要复习的单词数
  - `review_count_target`：复习目标数量（40%）
  - `new_word_target`：新单词目标数量（60%）
  - `yesterday_review_count`：前一天学习的新单词数量
  - `is_first_login`：是否是第一次登录

### 5.2 `get_today_learned_words_for_dictation`
- **功能**：获取今天学习过的单词（用于听写）
- **返回**：
  - `queue`：听写队列
  - `today_learned_count`：今天总学习数
  - `today_new_count`：今天新学数
  - `today_reviewed_count`：今天复习数
  - `has_learned`：今天是否学习过

## ✅ 六、总结

1. **每日学习 = 40%复习 + 60%新单词**（固定比例）
2. **复习单词优先级**：前一天学习的单词 > SM-2算法复习单词
3. **新单词优先级**：手动录入 > 单词库导入
4. **听写队列**：今天学习过的所有单词（新学+复习）
5. **第一次登录**：100%新单词，0%复习
6. **第二天开始**：强制复习前一天学习的所有新单词
