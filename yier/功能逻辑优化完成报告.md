# 功能逻辑优化完成报告

## 优化时间
2026-01-29

## 优化内容

### 1. ✅ 修复今日学习统计逻辑

**问题**：
- `today_learned_count` 只统计 `date_added = today` 的单词
- 不包括今天复习的单词，导致学习量统计不准确

**修复**：
- 统计今天新添加的单词（`date_added = today`）
- 统计今天复习的单词（通过 `word_review_logs` 表查询 `review_date = today`）
- 今日总学习数 = 新学单词数 + 复习单词数

**代码位置**：`api.php` 第761-780行

**影响**：
- 主页"今日任务"的学习量统计更准确
- 学习进度百分比计算更合理

---

### 2. ✅ 明确单词状态转换规则

**问题**：
- `status` 字段的状态转换逻辑不够清晰
- 缺少明确的 `mastered` 状态设置规则

**修复**：
- 明确状态转换规则：
  - `new` → `learning`：第一次学习
  - `learning` → `review`：repetitions >= 3
  - `review` → `mastered`：repetitions >= 5 且 ef_factor >= 2.5
- 在 `submit_review` API 中根据条件自动设置状态

**代码位置**：`api.php` 第873-888行

**状态转换逻辑**：
```php
if ($reps >= 5 && $ef >= 2.5) {
    $status = 'mastered';  // 已掌握
} elseif ($reps >= 3) {
    $status = 'review';    // 复习中
} else {
    $status = 'learning'; // 学习中
}
```

**影响**：
- 单词状态转换更清晰、更合理
- 已掌握单词的识别更准确

---

### 3. ✅ 修复数据一致性问题

**问题**：
- `forgot_count`, `vague_count`, `remembered_count` 字段与 `word_review_logs` 表数据可能不一致
- 这些字段在 `submit_review` 中手动更新，但可能不同步

**修复**：
- 在 `updateWordStats` 函数中，从 `word_review_logs` 表统计总点击次数
- 确保 `forgot_count`, `vague_count`, `remembered_count` 与 `word_review_logs` 表数据一致
- 每次更新单词统计时，都会重新计算这些字段

**代码位置**：`api.php` 第275-359行（`updateWordStats` 函数）

**统计逻辑**：
```php
// 从word_review_logs表统计，确保与words表一致
SELECT 
    SUM(CASE WHEN quality = 1 THEN 1 ELSE 0 END) as total_forgot,
    SUM(CASE WHEN quality = 3 THEN 1 ELSE 0 END) as total_vague,
    SUM(CASE WHEN quality = 5 THEN 1 ELSE 0 END) as total_remembered
FROM word_review_logs 
WHERE word_id = ?
```

**影响**：
- 数据一致性得到保证
- 统计更准确，避免数据不同步问题

### 4. ✅ 优化智能复习查询逻辑

**问题**：
- 智能复习抽取逻辑复杂，有多个层级的查询
- 每次查询都需要排除已选中的单词，导致多次查询
- 性能可能受影响

**修复**：
- 使用单一查询，通过 `LEFT JOIN` 和聚合函数计算优先级分数
- 通过 `ORDER BY calculated_priority DESC` 一次性获取所有优先级的数据
- 减少数据库查询次数，从4次查询优化为1次查询

**代码位置**：`api.php` 第603-649行

**优化前**：
- 4次独立查询（priority1, priority2, priority3, priority4）
- 每次查询都需要排除已选中的单词
- 查询次数：O(4)

**优化后**：
- 1次查询，通过 `LEFT JOIN` 和 `CASE WHEN` 计算优先级
- 通过 `ORDER BY` 排序，一次性获取所有数据
- 查询次数：O(1)

**优先级计算逻辑**：
```sql
CASE 
    -- 优先级1：听写模式连续忘记2次以上（分数：1000+）
    WHEN dictation_forgot_count >= 2 THEN 1000 + review_priority
    -- 优先级2：听写模式有失败记录但少于2次（分数：500+）
    WHEN dictation_fail_count > 0 THEN 500 + review_priority
    -- 优先级3：没有听写记录，但学习模式表现差（分数：200+）
    WHEN has_dictation_record = 0 AND study_forgot_count >= 2 THEN 200 + review_priority
    -- 优先级4：正常复习（分数：review_priority）
    ELSE review_priority
END as calculated_priority
```

**影响**：
- 查询性能显著提升（减少75%的查询次数）
- 代码更简洁，易于维护
- 逻辑更清晰，优先级计算更准确

## 注意事项

1. **数据库索引**：确保 `word_review_logs` 表有适当的索引（`word_id`, `review_mode`, `quality`），以提高查询性能

2. **数据迁移**：如果现有数据不一致，可能需要运行数据同步脚本：
   ```sql
   UPDATE words w
   SET 
       forgot_count = (SELECT COUNT(*) FROM word_review_logs WHERE word_id = w.id AND quality = 1),
       vague_count = (SELECT COUNT(*) FROM word_review_logs WHERE word_id = w.id AND quality = 3),
       remembered_count = (SELECT COUNT(*) FROM word_review_logs WHERE word_id = w.id AND quality = 5)
   WHERE EXISTS (SELECT 1 FROM word_review_logs WHERE word_id = w.id);
   ```

3. **状态更新**：已存在的单词状态可能需要根据新的规则更新，特别是 `mastered` 状态的单词
