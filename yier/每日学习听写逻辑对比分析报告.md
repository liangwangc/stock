# 每日学习/听写逻辑对比分析报告

## 📋 一、用户新需求逻辑

### 1.1 核心公式

**每日学习/听写队列 = 复习单词（40%）+ 昨天学习的新单词（全量）+ 今天学习的新单词（全量）**

**详细组成：**
- **复习单词（40%）**：根据复习算法抽取前面所有天的40%来复习
- **昨天学习的新单词（全量）**：前一天学习的所有新单词，强制复习
- **今天学习的新单词（全量）**：100%的每日目标数量

### 1.2 逐日逻辑示例（假设每日目标=10个）

#### 第一天
- **复习单词**：0个（没有历史记录）
- **昨天学习的新单词**：0个（没有昨天）
- **今天学习的新单词**：10个（100%）
- **总任务**：10个
- **队列**：[新单词1, 新单词2, ..., 新单词10]

#### 第二天
- **复习单词**：0个（第一天没有需要复习的）
- **昨天学习的新单词**：10个（第一天的10个新单词，全量强制复习）
- **今天学习的新单词**：10个（100%）
- **总任务**：20个
- **队列**：[第一天单词1, 第一天单词2, ..., 第一天单词10, 新单词1, 新单词2, ..., 新单词10]

#### 第三天
- **复习单词**：4个（根据复习算法抽取第一天的40% = 10 * 0.4 = 4个）
- **昨天学习的新单词**：10个（第二天的10个新单词，全量强制复习）
- **今天学习的新单词**：10个（100%）
- **总任务**：24个
- **队列**：[第一天单词（选4个）, 第二天单词1, 第二天单词2, ..., 第二天单词10, 新单词1, 新单词2, ..., 新单词10]

#### 第四天
- **复习单词**：8个（根据复习算法抽取第一天+第二天的40% = (10+10) * 0.4 = 8个）
- **昨天学习的新单词**：10个（第三天的10个新单词，全量强制复习）
- **今天学习的新单词**：10个（100%）
- **总任务**：28个
- **队列**：[第一天单词（选4个）, 第二天单词（选4个）, 第三天单词1, 第三天单词2, ..., 第三天单词10, 新单词1, 新单词2, ..., 新单词10]

#### 第五天
- **复习单词**：12个（根据复习算法抽取第一天+第二天+第三天的40% = (10+10+10) * 0.4 = 12个）
- **昨天学习的新单词**：10个（第四天的10个新单词，全量强制复习）
- **今天学习的新单词**：10个（100%）
- **总任务**：32个
- **队列**：[第一天单词（选4个）, 第二天单词（选4个）, 第三天单词（选4个）, 第四天单词1, 第四天单词2, ..., 第四天单词10, 新单词1, 新单词2, ..., 新单词10]

### 1.3 关键特点

1. **新单词数量**：每天都是100%的每日目标（例如10个目标=10个新单词）
2. **昨天学习的新单词**：每天都会强制复习前一天学习的所有新单词（全量）
3. **复习算法抽取**：从前面所有天（不包括昨天）中抽取40%来复习
4. **总任务量递增**：随着学习天数增加，总任务量会逐渐增加
   - 第1天：10个
   - 第2天：20个
   - 第3天：24个
   - 第4天：28个
   - 第5天：32个
   - 第N天：10 + 10 + (N-2) * 10 * 0.4 = 20 + (N-2) * 4

## 🔄 二、现在逻辑（当前实现）

### 2.1 核心公式

**每日学习队列 = 复习单词（40%）+ 新单词（60%）**

**详细组成：**
- **复习单词（40%）**：
  - 前一天学习的所有新单词（全量，最高优先级）
  - 基于SM-2算法的复习单词（剩余40%配额，排除前一天学习的单词）
- **新单词（60%）**：60%的每日目标数量

### 2.2 逐日逻辑示例（假设每日目标=10个）

#### 第一天
- **复习单词**：0个
- **新单词**：10个（100%，因为是第一次登录）
- **总任务**：10个
- **队列**：[新单词1, 新单词2, ..., 新单词10]

#### 第二天
- **复习单词**：
  - 前一天学习的新单词：10个（全量）
  - SM-2算法复习单词：0个（剩余配额 = 4 - 10 = -6，取0）
- **新单词**：6个（60% = 10 * 0.6 = 6个）
- **总任务**：16个
- **队列**：[前一天单词1, 前一天单词2, ..., 前一天单词10, 新单词1, 新单词2, ..., 新单词6]

#### 第三天
- **复习单词**：
  - 前一天学习的新单词：6个（全量）
  - SM-2算法复习单词：0个（剩余配额 = 4 - 6 = -2，取0）
- **新单词**：6个（60%）
- **总任务**：12个
- **队列**：[前一天单词1, 前一天单词2, ..., 前一天单词6, 新单词1, 新单词2, ..., 新单词6]

#### 第四天
- **复习单词**：
  - 前一天学习的新单词：6个（全量）
  - SM-2算法复习单词：0个（剩余配额 = 4 - 6 = -2，取0）
- **新单词**：6个（60%）
- **总任务**：12个
- **队列**：[前一天单词1, 前一天单词2, ..., 前一天单词6, 新单词1, 新单词2, ..., 新单词6]

### 2.3 关键特点

1. **新单词数量**：每天都是60%的每日目标（例如10个目标=6个新单词）
2. **昨天学习的新单词**：每天都会强制复习前一天学习的所有新单词（全量）
3. **复习算法抽取**：只从SM-2算法（`next_review <= 今天`）中抽取，排除前一天学习的单词
4. **总任务量相对稳定**：随着学习天数增加，总任务量会稳定在某个范围
   - 第1天：10个
   - 第2天：16个
   - 第3天及以后：12个左右（如果前一天新单词数=6）

## 📊 三、关键差异对比

| 对比项 | 现在逻辑 | 用户新需求 | 差异说明 |
|--------|---------|-----------|---------|
| **新单词数量** | 60%的每日目标 | 100%的每日目标 | 新需求每天学习更多新单词 |
| **复习单词组成** | 前一天全量 + SM-2剩余40% | 前一天全量 + 前面所有天的40% | 新需求复习范围更广，包括更早的单词 |
| **总任务量** | 相对稳定（12-16个） | 递增（10→20→24→28...） | 新需求总任务量会逐渐增加 |
| **复习算法** | SM-2算法（`next_review <= 今天`） | 从前面所有天抽取40% | 新需求需要重新设计复习算法 |
| **昨天新单词处理** | 全量强制复习（相同） | 全量强制复习（相同） | 两者一致 |
| **第一次登录** | 100%新单词 | 100%新单词 | 两者一致 |

## 🔍 四、详细差异分析

### 4.1 新单词数量差异

**现在逻辑：**
- 新单词 = 60%的每日目标
- 例如：每日目标=10，新单词=6个

**新需求：**
- 新单词 = 100%的每日目标
- 例如：每日目标=10，新单词=10个

**影响：**
- 新需求每天学习的新单词数量增加67%（从6个增加到10个）
- 学习强度更高，但可能增加学习负担

### 4.2 复习单词组成差异

**现在逻辑：**
```
复习单词 = 前一天学习的新单词（全量） + SM-2算法复习单词（剩余40%配额）
```

**新需求：**
```
复习单词 = 前一天学习的新单词（全量） + 前面所有天的40%（根据复习算法抽取）
```

**关键区别：**
1. **复习范围**：
   - 现在：只复习 `next_review <= 今天` 的单词（SM-2算法决定）
   - 新需求：从前面所有天（不包括昨天）中抽取40%来复习

2. **复习算法**：
   - 现在：基于SM-2算法的 `next_review` 字段
   - 新需求：需要重新设计算法，从前面所有天中抽取40%

3. **复习数量**：
   - 现在：如果前一天新单词很多，SM-2算法复习单词可能为0
   - 新需求：固定从前面所有天中抽取40%，数量相对稳定

### 4.3 总任务量差异

**现在逻辑：**
- 总任务量 = 前一天新单词数 + 新单词数（60%）
- 如果前一天新单词=6，新单词=6，总任务=12个
- 总任务量相对稳定

**新需求：**
- 总任务量 = 复习单词（40%）+ 前一天新单词（全量）+ 新单词（100%）
- 第2天：0 + 10 + 10 = 20个
- 第3天：4 + 10 + 10 = 24个
- 第4天：8 + 10 + 10 = 28个
- 总任务量递增

**影响：**
- 新需求的学习负担会逐渐增加
- 需要评估用户的学习承受能力

### 4.4 复习算法差异

**现在逻辑：**
- 使用SM-2算法的 `next_review` 字段
- 查询条件：`next_review <= 今天` 且 `date_added != 昨天`
- 根据优先级排序（听写错误次数、学习表现等）

**新需求：**
- 需要从前面所有天（不包括昨天）中抽取40%
- 例如：第5天需要从第1、2、3天中抽取40%
- 抽取逻辑需要重新设计：
  - 如何确定从哪些天抽取？
  - 如何确定从每天抽取哪些单词？
  - 是否需要考虑SM-2算法的 `next_review`？

**关键问题：**
1. **抽取范围**：从第1天到第N-2天（不包括昨天和今天）？
2. **抽取方式**：平均分配还是按优先级？
3. **抽取数量**：每天抽取的数量如何分配？
4. **算法依据**：是否仍然使用SM-2算法的优先级？

## 📝 五、新需求实现要点

### 5.1 需要修改的API

**`prepare_study_queue` API** 需要重大修改：

1. **新单词数量计算**：
   ```php
   // 现在
   $new_word_target = max(1, floor($daily_goal * 0.6)); // 60%
   
   // 新需求
   $new_word_target = $daily_goal; // 100%
   ```

2. **复习单词计算**：
   ```php
   // 现在
   $review_count_target = max(1, ceil($daily_goal * 0.4)); // 40%
   $yesterday_words = 前一天学习的所有新单词（全量）
   $remaining_review_target = max(0, $review_count_target - count($yesterday_words));
   $list_reviews_by_next_review = 从SM-2算法获取（剩余配额）
   
   // 新需求
   $review_count_target = max(1, ceil($daily_goal * 0.4)); // 40%
   $yesterday_words = 前一天学习的所有新单词（全量）
   $previous_days_words = 从前面所有天（不包括昨天）中抽取40%
   $list_reviews = array_merge($yesterday_words, $previous_days_words);
   ```

3. **前面所有天的40%抽取逻辑**：
   ```php
   // 需要实现的新逻辑
   // 1. 获取前面所有天（不包括昨天）的学习记录
   // 2. 计算每天需要抽取的数量（40%）
   // 3. 根据复习算法（优先级）从每天中抽取
   // 4. 合并所有抽取的单词
   ```

### 5.2 需要设计的算法

**前面所有天的40%抽取算法：**

1. **确定抽取范围**：
   - 从第1天到第N-2天（不包括昨天和今天）
   - 例如：第5天需要从第1、2、3天抽取

2. **计算每天抽取数量**：
   - 方法1：平均分配（总40% / 天数）
   - 方法2：按每天学习数量比例分配
   - 方法3：固定每天抽取40%

3. **抽取依据**：
   - 是否仍然使用SM-2算法的 `next_review`？
   - 是否使用优先级排序（听写错误次数、学习表现等）？
   - 是否需要考虑单词的掌握程度？

### 5.3 听写逻辑

**听写队列保持不变**：
- 听写队列 = 今天学习过的所有单词（新学+复习）
- 这个逻辑与新需求一致，不需要修改

## ⚠️ 六、潜在问题和建议

### 6.1 总任务量递增问题

**问题：**
- 新需求的总任务量会逐渐增加（10→20→24→28...）
- 长期学习可能导致任务量过大，影响用户体验

**建议：**
1. **设置上限**：总任务量不超过某个上限（例如50个）
2. **动态调整**：根据用户学习表现动态调整复习数量
3. **用户选择**：允许用户设置是否启用递增模式

### 6.2 复习算法设计问题

**问题：**
- 如何从前面所有天中抽取40%？
- 抽取的依据是什么？

**建议：**
1. **使用SM-2算法**：仍然使用 `next_review <= 今天` 作为主要依据
2. **优先级排序**：根据听写错误次数、学习表现等排序
3. **平均分配**：从每天中平均抽取，确保复习覆盖更全面

### 6.3 新单词数量问题

**问题：**
- 新需求每天学习100%的新单词，学习强度较高

**建议：**
1. **用户设置**：允许用户设置新单词比例（60%-100%）
2. **渐进式增加**：新用户从60%开始，逐渐增加到100%
3. **学习反馈**：根据用户学习表现动态调整
