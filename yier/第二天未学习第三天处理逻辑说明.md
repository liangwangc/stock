# 第二天未学习第三天处理逻辑说明

## 一、场景描述

**情况**：
- 第1天：用户学习了10个单词
- 第2天：用户没有学习（没有打开应用或没有点击"开始学习"）
- 第3天：用户重新开始学习

**问题**：第三天应该如何处理？

---

## 二、当前系统的处理逻辑

### 2.1 连续打卡天数

**逻辑**：`calculateCheckInStreak()` 函数

```php
function calculateCheckInStreak($conn, $user_id, $today) {
    // 获取所有有学习记录的日期（按日期倒序）
    $stmt = $conn->prepare("SELECT DISTINCT date_added FROM words WHERE user_id = ? ORDER BY date_added DESC LIMIT 30");
    // ...
    
    // 从今天（或昨天）往前计算连续天数
    foreach ($dates as $date) {
        if ($date === $current_date) {
            $streak++;
            $current_date = date('Y-m-d', strtotime("$current_date -1 day"));
        } elseif ($date < $current_date) {
            // 如果日期不连续，停止计算
            break;
        }
    }
}
```

**处理结果**：
- ✅ 第1天：连续打卡 = 1天
- ❌ 第2天：没有学习记录，连续打卡中断
- ✅ 第3天：连续打卡 = 1天（重新开始）

**说明**：连续打卡会中断，从第3天重新开始计算。

---

### 2.2 复习单词的处理

**逻辑**：`prepare_study_queue` API

#### 2.2.1 复习单词的查询条件

```sql
SELECT w.*, ...
FROM words w
WHERE w.user_id = ? 
  AND w.status != 'new' 
  AND w.next_review <= ?  -- 关键：只要next_review <= 今天，就会出现在复习列表中
ORDER BY calculated_priority DESC, w.next_review ASC
LIMIT ?
```

**关键点**：`next_review <= today`

#### 2.2.2 第1天学习的单词的复习计划

假设第1天学习了单词"apple"，答对了：
- `repetitions = 1`
- `ef_factor = 2.6`
- `interval_days = 1`
- `next_review = 第2天`（第1天 + 1天）

#### 2.2.3 第2天未学习的处理

**情况**：用户第2天没有学习

**结果**：
- ✅ 单词的`next_review`仍然是第2天（不会自动更新）
- ✅ 第3天查询时，`next_review <= 第3天`，所以单词会出现在复习列表中
- ✅ **第2天应该复习的单词会累积到第3天**

#### 2.2.4 第3天的复习队列

**计算逻辑**：
1. **固定比例分配**：40%复习，60%新单词
2. **复习单词来源**：
   - 第1天学习的单词（`next_review <= 第3天`）
   - 如果第2天有应该复习的单词，也会累积到第3天
3. **优先级排序**：
   - 听写模式连续忘记2次以上（优先级最高）
   - 听写模式有失败记录
   - 学习模式表现差
   - 正常复习（按`next_review`排序，越早的越优先）

**示例**：
- 第1天学习了10个单词，`next_review`都是第2天
- 第2天没有学习
- 第3天：
  - 复习单词：10个（第1天学习的，应该在第2天复习的）
  - 新单词：根据daily_goal和40%比例计算
  - 如果daily_goal=10，则复习4个，新单词6个

---

### 2.3 今日星星的计算

**逻辑**：基于`word_review_logs`表统计实际学习过的单词

**第3天的情况**：
- 如果第3天学习了4个复习单词 + 6个新单词 = 10个单词
- 今日星星 = 10颗（每个单词1颗星）

**注意**：第2天没有学习，所以第2天的星星 = 0

---

### 2.4 完成率的计算

**逻辑**：`(今天实际学习的单词数 / daily_goal) * 100`

**第3天的情况**：
- 如果学习了10个单词，daily_goal=10
- 完成率 = (10/10)*100 = 100%

**注意**：完成率只计算当天的学习情况，不累计前几天的。

---

## 三、具体示例

### 示例：用户学习流程

**第1天（2026-01-30）**：
- 学习了10个新单词
- 每个单词答对了，`next_review = 2026-01-31`（明天）
- 连续打卡 = 1天
- 今日星星 = 10颗

**第2天（2026-01-31）**：
- ❌ 用户没有学习（没有打开应用）
- 连续打卡中断
- 今日星星 = 0颗
- 应该复习的10个单词没有复习，`next_review`仍然是`2026-01-31`

**第3天（2026-02-01）**：
- ✅ 用户重新开始学习
- 点击"开始学习"按钮
- 系统计算复习队列：
  - 复习单词：10个（第1天学习的，`next_review <= 2026-02-01`）
  - 固定比例：40%复习，60%新单词
  - 如果daily_goal=10：
    - 复习单词：4个（从10个中按优先级选择4个）
    - 新单词：6个
- 连续打卡 = 1天（重新开始）
- 今日星星 = 实际学习的单词数

## 四、潜在问题与优化建议

### 4.1 问题：复习单词累积过多

**问题**：如果用户连续多天没有学习，复习单词会累积很多。

**示例**：
- 第1天学习了10个单词，`next_review = 第2天`
- 第2-5天都没有学习
- 第6天：应该复习的单词累积到10个（甚至更多）

**当前处理**：
- ✅ 固定比例：40%复习，60%新单词
- ✅ 如果复习单词很多，新单词会减少（甚至为0）

**优化建议**：
1. **设置复习单词上限**：例如最多复习daily_goal的50%
2. **优先复习过期的单词**：按`next_review`排序，越早的越优先
3. **提醒用户**：如果累积的复习单词过多，提醒用户优先复习

### 4.2 问题：连续打卡中断

**问题**：第2天没有学习，连续打卡会中断。

**当前处理**：
- ✅ 连续打卡从第3天重新开始计算
- ✅ 这是合理的，因为用户确实中断了

**优化建议**：
1. **宽限期**：可以考虑给1天的宽限期（例如，如果第2天没有学习，但第3天学习了，可以算作连续）
2. **提醒功能**：如果连续打卡即将中断，提醒用户学习

### 4.3 问题：复习单词的优先级

**当前逻辑**：
- ✅ 听写模式连续忘记2次以上（优先级最高）
- ✅ 听写模式有失败记录
- ✅ 学习模式表现差
- ✅ 正常复习（按`next_review`排序）

**说明**：这个逻辑是合理的，优先复习困难的单词。

## 五、总结

### 第三天处理逻辑：

1. **连续打卡**：
   - ✅ 中断后重新开始计算
   - ✅ 第3天连续打卡 = 1天

2. **复习单词**：
   - ✅ 第1天学习的单词（`next_review <= 第3天`）会出现在复习列表中
   - ✅ 第2天应该复习的单词会累积到第3天
   - ✅ 按固定比例分配：40%复习，60%新单词
   - ✅ 按优先级排序：困难的单词优先复习

3. **今日星星**：
   - ✅ 基于实际学习的单词数计算
   - ✅ 每个单词1颗星

4. **完成率**：
   - ✅ 只计算当天的学习情况
   - ✅ 不累计前几天的

### 关键点：

- ✅ **复习单词不会丢失**：即使第2天没有学习，第3天仍然会出现在复习列表中
- ✅ **复习单词会累积**：如果连续多天没有学习，复习单词会累积
- ✅ **固定比例分配**：40%复习，60%新单词，确保复习和新学平衡
- ✅ **优先级排序**：困难的单词优先复习
