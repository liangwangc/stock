**重要**：必须先执行数据库升级脚本！

```bash
mysql -u root -p word_app < 智能复习系统升级.sql
```

或者在MySQL客户端中执行：
```sql
source 智能复习系统升级.sql
```

### 2. 升级内容

- ✅ 创建 `word_review_logs` 表（复习记录表）
- ✅ 为 `words` 表添加统计字段：
  - `last_review_date`：最后一次复习日期
  - `last_review_mode`：最后一次复习模式（study/dictation）
  - `consecutive_remembered`：连续记住次数（以听写为主）
  - `consecutive_forgot`：连续忘记次数（以听写为主）
  - `review_priority`：复习优先级
- ✅ 添加必要的索引优化查询性能

## 二、功能说明

### 1. 复习记录

每次用户点击"忘记/模糊/记住"按钮时：
- ✅ 记录到 `word_review_logs` 表（包括复习前和复习后的状态）
- ✅ 区分学习模式（study）和听写模式（dictation）
- ✅ 更新 `words` 表的统计字段
- ✅ 计算复习优先级（以听写为主）

### 2. 智能复习抽取（以听写为主）

**复习量**：新学单词量 × 50%

**优先级分配**：
1. **50%** → 听写模式连续忘记2次以上的单词（最高优先级）
2. **30%** → 听写模式有失败记录的单词（需要巩固）
3. **10%** → 没有听写记录，但学习模式表现差的单词（需要听写验证）
4. **10%** → 其他正常复习（按优先级和日期排序）

### 3. 复习优先级计算

**听写模式权重（主要）**：
- 听写连续忘记：权重 **20**
- 听写连续模糊：权重 **12**
- 听写失败率：权重 **15**
- 听写连续记住：降低优先级 **-5**

**学习模式权重（辅助）**：
- 学习连续忘记：权重 **5**（仅为听写的1/4）
- 学习连续模糊：权重 **3**
- 学习连续记住：降低优先级 **-1**（影响很小）

前端已自动传递 `review_mode` 参数：

- 听写模式：`review_mode = 'dictation'`

### 2. 无需额外修改

前端代码已自动识别当前学习模式，无需手动设置。

## 五、注意事项

1. **必须先执行SQL脚本**，否则会出现数据库错误
2. **复习记录会持续增长**，建议定期归档（90天后的记录）
3. **性能优化**：如果单词量很大，可以考虑使用缓存预计算复习队列
4. **数据迁移**：现有数据会自动兼容，新字段默认为0或NULL

## 七、问题排查

### 问题1：复习记录没有保存

**检查**：
- `word_review_logs` 表是否存在
- API返回的 `review_mode` 是否正确
- 数据库连接是否正常

### 问题2：复习队列不正确

**检查**：
- `words` 表的统计字段是否正确更新
- `review_priority` 是否正确计算
- SQL查询是否正确执行

### 问题3：听写模式优先级不正确

**检查**：
- `word_review_logs` 表的 `review_mode` 字段是否正确
- 听写模式的记录是否正确保存
- 优先级计算函数是否正确
